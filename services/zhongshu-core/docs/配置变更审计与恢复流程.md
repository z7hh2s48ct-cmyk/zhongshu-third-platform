# 配置变更审计与恢复流程（ZS-CFG-004 B04）

> 任务：ZS-CFG-004 B04 复验部分（变更审计 + 恢复流程）。B03 部分（值校验 / 参数目录 / 乐观锁版本）已于 2026-09-13 交付（`e218fe04`）。
> 本批次接线 ZS-AUDIT-001 的统一 `AuditPort`（B04 同库事务内审计），为 infra 参数配置补齐「变更留痕 + 审查后恢复」。

## 1. 现状缺陷（B03 交付后残留）

- 配置 create/update/delete 无任何业务留痕：改错值后既无「谁在何时把什么改成什么」的可追查记录，也无回滚依据。
- 配置值与审计脱敏脱节：若直接把前后值写入审计，`system.user.init-password` 等秘密参数的明文将进入审计面。
- 误改无受控恢复路径：只能凭记忆手工改回，且绕过值校验 / 乐观锁契约的风险不可控。

## 2. 双轨留痕设计

每次 `create / update / delete / restore` 由 `ConfigChangeRecorder` 统一落两路记录（同一事务）：

| 轨道 | 载体 | 事务语义 | 内容 |
|---|---|---|---|
| 变更历史 | `infra_config_history`（迁移 `V20260914.011`） | 随业务事务提交，业务回滚则不留 | config_id / 变更时 key / 变更类型（CREATE/UPDATE/DELETE/RESTORE）/ 前后值 / 前后乐观锁版本 / 操作者 / 审查依据 |
| 业务审计 | `AuditPort.record`（AUDIT-001，audit_event 表） | SUCCESS 随业务事务 + fail-closed（审计失败整体回滚）；DENIED 独立事务 | 事件类型（OBJECT_CREATED/OBJECT_UPDATED/OBJECT_DELETED/`CONFIG_PARAM_RESTORED`）+ actor + bizType `infra_config` + detail 脱敏摘要 |

### 2.1 敏感脱敏规则（敏感旧值不写审计原文）

- `ConfigSensitiveClassifier` 三档判定（SECRET=秘密键模式命中 / SENSITIVE=visible=false / NORMAL）；
- 秘密/敏感参数在**变更历史**与**审计 detail** 中一律落掩码 `******`，明文不落任何留痕面；
- **显式脱敏标志**（`old_value_redacted` / `new_value_redacted`，codex r0 P2）：NORMAL 配置的字面 `******` 与脱敏哨兵同形，可恢复性判定以标志为准、不做值形推断，字面值可正常恢复；
- key 改名场景：前后值各按变更前后的 key 判定敏感级，改名链上任一侧为敏感即不落明文；
- 历史查询输出二次防护：当前配置为敏感/秘密级时**整页掩码**（覆盖「NORMAL 期明文入史 + 后改密」的历史行）；敏感期历史落库时已是掩码，不泄露。

### 2.2 删除留痕的行级真实性（codex r0 P2）

- `deleteConfig` / `deleteConfigList` 逐行走**条件删除**（逻辑删除 UPDATE 自带 `deleted=0` 谓词），仅对 `affected > 0` 的行落 DELETE 历史 + SUCCESS 审计；并发下被抢先删除的行不产生留痕，不给未实际删除的调用方记成功审计；单删 `affected = 0` 时按 `CONFIG_NOT_EXISTS` 拒绝。

## 3. 审查后恢复流程（`PUT /infra/config/restore`）

恢复 = 回写某条 UPDATE/RESTORE 历史记录的 `old_value`，全程走与更新相同的守卫路径，不新增旁路：

1. **权限**：`@PreAuthorize("@ss.hasPermission('infra:config:update')")`（恢复即一次受控更新，不设独立越权通道）；
2. **目标约束**：仅既有配置可恢复（已删除配置 `CONFIG_NOT_EXISTS`）——恢复仅回写既有行 value、不插入新行。模块启停由 `ModuleCatalog` 构建期白名单决定（ZS-ENG-001/ZS-CFG-003.A），`infra_config` 无模块开关键，恢复结构性排除「复活关闭模块」路径（看守用例锁定）；
3. **历史匹配**：historyId 必须属于该配置（跨配置恢复 `CONFIG_RESTORE_HISTORY_MISMATCH`，并按 DENIED 独立留痕）;
4. **可恢复性**：仅 UPDATE/RESTORE 历史可恢复，且显式脱敏标志 `old_value_redacted = FALSE`——秘密/敏感历史已脱敏不可自动恢复（`CONFIG_RESTORE_NOT_RESTORABLE`，DENIED 留痕），须管理员手工重新填写；NORMAL 配置的字面 `******` 值不受影响（codex r0 P2）；
5. **值校验**：恢复值走与更新同一 `ConfigValueValidator`（非法历史值不得进入运行，防历史脏数据回灌）；
6. **乐观锁**：请求须携带当前 version，冲突 `CONFIG_UPDATE_CONFLICT`（与更新同一契约）；
7. **只回写 value**：key/visible/category/name 不动（看守用例锁定）；
8. **留痕**：RESTORE 历史行 + `CONFIG_PARAM_RESTORED` 审计，reason（审查依据）必填并落两轨。

## 4. 权限与端点矩阵

| 端点 | 权限 | 说明 |
|---|---|---|
| `PUT /infra/config/restore` | `infra:config:update` | 恢复至历史值（审查依据必填） |
| `GET /infra/config/history/page` | `infra:config:query` | 变更历史分页（敏感配置整页掩码） |
| 既有 create/update/delete | 不变 | 变更即留痕（历史 + SUCCESS 审计） |

## 5. 错误码（1-001-000-011~013 号段）

| 码 | 常量 | 语义 |
|---|---|---|
| 1-001-000-011 | `CONFIG_RESTORE_HISTORY_NOT_EXISTS` | 配置变更历史不存在 |
| 1-001-000-012 | `CONFIG_RESTORE_NOT_RESTORABLE` | 历史不可自动恢复（敏感脱敏 / 记录类型不支持） |
| 1-001-000-013 | `CONFIG_RESTORE_HISTORY_MISMATCH` | 恢复目标历史与参数配置不匹配 |

## 6. 测试矩阵（`ConfigChangeAuditRestoreTest` 17 用例，H2）

1. NORMAL 更新 → 历史明文 + OBJECT_UPDATED 审计（detail 摘要）+ 脱敏标志 FALSE；
2. SECRET 更新 → 历史/审计全掩码 + 脱敏标志 TRUE，明文零出现；
3. CREATE → CREATE 历史行 + OBJECT_CREATED 审计；
4. DELETE → DELETE 历史行 + OBJECT_DELETED 审计；
5. SUCCESS 审计失败 → 业务与历史整体回滚（fail-closed）；
6. 恢复正向 → 值回滚、版本 +1 续链、RESTORE 历史行 + `CONFIG_PARAM_RESTORED` 审计；
7. 乐观锁过期 → `CONFIG_UPDATE_CONFLICT`，无恢复留痕；
8. 秘密历史恢复 → `CONFIG_RESTORE_NOT_RESTORABLE` + DENIED 留痕（原因不含明文）；
9. NORMAL 字面 `******` 恢复 → 正常恢复（显式标志判定，codex r0 P2 看守）；
10. CREATE 历史恢复 → 同上拒绝；
11. 跨配置恢复 → `CONFIG_RESTORE_HISTORY_MISMATCH`；
12. 历史脏数据（越界值）→ 恢复值再校验拒绝（`CONFIG_VALUE_OUT_OF_RANGE`）；
13. 已删除配置 → 不可恢复、不复活（无新行插入）；
14. 恢复仅回写 value（key/名称/可见性不动）；
15. DENIED 审计失败 → 业务拒绝原样返回（不变形）；
16. 历史分页掩码输出（敏感整页掩码 / NORMAL 明文）；
17. 历史分页目标不存在 → `CONFIG_NOT_EXISTS`。

既有 `ConfigServiceImplTest` / `ConfigServiceImplMaskTest` / `ConfigServiceImplValueValidationTest` 已补齐新依赖装配（Recorder + Mapper + AuditPort 假件）；`DatabaseTableServiceImplTest` 表清单断言同步（新表命中 config 关键字 1→2）。
