# 接口清单与匿名白名单（ZS-SEC-002）

> 建立日期：2026-09-09。基线：ZS-ENG-001（模块白名单）、ZS-ENG-004（关闭模拟认证）、ZS-ENG-005（管理端点仅暴露 health）完成后。
> 性质：以**实际 Controller 源码**为事实来源，静态生成「HTTP 方法 / 路径 / 主体类型 / 授权类别 / 权限标识 / 模块归属」全量接口清单 + **漂移基线**，并对匿名（`@PermitAll`）白名单逐项登记理由、建立「新增/移除匿名端点必须评审」的门禁。
> 复用边界：**运行时安全链行为**（ADMIN/MEMBER Token 串用、ASYNC 首次派发不免认证、缺方法权限拒绝）复用 [ZS-SEC-012.A 夹具](../zszj-framework/zszj-spring-boot-starter-biz-tenant/src/test/java/cn/zszj/framework/security/SecurityFilterChainFixtureTest.java)，本清单不重写；对象级数据范围授权归 [ZS-PERM-002.A](数据权限授权矩阵.md)；Token 传输/凭据规范归 ZS-SEC-003；全面 async/SSE 运行时合同归 ZS-SEC-012.B。

## 1. 主体类型与 API 前缀推导机制（现状证据）

| 维度 | 代码入口 | 规则 |
|---|---|---|
| 前缀 + 主体推导（编译期） | [ZszjWebAutoConfiguration](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/config/ZszjWebAutoConfiguration.java) | 包路径 `**.controller.admin.**` → 前缀 `/admin-api`；`**.controller.app.**` → `/app-api` |
| 主体类型推导（运行期） | [WebFrameworkUtils#getLoginUserType](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/util/WebFrameworkUtils.java) | 依 `servletPath` 前缀：`/admin-api` → `ADMIN(2)`；`/app-api` → `MEMBER(1)`；其余（如 `/ws`）→ null |
| 用户类型串用校验 | [TokenAuthenticationFilter](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/filter/TokenAuthenticationFilter.java) | `userType != null && notEqual(token.userType, userType)` → `AccessDeniedException("错误的用户类型")` → 403 |

**结论**：主体类型可由包路径**静态判定**，与运行期 `servletPath` 前缀推导一致——清单的「主体类型」列是可靠的静态事实，无需启动上下文。

## 2. 匿名白名单三来源（现状证据）

来源汇总于 [ZszjWebSecurityConfigurerAdapter#filterChain](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/config/ZszjWebSecurityConfigurerAdapter.java)：

| 来源 | 现状 | 说明 |
|---|---|---|
| ① `@PermitAll` 注解（方法级/类级） | **25 个端点** | `getPermitAllUrlsFromAnnotations` 遍历 HandlerMapping 收集，按 HTTP 方法分组放行 |
| ② `zszj.security.permit-all-urls` | 生产默认**空** | [SecurityProperties](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/config/SecurityProperties.java) 默认 `Collections.emptyList()`；仅测试夹具配 `/actuator/health` |
| ③ `AuthorizeRequestsCustomizer` 实现 | 全仓**仅 1 个**（WebSocket） | 其余无自定义放行；本清单不含 WebSocket（非 REST，无 admin/app 前缀） |
| 附：静态资源 | `GET /*.html,/*.css,/*.js` permitAll | 非业务 API，不纳入清单 |
| 附：ASYNC 派发 | `dispatcherTypeMatchers(ASYNC).permitAll()` | 仅放行**异步二次派发**（SSE 续接）；首次 REQUEST 派发仍 `anyRequest().authenticated()`（见 §6） |

> **兜底规则**：以上均未命中的请求 → `anyRequest().authenticated()`（仅需登录，无特定方法权限），清单归类为 `AUTHENTICATED`。

## 3. 静态接口清单（ZS-SEC-002 交付物）

清单生成器 [ApiInventoryTest](../zszj-server/src/test/java/cn/zszj/server/ApiInventoryTest.java)（置于 zszj-server/src/test，仿 [ModuleWhitelistTest](../zszj-server/src/test/java/cn/zszj/server/ModuleWhitelistTest.java) 静态源码扫描约定，**不依赖 Spring 上下文**），遍历启用模块（`ModuleWhitelist.ENABLED_MODULES` = system/infra）的 Controller 源码，每端点编码一行：

```
HTTP方法 | 完整路径（含 /admin-api、/app-api 前缀）| 主体类型 | 授权类别 | 权限标识 | 模块 | Controller
```

基线文件：[api-inventory-baseline.txt](../zszj-server/src/test/resources/api-inventory-baseline.txt)。

### 3.1 清单统计（351 端点，2026-09-25 基线）

| 维度 | 分布 |
|---|---|
| 授权类别 | `ANONYMOUS`=25、`AUTHENTICATED`=59、`PERMISSION`=267 |
| 模块 | system=219、infra=132 |
| HTTP 方法 | GET=174、POST=68、PUT=45、DELETE=64 |
| 主体类型 | ADMIN=346、MEMBER=5 |

> 2026-09-25 随 ZS-CLIENT-002.B 以 `-Dapi.inventory.update=true` 重新生成基线并同步本统计：新增 `GET /admin-api/system/cross-org-visit/my-targets`（`AUTHENTICATED`，仅需登录；仅返回登录主体自身的授权访问目标，fail-closed 空列表）；建立（2026-09-09，328 端点）之后中间各卡对基线的漂移更新未回写本文档，本次一并对齐基线文件事实（328→351）。

**授权类别三分**：`ANONYMOUS`（`@PermitAll`，免登录）/ `PERMISSION`（`@PreAuthorize` hasPermission/hasRole/hasScope，需登录 + 方法权限）/ `AUTHENTICATED`（两者皆无，仅需登录的合法公共能力，逐项编目复核，**不默认判为漏洞**）。

### 3.2 生成与校验命令

```bash

mvn -pl :zszj-server -Dtest=ApiInventoryTest test
# 重新生成基线（仅在评审通过后）
mvn -pl :zszj-server -Dtest=ApiInventoryTest -Dapi.inventory.update=true test
```

## 4. 25 个匿名端点目录（分类 + 理由）

`ApiInventoryTest.ANONYMOUS_CATALOGUE` 强约束：**每个真实匿名端点必须登记理由，目录里每个端点必须真实存在**（双向一致），否则 `anonymousWhitelistMatchesCatalogue` 失败。25 项经复核**均为合法必需能力，无冗余项可移除**：

| # | 端点 | 类别 | 匿名理由 |
|---|---|---|---|
| 1-8 | `POST /admin-api/system/auth/{login,logout,refresh-token,register,sms-login,send-sms-code,reset-password,social-login}` | 认证入口 | 认证前必须免登录（登录/登出/刷新/注册/短信登录/发码/改密/社交登录） |
| 9 | `GET /admin-api/system/auth/social-auth-redirect` | 认证入口 | 第三方社交登录授权回调跳转 |
| 10-11 | `POST /admin-api/system/captcha/{get,check}` | 验证码 | 登录前人机校验 |
| 12-14 | `POST/DELETE /admin-api/system/oauth2/token`、`POST /admin-api/system/oauth2/check-token` | OAuth2 开放端点 | 凭 client_id/client_secret（Basic）自校验，非用户令牌 |
| 15-18 | `POST /admin-api/system/sms/callback/{aliyun,tencent,huawei,qiniu}` | 短信服务商回调 | 外部平台异步回调，无用户令牌（须验签，见 §5.4） |
| 19-21 | `GET /admin-api/system/tenant/{get-id-by-name,simple-list,get-by-website}` | 租户查询 | 登录页按名称/域名定位租户（见 §5.1 枚举面） |
| 22-24 | `GET /app-api/system/{dict-data/type,area/tree,tenant/get-by-website}` | App 公共数据 | 小程序启动即需读取的公共基础数据/租户定位 |
| 25 | `GET /admin-api/infra/file/{configId}/get/**` | 文件读取 | 公开素材下载（私有文件主体绑定归 ZS-FILE-001.A，见 §5.3） |

> 租户匿名端点均标 `@PermitAll @TenantIgnore`（[TenantController](../zszj-module-system/src/main/java/cn/zszj/module/system/controller/admin/tenant/TenantController.java) L44-76），且 `simple-list`/`get-by-website` **只 set `id`+`name`**——TenantRespVO 虽含 contactName/contactMobile/status/websites/packageId，匿名端点显式不填充，敏感字段为 null。

## 5. 审查点（标记待评审 / 后续任务收口）

SEC-002 的「收紧」不是删端点，而是建立**目录 + 漂移门禁**：任何新增/移除匿名端点必须登记理由并通过评审。以下 5 项为登记在册的**残余审查点**，非 SEC-002 阻断项，由对应后续任务收口：

1. **租户枚举面**（`simple-list`）：匿名可获全部**启用**租户的 `id`+`name`（敏感联系字段已不填充，暴露面收敛到登录页选择租户的最小集）。残余「租户名可被匿名枚举」如需进一步收紧，评估速率限制/按需精确查询——归后续硬化（限流/日志归 ZS-SEC-006）。`get-by-website` 已对域名做 `@Pattern` 校验、禁用租户返回 null。
2. **自助注册开放策略**（`register`/`sms-login`/`send-sms-code`）：当前保留 `@PermitAll`；是否对外开放自助注册、发码频率限制由 **ZS-LOGIN-004** 收口。
3. **文件读取授权**（`infra/file/{configId}/get/**`）：公开素材下载合法；私有文件的主体绑定与访问授权归 **ZS-FILE-001.A**（文件票据/取流归 ZS-FILE-004.A，B04）。
4. **短信回调验签**（`sms/callback/*`）：外部平台回调免登录合法，但**须验签**防伪造——真实性/防重放归领域校验（短信模块），SEC-002 仅登记匿名理由。
5. **OAuth2 凭据传输**（`oauth2/token`、`check-token`）：client 凭据 Basic 认证；Authorization 解析规范化、URL 不泄露凭据归 **ZS-SEC-003**。

## 6. 运行时合同复用 ZS-SEC-012.A（覆盖映射）

SEC-002 验收的运行时项由 [SecurityFilterChainFixtureTest](../zszj-framework/zszj-spring-boot-starter-biz-tenant/src/test/java/cn/zszj/framework/security/SecurityFilterChainFixtureTest.java) 覆盖（真实安全链，未禁用任何过滤器）；本次为 SEC-002 新增 `ApiClassificationContract` 组（第 8 组，4 例），夹具达 **35 例全过**：

| SEC-002 验收项 | 覆盖用例 | 归属 |
|---|---|---|
| 匿名仅能访问获准能力 | 静态目录 `anonymousWhitelistMatchesCatalogue` + 夹具 `PublicEndpoints`(3) | SEC-002 + SEC-012.A |
| 缺方法权限不能操作受限动作 | 夹具 `PermissionEndpoints`：`t2AdminLacksUserCreatePermission`、`t1NoPermAdminDenied`(403) | SEC-012.A（既有） |
| 同租户无对象授权仍拒绝 | [DeptDataPermissionChecker](数据权限授权矩阵.md) + 夹具 `ObjectAuthorization`(3) | ZS-PERM-002.A（对象授权轴） |
| ADMIN/MEMBER Token 不能串用 | `AuthEndpoints.memberTokenOnAdminApiRejected`(MEMBER→/admin-api 403) + **新增** `adminTokenOnAppApiRejected`(ADMIN→/app-api 403)/`memberTokenOnAppApiAccepted`(MEMBER→/app-api 200) | SEC-002（补全双向矩阵 + /app-api→MEMBER 推导分支） |
| ASYNC 不使首次受保护请求免认证 | **新增** `asyncEndpointWithoutTokenStillAuthenticated`(无 token→首次 REQUEST 派发 401)/`asyncEndpointWithValidTokenStartsAsync`(有效 token→asyncStarted) | SEC-002（分类完整性） |
| 路由/注解新增致清单变化测试失败并要求评审 | `inventoryMatchesBaseline`（漂移门禁）+ `anonymousWhitelistMatchesCatalogue` | SEC-002 |
| 管理端点复用 ZS-ENG-005 | actuator 仅暴露 health（[ModuleWhitelistTest](../zszj-server/src/test/java/cn/zszj/server/ModuleWhitelistTest.java) 治理兜底路由） | ZS-ENG-005 |

> **ASYNC 边界说明**：`ApiClassificationContract` 的 2 个异步用例证明「静态清单中归为 `AUTHENTICATED` 的异步端点，运行时不会因 `dispatcherTypeMatchers(ASYNC).permitAll()` 被降级为匿名——首次 REQUEST 派发仍强制认证」。这是 SEC-002 的**分类完整性**关切。**全面** async/SSE 运行时合同（流式响应、异步异常出口、跨线程租户上下文传播、[Web]/[移动端] 异步合同同步、真实 PG/Redis）仍归 **ZS-SEC-012.B**（见 [05 文档](../../../docs/05-底座模块分析与开发任务清单.md) ZS-SEC-012 卡「待验收说明」）。

## 7. 漂移门禁与评审流程

1. 开发者新增/修改 Controller 路由或 `@PermitAll`/`@PreAuthorize` 注解 → `mvn -pl :zszj-server -Dtest=ApiInventoryTest test` 因清单漂移**失败**，输出新增/移除端点差异。
2. 若涉及**匿名端点**变动 → `anonymousWhitelistMatchesCatalogue` 额外失败，提示「发现未登记的匿名(@PermitAll)端点，收紧匿名白名单要求先评审理由再登记」。
3. 评审通过（确认新端点分类/权限/匿名理由合理）后 → 更新 `ANONYMOUS_CATALOGUE`（含理由）+ 本文档 §4/§5 → 以 `-Dapi.inventory.update=true` 重新生成基线 → 提交基线 diff 供复审。

## 8. 验收对齐（ZS-SEC-002 卡验收标准）

- **匿名仅能访问获准能力**：25 匿名端点逐项登记理由（§4）+ 目录漂移门禁（§7）；运行时 `PublicEndpoints` 验证 `@PermitAll` 无 token 可访问。
- **缺方法权限不能操作受限动作**：`PERMISSION`=267 端点权限标识入清单 + 结构断言校验合法性；运行时 403 拒绝路径由 `PermissionEndpoints` 覆盖。
- **同租户无对象授权仍拒绝**：对象授权轴归 ZS-PERM-002.A（§6 映射），本清单标方法权限轴，不重复。
- **ADMIN/MEMBER Token 不能串用**：清单「主体类型」列静态判定 + 前缀一致性断言；运行时双向串用矩阵 403/200 全覆盖（§6）。
- **ASYNC 不使首次受保护请求免认证**：§6 分类完整性 2 例 + 边界说明。
- **路由或注解新增致清单变化时测试失败并要求评审**：`inventoryMatchesBaseline` + `anonymousWhitelistMatchesCatalogue` 双门禁（§7）。
- **管理端点复用 ZS-ENG-005**：actuator 仅 health，兜底路由由 ModuleWhitelistTest 治理（§6）。

## 9. 边界与待验收说明

1. 本清单为**启用模块（system/infra）**的静态源码事实来源；未启用模块的兜底路由由 [ZS-ENG-001 ModuleWhitelistTest](../zszj-server/src/test/java/cn/zszj/server/ModuleWhitelistTest.java) 治理，不纳入本清单。后续启用新业务模块（member/mall/…）时，清单随 `ENABLED_MODULES` 自动扩展并经漂移门禁评审。
2. WebSocket（`AuthorizeRequestsCustomizer` 唯一实现）非 REST、无 admin/app 前缀，不在本清单；其凭据传输归 ZS-SEC-003。
3. `AUTHENTICATED`=59 端点为「需登录但无特定方法权限」的合法公共能力（如个人资料、字典读取），**未标 `@PreAuthorize` 不等于漏洞**；若某端点应受方法权限保护却缺失，由漂移门禁在评审中暴露。
4. 本清单不含对象级数据范围授权（dept/self 轴），归 [ZS-PERM-002.A](数据权限授权矩阵.md)；跨租户 visit 授权归 ZS-SEC-001.A/.B。
5. 待验收：本子项以静态清单（351 端点、4/4 结构断言）+ 漂移门禁 + 运行时合同复用（SEC-012.A 夹具 35/35，含新增 4 例）证明接口分类/匿名白名单/方法权限清单已建立并可门禁化；其在真实 PG + 完整多模块启用下的端到端联验随后续模块开发与 ZS-SEC-012.B 收口。
