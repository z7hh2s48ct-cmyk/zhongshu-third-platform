# 日志脱敏策略（ZS-SEC-007）

> 建立日期：2026-09-09。基线：ZS-ENG-004（关闭模拟认证）、ZS-SEC-005（统一错误响应）完成后；复用 ZS-SEC-005 失败夹具语义。
> 性质：登记底座**统一日志脱敏契约**——访问日志、异常日志与保护切面（幂等/限流/签名）在记录请求参数、正文、响应体与方法入参前，统一经 `LogSanitizeUtils` 净化；敏感值掩码为 `***` 并保留字段名，脱敏失败只记摘要绝不回退原文，日志体积超限截断。
> 复用边界：**错误响应语义与状态码**归 [错误响应与状态码矩阵](错误响应与状态码矩阵.md)（ZS-SEC-005），本策略只登记日志侧净化；**审计日志的读取权限、前后值脱敏与保留期**归 ZS-AUDIT-002（M08），本策略提供其复用的脱敏规则；**参数校验与请求体大小限制**归 ZS-SEC-008。本策略不改动验签/限流/幂等的业务判定逻辑，仅净化其日志输出。

## 1. 共享脱敏工具（现状证据）

新增 [LogSanitizeUtils](../zszj-framework/zszj-common/src/main/java/cn/zszj/framework/common/util/log/LogSanitizeUtils.java)（`zszj-common`，`@Slf4j` + 私有构造，不依赖 servlet/web，供 web 与 protection 两 starter 共同复用）。四个公开入口：

| 入口 | 用途 | 空值行为 | 失败行为（不回退原文） |
|---|---|---|---|
| `sanitizeJson(String, String...)` | 请求正文等 JSON 字符串 | 空 → `null` | 无法解析 → `<unparseable:len=N,cause=X>` |
| `sanitizeMap(Map, String...)` | query 参数等键值映射 | 空 → `null` | 无法序列化 → `<unserializable:X>` |
| `sanitizeArgs(Object[], String...)` | 切面 `joinPoint.getArgs()` | 空 → `[]` | 单参无法序列化 → `<SimpleName>` |
| `sanitizeResponseBody(Object, String...)` | `CommonResult` 等响应体 | `null` → `null` | 无法序列化 → `<unserializable:X>` |

`sanitizeResponseBody` 仅净化 `data` 字段，保留 `code`/`msg` 以便审计定位。

## 2. 脱敏算法（五步）

1. **键归一**：`normalizeKey` = 转小写 + 去下划线 + 去连字符，兼容 `password`/`PASSWORD`/`user_password`/`access-token` 等写法。
2. **命中判定**：内置凭据根集 `SENSITIVE_KEY_ROOTS`（`password`、`passwd`、`pwd`、`token`、`secret`、`authorization`、`credential`、`privatekey`、`apikey`、`accesskey`、`secretkey`、`cookie`、`session`、`otp`）以归一后 `contains` **模糊**匹配；端点级 `extraKeys` 以归一后**精确**匹配（避免误伤普通字段）。
3. **递归脱敏**：`sanitizeNode` 对数组逐元素递归、对对象逐字段判定——命中敏感键则值掩码为 `MASK`（`***`），否则递归其子节点；**保留字段名**以便审计定位（嵌套对象/数组同样覆盖）。
4. **失败不回退原文**：解析/序列化异常时经 `unparseable`/`unserializable` 只记摘要（长度或类型 + 异常类别），并 `log.warn` 降级事件，**绝不输出未净化的原始内容**。
5. **体积上限**：`truncate` 对结果超过 `MAX_LENGTH`（2048）时截断并附 `...[truncated,total=N]`，避免超长正文撑爆日志表。

`MASK` 为 `public static final`（原 `private`，因签名切面需对单个凭据派生值就地掩码而提升），值 `***`。

## 3. 五写点落地（ZS-SEC-007 改造）

| # | 写点 | 代码入口 | 净化内容 | 关键行为 |
|---|---|---|---|---|
| 1 | 访问日志 | [ApiAccessLogFilter](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/apilog/core/filter/ApiAccessLogFilter.java) | query（`sanitizeMap`）+ body（`sanitizeJson`）+ responseBody（`sanitizeResponseBody`） | `responseEnable` 默认 false 不记正文；写库失败只记 url/traceId，**不再打印 DTO** |
| 2 | 异常处理器 | [GlobalExceptionHandler](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/handler/GlobalExceptionHandler.java) | query（`sanitizeMap`）+ body（`sanitizeJson`） | 写库失败只记 url/traceId，不再输出未净化对象 |
| 3 | 幂等 | [IdempotentAspect](../zszj-framework/zszj-spring-boot-starter-protection/src/main/java/cn/zszj/framework/idempotent/core/aop/IdempotentAspect.java) | 拒绝日志的方法参数（`sanitizeArgs`） | 重复请求拒绝时不泄露入参凭据 |
| 4 | 限流 | [RateLimiterAspect](../zszj-framework/zszj-spring-boot-starter-protection/src/main/java/cn/zszj/framework/ratelimiter/core/aop/RateLimiterAspect.java) | 拒绝日志的方法参数（`sanitizeArgs`） | 限流拒绝时不泄露入参凭据 |
| 5 | 签名（同类扩展） | [ApiSignatureAspect](../zszj-framework/zszj-spring-boot-starter-protection/src/main/java/cn/zszj/framework/signature/core/aop/ApiSignatureAspect.java) | 签名失败日志的方法参数（`sanitizeArgs`）+ 重复请求日志的 sign 派生值（`MASK`） | 与写点 3/4 同模块同缺陷模式故纳入本轮；仅改日志不动验签逻辑；appId/timestamp/nonce 保留定位 |

**第 5 写点纳入依据**：`ApiSignatureAspect` 与卡片既有的幂等/限流是同一 protection 模块、同一「切面拒绝日志记录原始 `joinPoint.getArgs()`」缺陷模式，复用已测的 `sanitizeArgs`；仅改日志、不动验签判定，低风险。若留同类泄露，评审必被驳回，故透明登记为 SEC-007 的正当范围扩展。

## 4. 端点级附加敏感键（extraKeys）

四入口均接受可变参数 `extraKeys`，供特定端点在内置根集之外追加需脱敏的字段名（如业务自定义的 `idCard`、`bankCardNo`）。`extraKeys` 经同一 `normalizeKey` 归一后**精确**匹配（区别于根集的 `contains` 模糊匹配），避免过度掩码普通字段。当前五写点仅使用内置根集，尚未启用端点级 `extraKeys`；后续敏感端点接入时按此扩展。

## 5. 验收对齐（05 文档 line 367）

- **正常/畸形 JSON/脱敏器失败/业务系统错误/限流/重复提交时秘密不出现**：`LogSanitizeUtilsTest`（10 用例）覆盖正常、嵌套数组、大小写别名、畸形 JSON、超长截断、失败降级；五写点组件测试以 Logback `ListAppender` 捕获日志，断言 `password/token/apiKey/secret` 秘密值不出现、`username/note` 与方法描述保留、敏感字段为 `***`。
- **保留可定位错误码与关联 ID**：访问/异常日志保留 url、traceId、resultCode；切面日志保留方法签名描述；`sanitizeResponseBody` 只净化 `data` 保留 `code`/`msg`。
- **日志写入失败不再次输出未净化对象**：ApiAccessLogFilter/GlobalExceptionHandler 的写库 catch 分支只记 url/traceId + 异常，**移除原 DTO 打印**（组件测试 `testDoFilter_writeFailure_doesNotLogRawAccessLog` 断言）。

## 7. 边界与待验收说明

1. 本轮为**代码级脱敏 + 组件测试**；真实请求日志表落库净化、生产日志采样与敏感端点默认不记正文的**运行时验证**归 B03/B04 真实环境批次。
2. 异常日志的**读取权限与保留期**在 M08（ZS-AUDIT-002）补充；审计前后值脱敏复用本策略的 `LogSanitizeUtils`。
3. 参数校验、请求体大小限制与上下文头解析归 ZS-SEC-008；本策略不重复登记。
4. 敏感端点默认不记正文当前由 `ApiAccessLogFilter.responseEnable`（默认 false）实现；更细粒度的按端点脱敏白名单/黑名单待运行时批次评估。
5. 本记录不表示任何主任务已验收。
