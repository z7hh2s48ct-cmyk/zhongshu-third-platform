# 定时任务与后台任务启停盘点（ZS-ENG-006）

> 核查日期：2026-09-09；基线：ZS-ENG-005 之后（模块白名单 system/infra）
> 结论：本地/部署默认不开业务定时任务；仅保留无业务副作用的框架内部维护调度；全部边界可经配置/依赖闭包关闭。

## 1. 调度器层

| 项 | 位置 | 当前边界 | 副作用 |
|---|---|---|---|
| Quartz 调度器（业务 Job 执行器） | local：`spring.autoconfigure.exclude` 排除 `QuartzAutoConfiguration`，且 `spring.quartz.auto-startup` 改为默认 false（ZSZJ_QUARTZ_AUTO_STARTUP 可显式开启）；dev（测试环境 profile）：显式开启并注释"需要开启 Job"；部署模板默认 false | **local/部署默认关闭；dev 为测试环境显式开启**。开启须同时：引入 job starter + 移除 exclude + 显式开启 auto-startup + infra_job 表存在登记记录 | 业务 Job（见第 2 节）仅在 Quartz 调度下运行 |
| Spring @EnableScheduling（job starter） | `zszj-framework/zszj-spring-boot-starter-job/.../ZszjQuartzAutoConfiguration` | 随 starter 在依赖闭包内即生效；本身不产生任务，只启用 @Scheduled 处理器 | 无直接副作用 |
| Spring @EnableScheduling（mq starter） | `zszj-framework/zszj-spring-boot-starter-mq/.../ZszjRedisMQConsumerAutoConfiguration` | 同上；服务于第 3 节内部维护任务 | 无直接副作用 |

## 2. 业务定时任务（Quartz JobHandler，需显式登记才会执行）

| 任务 | 位置 | 用途 | 副作用 | 默认状态 |
|---|---|---|---|---|
| JobLogCleanJob / AccessLogCleanJob / ErrorLogCleanJob | `zszj-module-infra/.../job/` | 清理过期任务/访问/错误日志 | 删除历史日志（有保留期参数） | 仅当 Quartz 开启且 infra_job 登记后执行；本地与部署默认关闭 |

其余启用模块（system）无 Quartz JobHandler；未启用模块（bpm/mall/...）虽含 JobHandler 源码，但不在依赖闭包内，不会装配（ZS-ENG-001 白名单保证）。

## 3. 框架内部维护调度（@Scheduled，允许保留的必要内部调度）

| 任务 | 触发 | 用途 | 副作用 | 边界 |
|---|---|---|---|---|
| RedisPendingMessageResendJob | cron 每分钟（35s） | 重发 Redis Stream Pending 消息，避免消费丢失 | 仅重投递框架消息，无业务写入 | `@ConditionalOnBean(AbstractRedisStreamMessageListener)`：仅当业务声明了 Stream 监听器才装配；当前启用模块（system/infra）未声明 → 不装配 |
| RedisStreamMessageCleanupJob | 定时清理 | 清理已消费完的 Redis Stream | 删除空 Stream 队列 | 同上，条件装配 |
| MpAccountServiceImpl 内部刷新 | 定时刷新公众号 access_token | mp 模块（未启用） | — | 不在依赖闭包，不装配 |

## 4. 其他条件式后台机制

| 机制 | 说明 | 边界 |
|---|---|---|
| Spring @EnableAsync（ZszjAsyncAutoConfiguration） | 异步线程池（TTL 装饰），服务业务异步执行 | 非定时任务；随 starter 生效，线程池参数走框架默认 |
| Redisson/缓存内部维护 | Redisson 客户端内部看门狗等 | 框架必要内部调度，无业务副作用，不关闭 |
| Spring Boot Admin（监控） | 无后台任务；端点暴露已按 ZS-ENG-005 收紧 | 部署模板客户端默认关闭 |

## 5. 边界决定

1. 业务定时任务的唯一入口是 Quartz + infra_job 登记记录；local 与部署模板默认关闭（`auto-startup: false`），启用须过本盘点表评估数据副作用。
2. 第 3 节内部维护调度均为条件装配且当前不满足装配条件，无需额外开关；若未来启用 Redis Stream MQ，这两项属必要基础设施调度，随消息功能验收一并放行。
3. 未启用模块的后台任务源码保留但不装配（ZS-ENG-001 白名单）。
4. 后续新增任何 @Scheduled / Quartz Job，必须先在本盘点表登记用途、开关与副作用（纳入 ZS-JOB-001 的持续范围）。
