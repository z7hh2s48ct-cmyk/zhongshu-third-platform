## 2. 独立测试环境部署步骤

### 2.1 前提

- Docker Engine ≥ 24，Docker Compose V2（`docker compose` 子命令）
- 已构建 `zszj-server:latest` 镜像（或可访问的私有 registry，地址填入 compose）
- TLS 证书（自签名或 Let's Encrypt）放置于 `services/zhongshu-core/deploy/tls/` 目录
- `services/zhongshu-core/script/config/application-prod.yaml` 存在（ZS-ENG-003 交付）

### 2.2 部署

```bash
cd services/zhongshu-core/deploy

# 1. 复制配置合同模板
cp .env.example .env

# 2. 填入真实值（数据库口令、Redis 口令等）
#    .env 已在 .gitignore 中，禁止提交
vim .env

# 3. 启动（后台）
docker compose -f docker-compose.deploy.yml up -d

# 4. 等待健康检查通过（约 60–90s）
docker compose -f docker-compose.deploy.yml ps
```

### 2.3 撤回

```bash
cd services/zhongshu-core/deploy

# 停止并删除容器（保留数据卷）
docker compose -f docker-compose.deploy.yml down

# 完全清除（含数据卷——⚠ 会删除数据库数据）
docker compose -f docker-compose.deploy.yml down -v
```

## 3. 配置注入合同

### 3.1 合同变量（必填）

所有变量定义见 `.env.example`；缺任一必填项时 `zszj-server` 应启动失败并输出明确错误，不得静默降级。

| 变量名 | 说明 | 来源 |
|---|---|---|
| `ZSZJ_SERVER_PORT` | HTTP 端口（默认 48080，与 Dockerfile EXPOSE 一致） | ENG-003 |
| `ZSZJ_PROFILE` | Spring Profile（prod/staging/test） | ENG-003 |
| `ZSZJ_PG_BOOTSTRAP_USERNAME` | PostgreSQL 初始化超级用户（owner，仅首次建库） | DB-002 |
| `ZSZJ_PG_BOOTSTRAP_PASSWORD` | PostgreSQL 初始化超级用户口令 | DB-002 |
| `ZSZJ_DATASOURCE_URL` | JDBC URL，格式 `jdbc:postgresql://HOST:PORT/DB` | ENG-003 |
| `ZSZJ_DATASOURCE_USERNAME` | 应用账号（zhongshu_app，低权限，非 owner） | DB-002 |
| `ZSZJ_DATASOURCE_PASSWORD` | 应用账号口令，秘密管理注入 | CFG-001.A |
| `ZSZJ_REDIS_HOST` | Redis 主机（容器内填 `redis`） | ENG-003 |
| `ZSZJ_REDIS_PORT` | Redis 端口（默认 6379） | ENG-003 |
| `ZSZJ_REDIS_PASSWORD` | Redis 口令，秘密管理注入 | CFG-001.A |
| `ZSZJ_TLS_CERT_PATH` | TLS 证书宿主机路径（volume mount 注入 nginx） | 本批新增 |
| `ZSZJ_TLS_KEY_PATH` | TLS 私钥宿主机路径（volume mount 注入 nginx） | 本批新增 |

### 3.2 凭据分离（ZS-DB-002）

PostgreSQL 使用两套凭据：
- **Bootstrap/Owner**（`ZSZJ_PG_BOOTSTRAP_*`）：首次初始化时创建数据库和 schema，拥有 DDL 权限，仅供 Flyway 迁移使用
- **Application**（`ZSZJ_DATASOURCE_*`）：日常运行使用的低权限账号（zhongshu_app），仅有 CRUD 权限

compose 中 `postgres` 服务使用 bootstrap 凭据初始化；`zszj-server` 使用 application 凭据连接。

**应用角色自动 provision（codex r1 P1 修复）**：PostgreSQL 官方镜像首次初始化仅创建 `POSTGRES_USER`（即 bootstrap owner），不会自动创建应用账号。为此 compose 将 `postgres-init/` 挂载到 `/docker-entrypoint-initdb.d`，其中的 `01-create-app-role.sql` 在首次建库时自动执行：从环境变量 `ZSZJ_DATASOURCE_USERNAME/PASSWORD` 读取应用凭据，`CREATE ROLE`（若不存在）并授予 public schema 的 CRUD 权限与默认权限。因此**全新数据卷部署后 zhongshu_app 即可认证**，无需手工建角色。

> ⚠ 该脚本仅在**数据卷首次初始化**时由镜像入口自动执行。若复用已有数据卷（角色未建）或 Flyway 迁移后新增表，需按脚本尾部说明手动重跑 GRANT（对已存在对象授权）。此为 .A 批次的模板级说明，真实环境执行属 B02/B03。

### 3.3 Spring Boot 3.x 属性映射

本项目使用 Spring Boot 3.x，Redis 属性路径为 `spring.data.redis.*`（非 2.x 的 `spring.redis.*`）。
`application-prod.yaml`（ZS-ENG-003）已正确映射，compose 通过 volume mount 注入该配置文件。

数据源使用 `dynamic-datasource` starter，属性路径为 `spring.datasource.dynamic.datasource.master.*`。
`application-prod.yaml` 中的 `ZSZJ_*` 占位符由 compose 环境变量解析。

**挂载路径必须匹配镜像 WORKDIR（codex r1 P1 修复）**：`zszj-server/Dockerfile` 设置 `WORKDIR /zszj-server`，Spring Boot 外部化配置默认搜索 `<workdir>/config/`，因此 compose 将 `application-prod.yaml` 挂载到 `/zszj-server/config/application-prod.yaml`（**不是** `/app/config/`）。挂错路径会导致 `prod` profile 下配置被忽略、`ZSZJ_DATASOURCE_*` 占位符无法解析、数据源初始化失败。

### 3.4 与 ZS-CFG-001.A 的关系

本配置合同是 ZS-CFG-001.A「部署合同」的具体化实现（模板层），秘密扫描（`scripts/cfg/verify-config-secrets.mjs`）与本批校验脚本（`scripts/ops/verify-deploy-templates.mjs` C1 项）使用相同判定口径，不重复记账。

### 3.5 敏感项红线

- `*_PASSWORD`、`*_KEY`、`*_TOKEN` 类值：禁止出现在任何已提交文件中
- TLS 私钥内容：禁止嵌入 compose 或 nginx.conf，必须通过 volume mount 注入
- `.env` 文件：禁止提交（已在 `.gitignore`）
- 命令行参数中的凭据（如 `--requirepass`）：必须使用 `${VAR}` 占位符，禁止硬编码

## 4. 探针边界

### 4.1 actuator 暴露（ZS-ENG-005 已收紧）

`application.yaml`（所有 Profile）中：
```yaml
management:
  endpoints:
    web:
      base-path: /actuator
      exposure:
        include: health    # 仅 health，不含 env/beans/configprops 等敏感端点
```

### 4.2 Docker healthcheck（容器内探针）

compose 中 `zszj-server` 的 healthcheck 调用 `/actuator/health/liveness`：
```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:${ZSZJ_SERVER_PORT}/actuator/health/liveness"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 60s   # JVM 冷启动宽限期，避免误报 unhealthy
```

`MANAGEMENT_ENDPOINT_HEALTH_PROBES_ENABLED=true` 通过 compose 环境变量注入，激活 liveness/readiness 子路径。

### 4.3 探针不对公网暴露

Nginx 在 TLS 终结层关闭了 `/actuator/` 路径（`deny all; return 403;`），公网无法访问任何 actuator 端点。探针调用仅发生在 Docker 内部网络（localhost healthcheck）。

### 4.4 依赖不可用时的明确失败

| 依赖 | 不可用时行为 | 可观测信号 |
|---|---|---|
| PostgreSQL | Flyway 迁移失败，容器启动中止，`depends_on: condition: service_healthy` 阻止 zszj-server 启动 | compose ps 显示 postgres `unhealthy`；zszj-server 处于 `created` 状态 |
| Redis | Spring Boot RedisHealthIndicator 报 DOWN；healthcheck 失败后 Docker 重启容器 | `/actuator/health` 返回 `{"status":"DOWN"}` |
| TLS 证书缺失 | Nginx 启动失败（`cannot load certificate`），容器立即退出 | `docker logs zszj-nginx` 显示错误 |

## 5. TLS / 反向代理边界

### 5.1 TLS 终结架构

```
客户端 → :443 (nginx, TLS) → zszj-internal 网络 → zszj-server:48080 (HTTP)
```

zszj-server 不直接暴露到公网；公网流量必须经过 nginx TLS 终结。

### 5.2 证书管理

- 证书文件（`fullchain.pem`、`privkey.pem`）放置于宿主机 `deploy/tls/` 目录
- 通过 docker-compose volume mount（`:ro`）注入 nginx 容器
- 证书路径通过 `ZSZJ_TLS_CERT_PATH` / `ZSZJ_TLS_KEY_PATH` 环境变量配置
- 禁止将证书文件提交到版本库（`tls/*.pem` 已在 `.gitignore`）

### 5.3 敏感管理路径关闭

nginx.conf 中：
```nginx
location /actuator/ { deny all; return 403; }
location /admin/    { deny all; return 403; }
```

可审查性校验（C3 项）自动验证这两条规则存在，且排除注释行（注释掉的 deny 不算有效关闭）。

### 5.4 WebSocket 转发

后端启用 `/infra/ws` WebSocket 端点（admin-web 和 miniapp 客户端连接）。
nginx 配置了 HTTP/1.1 升级头转发：
```nginx
location /infra/ws {
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

### 5.5 端口固定说明

nginx upstream 硬编码 `zszj-server:48080`。`ZSZJ_SERVER_PORT` 默认值为 48080；
如修改此值，须同步更新 `nginx/zszj-server.conf` 中的 `proxy_pass` 端口。
本批模板不支持动态端口渲染（属 .B/.C 批次增强范围）。

## 6. 可审查性校验说明

### 6.1 校验项

| 编号 | 规则 | 说明 |
|---|---|---|
| C1 | 模板无真实秘密 | 检测硬编码口令、PEM 私钥块、长十六进制串（≥32 字符）、命令行参数凭据（含 YAML exec-list 形式，如 `["--requirepass","x"]` / `["redis-cli","-a","x"]`） |
| C2 | 探针路径与 actuator include 一致 | compose 须含 healthcheck；zszj-server 须有专属 /actuator 探针 |
| C3 | 敏感管理路径在反代中关闭 | nginx.conf 必须含 deny /actuator/ 和 /admin/（注释行无效） |
| C4 | 内部端口不公开暴露 | 按容器端口分类（防 15432:5432 绕过）；127.0.0.1 绑定放行 |
| C5 | 环境变量合同双向一致 | .env.example 必须含全部合同变量；compose 引用的变量必须在合同表中 |

### 6.2 运行方式

```bash
# 对当前树全量扫描（退出码 0=通过，1=有 issue）
node scripts/ops/verify-deploy-templates.mjs

# 负向对照（证明校验非空洞，12 项全 PASS）
node scripts/ops/verify-deploy-templates.mjs --self-test
```
