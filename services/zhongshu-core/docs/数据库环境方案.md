# 数据库环境方案（ZS-DB-002 · PEND-004 配套）

> 编制日期：2026-09-09。本文件是**方案与操作模板**：真实环境创建/授权动作必须在目标与授权明确后，
> 由环境负责人按本方案人工执行（05 文档 ZS-DB-002："真实环境创建动作须在明确目标和授权后执行"）。
> 执行后按第 6 节核验清单回填 PEND-004。

## 1. 实例与库规格

| 项 | 要求 | 依据 |
|---|---|---|
| 版本 | PostgreSQL 17（16 可接受；14 不作基线） | PEND-004 建议 |
| 实例 | 独立实例或独立集群，不与无关项目共用 | 隔离边界 |
| 数据库 | 单库（建议名 `zhongshu`，核验时与负责人确认） | D-08 仅 PG；ZS-DB-004 V1 基线为唯一初始化入口 |
| 时区/编码 | `Asia/Shanghai` / `UTF8` | 建库参数 |
| 扩展 | 基线 V1 无需额外扩展；如后续迁移引入扩展，须作为迁移文件前置检查 | ZS-DB-003 |
| 资源 | 容量/RPO/RTO 目标待负责人确认（联动 ZS-OPS-002 演练） | — |

## 2. 账号分离（迁移账号 ≠ 应用账号）

| 角色 | 建议名 | 权限 | 用途 |
|---|---|---|---|
| 管理员（库属主） | `zhongshu_owner` | 库内 CREATE/ALTER/DROP | 仅 Flyway 迁移连接使用（`ZSZJ_FLYWAY_USER`） |
| 应用账号 | `zhongshu_app` | 表/序列 CRUD（SELECT/INSERT/UPDATE/DELETE/USAGE），无 DDL | 应用日常运行（`ZSZJ_DATASOURCE_USERNAME`） |
| 只读账号（可选） | `zhongshu_ro` | SELECT | 报表/审计查询，后续按需 |

授权操作模板（由 owner 在目标库执行一次；迁移新建对象后须补授，ZS-DB-005 规程覆盖）：

```sql
-- 以超管在建库后执行
CREATE ROLE zhongshu_owner LOGIN PASSWORD '<由秘密管理注入>';
CREATE ROLE zhongshu_app  LOGIN PASSWORD '<由秘密管理注入>';
GRANT ALL ON SCHEMA public TO zhongshu_owner;
GRANT USAGE ON SCHEMA public TO zhongshu_app;
-- 迁移执行后（Flyway V1 建表完成）：
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO zhongshu_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO zhongshu_app;
ALTER DEFAULT PRIVILEGES FOR ROLE zhongshu_owner IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO zhongshu_app;
ALTER DEFAULT PRIVILEGES FOR ROLE zhongshu_owner IN SCHEMA public
  GRANT USAGE, SELECT ON SEQUENCES TO zhongshu_app;
```

口令不入库：经秘密管理注入环境变量（ZS-CFG-001.A 合同），本文件与任何提交内容不得出现真实口令。

## 3. 初始化顺序

1. 建库（owner 执行）：`CREATE DATABASE zhongshu ENCODING 'UTF8' TEMPLATE template0;`
2. 应用启动一次并置 `ZSZJ_FLYWAY_ENABLED=true` + Flyway 凭据=owner（ZS-DB-003）：执行 V1 基线。
3. 补授 app 账号（第 2 节模板"迁移执行后"部分）。
4. 应用改用 app 凭据运行——**日常运行不使用高权限迁移凭据**。
5. 初始管理员：`sql/postgresql/init-admin.sql.example` 安全初始化（ZS-DB-004）。

## 4. 备份与恢复（规程模板，演练归 ZS-OPS-002）

- 逻辑备份：每日 `pg_dump -Fc -U zhongshu_owner zhongshu > zhongshu_$(date +%F).dump`，保留策略由负责人确认。
- 恢复演练：恢复到独立临时库（可用 ZS-DB-019.A 夹具脚本）→ 应用以 app 账号连临时库冒烟 → 比对核心表行数与关键种子。
- 实测 RPO/RTO 与容量数据在演练后回填本节，不得预先声称达标。

## 5. 隔离边界

- 应用账号不得访问其他项目数据（仅授予本库 USAGE/CRUD）。
- 迁移账号仅部署/升级时使用，不进入应用默认配置。
- 临时测试库一律使用 ZS-DB-019.A 夹具创建（一次性容器，自动清理），禁止复用任何持久环境做测试。
