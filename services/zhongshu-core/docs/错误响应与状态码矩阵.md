# 错误响应与状态码矩阵（ZS-SEC-005）

> 建立日期：2026-09-09。基线：ZS-SEC-002（接口清单与匿名白名单）、ZS-SEC-012.A（真实安全链夹具）、ZS-PERM-002.A（数据权限授权矩阵）完成后。
> 性质：登记底座**统一错误响应契约**——HTTP 传输层固定 `200`，业务结果由 `CommonResult.code` 表达（业务码刻意镜像 HTTP 语义）；统一 filter-direct 出口使其登记 `common_result`，令 API 访问日志按业务码记录（不再误记成功）；畸形 JSON / 请求体类型错误归 `400` 客户端错误且不回显敏感入参值。
> 复用边界：**运行时安全链行为**（401/403 出口、跨层一致语义、畸形 JSON）复用 [ZS-SEC-012.A 夹具第 9 组](../zszj-framework/zszj-spring-boot-starter-biz-tenant/src/test/java/cn/zszj/framework/security/SecurityFilterChainFixtureTest.java)，本矩阵不重写；Token 传输/凭据规范归 ZS-SEC-003；异常日志脱敏（对内可追踪、对外不外泄）归 ZS-SEC-007；限流 `429` 的产生机制归对应限流任务，本矩阵只登记其响应语义。**本矩阵不承诺所有请求都强行包 CommonResult**（如 SSE / 文件流 / 静态资源）。

## 1. 错误响应契约（现状证据）

底座 API 统一以 HTTP `200` 传输 + `CommonResult{code, msg, data}` 表达业务结果：`code=0` 为成功，其余为业务码。[GlobalErrorCodeConstants](../zszj-framework/zszj-common/src/main/java/cn/zszj/framework/common/exception/enums/GlobalErrorCodeConstants.java) 注释原文：「一般情况下，使用 HTTP 响应状态码……因为之前一直使用 0 作为成功，就不使用 200 啦」——即业务码镜像 HTTP 语义，唯成功用 `0`。

| 出口 | 代码入口 | 是否设 HTTP 状态 | 是否登记 common_result（访问日志结果来源） |
|---|---|---|---|
| MVC 正常/异常返回 | [GlobalResponseBodyHandler](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/handler/GlobalResponseBodyHandler.java) `beforeBodyWrite` | 否（恒 200） | **是**（既有） |
| filter 直接写出（修复前） | [ServletUtils#writeJSON](../zszj-framework/zszj-common/src/main/java/cn/zszj/framework/common/util/servlet/ServletUtils.java) | 否（恒 200） | **否** → 访问日志误记 SUCCESS(0) |
| filter 直接写出（ZS-SEC-005 修复后） | [WebFrameworkUtils#writeJSON](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/util/WebFrameworkUtils.java) | 否（恒 200） | **是**（setCommonResult + 写体） |

访问日志结果码来源：[ApiAccessLogFilter](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/apilog/core/filter/ApiAccessLogFilter.java) `buildApiAccessLog` 读取 `WebFrameworkUtils.getCommonResult(request)`；若为 null 且无异常（`ex==null`）则落 `SUCCESS`——这正是 filter-direct 出口修复前被误记为成功的根因。

## 3. HTTP 传输状态 × 业务码矩阵

所有 REST 错误响应 HTTP 传输状态恒为 `200`；下表「业务码」列即 `CommonResult.code`，「访问日志（修复前→后）」列体现 ZS-SEC-005 的核心修复。

| 场景 | 执行层 | HTTP | 业务码 | msg 来源 | 访问日志结果（修复前→后） |
|---|---|---|---|---|---|
| 未登录访问受保护端点 | filter-direct（[AuthenticationEntryPointImpl](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/handler/AuthenticationEntryPointImpl.java)） | 200 | 401 | UNAUTHORIZED | SUCCESS(0) → **401** |
| 已登录无 URL 级权限 | filter-direct（[AccessDeniedHandlerImpl](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/handler/AccessDeniedHandlerImpl.java)） | 200 | 403 | FORBIDDEN | SUCCESS(0) → **403** |
| 方法级 @PreAuthorize 拒绝 | MVC（[GlobalExceptionHandler](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/handler/GlobalExceptionHandler.java) accessDenied） | 200 | 403 | FORBIDDEN | 403（既有，MVC 登记） |
| 越权访问他租户数据 | filter-direct（[TenantSecurityWebFilter](../zszj-framework/zszj-spring-boot-starter-biz-tenant/src/main/java/cn/zszj/framework/tenant/core/security/TenantSecurityWebFilter.java)） | 200 | 403 | 「您无权访问该租户的数据」 | SUCCESS(0) → **403** |
| 未传租户标识 | filter-direct（TenantSecurityWebFilter） | 200 | 400 | 「请求的租户标识未传递，请进行排查」 | SUCCESS(0) → **400** |
| 租户禁用/过期/不存在 | filter-direct（TenantSecurityWebFilter → allExceptionHandler） | 200 | 403/400 | ServiceException | SUCCESS(0) → **业务码** |
| Token 校验异常 | filter-direct（[TokenAuthenticationFilter](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/filter/TokenAuthenticationFilter.java) → allExceptionHandler） | 200 | 视异常 | allExceptionHandler | SUCCESS(0) → **业务码** |
| 演示模式写操作 | filter-direct（[DemoFilter](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/filter/DemoFilter.java)） | 200 | 901 | DEMO_DENY | SUCCESS(0) → **901** |
| 加密请求解密失败 | filter-direct（[ApiEncryptFilter](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/encrypt/core/filter/ApiEncryptFilter.java) → allExceptionHandler） | 200 | 视异常 | allExceptionHandler | SUCCESS(0) → **业务码** |
| 畸形 JSON / 请求体不可解析 | MVC（GlobalExceptionHandler httpMessageNotReadable） | 200 | **400**（修复前 500） | 「请求参数格式错误：无法解析请求体…」 | 400（MVC 登记） |
| 请求体字段类型错误 | MVC（GlobalExceptionHandler invalidFormat） | 200 | 400 | 「请求参数类型错误：期望类型 X」（**不回显入参值**） | 400 |
| 限流触发 | 限流组件（归对应任务） | 200 | 429 | TOO_MANY_REQUESTS | 429 |
| 未捕获异常 | MVC（GlobalExceptionHandler default） | 200 | 500 | 「系统异常」（对外脱敏）+ 内部异常日志 | 500 |

## 4. filter-direct 出口统一（ZS-SEC-005 改造）

新增统一出口 [WebFrameworkUtils#writeJSON(request, response, result)](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/util/WebFrameworkUtils.java)：内部 `setCommonResult(request, result)` + `ServletUtils.writeJSON(response, result)`。**不改 HTTP 状态码**（保持 200 传输契约），仅补登记 `common_result`，使访问日志按业务码记录。之所以落在 `WebFrameworkUtils`（web starter）而非 `ServletUtils`（common）：`setCommonResult` 属性读写在 web starter，common 不可反向依赖 web。

改造的 6 文件 8 调用点（原 `ServletUtils.writeJSON(response, …)` → `WebFrameworkUtils.writeJSON(request, response, …)`）：

| # | 文件 | 出口 | 业务码 |
|---|---|---|---|
| 1 | [AuthenticationEntryPointImpl](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/handler/AuthenticationEntryPointImpl.java) | 未认证 401 | 401 |
| 2 | [AccessDeniedHandlerImpl](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/handler/AccessDeniedHandlerImpl.java) | URL 级拒绝 403 | 403 |
| 3 | [TokenAuthenticationFilter](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/filter/TokenAuthenticationFilter.java) | Token 校验异常 | allExceptionHandler |
| 4–6 | [TenantSecurityWebFilter](../zszj-framework/zszj-spring-boot-starter-biz-tenant/src/main/java/cn/zszj/framework/tenant/core/security/TenantSecurityWebFilter.java) | 越权 403 / 缺租户 400 / 无效租户 | 403 / 400 / allExceptionHandler |
| 7 | [DemoFilter](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/filter/DemoFilter.java) | 演示模式 901 | 901 |

## 5. 畸形 JSON 归 400 且不回显敏感值（ZS-SEC-005 改造）

[GlobalExceptionHandler#methodArgumentTypeInvalidFormatExceptionHandler](../zszj-framework/zszj-spring-boot-starter-web/src/main/java/cn/zszj/framework/web/core/handler/GlobalExceptionHandler.java)：

| 分支 | 修复前 | 修复后 |
|---|---|---|
| InvalidFormatException（字段类型错误） | `400` + msg 回显 `invalidFormatException.getValue()`（**泄露敏感入参值**） | `400` + msg 仅提示期望类型 `getTargetType().getSimpleName()`，**不回显入参值** |
| request body 缺失 | `400`「request body 缺失」 | 不变 |
| 其它解析失败（畸形 JSON 等） | fall-through `defaultExceptionHandler` → **`500` 系统异常** + 异常日志 | **`400` 客户端错误**「请求参数格式错误：无法解析请求体，请检查是否为合法 JSON」，不落 500、不回显报文 |

## 6. 两端请求层处理映射（方案A：零改动，仅验证）

底座保持 HTTP 200 + 业务码契约，两端**无需改动**。核对如下：

| 端 | 请求层 | 401 处理 | 其它业务码 |
|---|---|---|---|
| Web 管理端 | [service.ts](../../../apps/zhongshu-admin-web/src/config/axios/service.ts) axios response 拦截器**成功回调**（仅 2xx 触发） | `code===401` → 无感刷新令牌；刷新失败跳登录 | 500 / 901 / generic 提示 |
| 移动端 | [http.ts](../../../apps/zhongshu-miniapp/src/http/http.ts) uni.request `success` 回调（所有状态码触发） | `statusCode===401 \|\| code===401` → 刷新 / 跳登录 | 非 2xx 兜底 toast + reject |

**关键约束（选定方案A 的依据）**：Web axios 的 `code===401` 刷新逻辑位于**成功回调**内，仅当 HTTP 2xx 才触发；若后端改真实 HTTP 401，刷新链断裂。故 ZS-SEC-005 保持 HTTP 200 传输，仅统一日志结果语义——两端零改动、仅验证。

## 7. 验收对齐（05 文档 line 350）

- **同类错误跨层一致语义**：401/403/400 无论 filter-direct 或 MVC，均 HTTP200 + 镜像业务码（夹具第 9 组 `forbiddenConsistentAcrossLayers`）。
- **畸形 JSON 是客户端错误且不回显敏感值**：`malformedJsonIsBadRequest`（400 非 500）+ `invalidFormatDoesNotEchoSensitiveValue`（响应体不含敏感值）。
- **401/403/429/5xx 不记为成功**：filter-direct 出口登记 common_result（夹具 `commonResultCode` 断言 = ApiAccessLogFilter 读取值），修复前误记 SUCCESS(0)。
- **两端刷新/跳转/提示/下载错误正常**：方案A 保持 HTTP200 + 业务码，两端零改动（§6）。
- **未知异常对外脱敏、对内可追踪**：`defaultExceptionHandler` 对外「系统异常」+ 内部 createExceptionLog（既有，未改；深化归 ZS-SEC-007）。
- **不承诺所有请求都强行包 CommonResult**：SSE / 文件流 / 静态资源不在此契约内。

## 8. 边界与待验收说明

1. 本矩阵只登记**响应语义与日志结果**；限流 `429` 的产生（阈值/算法）、Token 传输规范、异常日志脱敏深化分别归对应任务（ZS-SEC-003 / ZS-SEC-007 / 限流任务）。
2. 访问日志「不记为成功」的验证以夹具断言 `WebFrameworkUtils.getCommonResult(request)`（= ApiAccessLogFilter.buildApiAccessLog 的输入）为回归护栏；ApiAccessLogFilter 完整落库联验随 infra 日志链路在后续批次收口。
3. 方案A 为**非破坏**改造：HTTP 传输状态维持 200，不引入真实 4xx/5xx 状态码（避免断 Web axios 刷新链、控制回归面）。若未来两端请求层改造为兼容真实状态码，可另立任务评估方案B。
4. 待验收：本子项以 SEC-012.A 夹具（41/41，含新增第 9 组 6 例）+ web/security/biz-tenant 编译通过证明；端到端联验随 ZS-SEC-012.B / ZS-SYS-001.A 在 B03/B04 收口。
