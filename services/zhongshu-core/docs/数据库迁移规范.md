# 数据库迁移规范（ZS-DB-003 · PEND-005 技术结论）

> 冻结日期：2026-09-09；关联决策：D-08（仅 PostgreSQL）
> 本文档是版本化数据库迁移的唯一规范；`sql/postgresql/` 下的历史脚本保留为来源证据，
> 不是可执行的第二套初始化入口（其整理后的产物即本目录 V1 基线迁移，由 ZS-DB-004 交付）。

## 1. 机制与依赖

| 项 | 决定 |
|---|---|
| 迁移机制 | Flyway，版本随 Spring Boot 3.5 BOM 管理，另引入 `flyway-database-postgresql` |
| 权威入口 | **应用启动时执行**（`spring.flyway.*`），不引入第二套初始化脚本或独立迁移 CLI |
| 历史表 | `flyway_schema_history`（默认名，不改） |
| 版本号规则 | `V<yyyyMMdd>.<NNN>__<module>_<描述>.sql`，如 `V20260909.001__infra_demo_baseline.sql`；版本号全局唯一、按字典序即执行序 |
| out-of-order | **false**（多实例发布遵循"先兼容迁移后滚动重启"：加可空列→回填→加约束） |
| 篡改防护 | `validate-on-migrate: true`：已执行脚本内容变更（校验和失配）将阻止应用启动 |
| 误清理防护 | `clean-disabled: true`（全环境硬禁用 clean）；测试库清理由 ZS-DB-019 临时实例夹具负责，应用配置永不提供 clean 能力 |
| 既有库吸收 | `baseline-on-migrate: true` + `baseline-version: 20260909.001`（与 V1 基线迁移版本一致）：以旧 dump 手工建的库首次接入时按该版本建立基线，V1 不重放，后续版本正常应用；结构性差异以更新版本号的差异迁移表达 |
| 凭据分离 | `spring.flyway.url/user/password` 显式注入，默认回落应用数据源；需要更高 DDL 权限时配置专用迁移账号（ZS-DB-002 权限模型），运行凭据不承担迁移 |

## 2. 目录与命名

```
zszj-server/src/main/resources/db/migration/   # 唯一迁移目录（单一 location）
  V20260909.001__system_xxx.sql
  V20260909.002__infra_xxx.sql
```

- 版本号规则：`V<8位日期>.<3位当日序号>`，同日多个迁移顺延序号；跨日必须用新日期，禁止篡改已提交的版本号。
- 描述段以启用模块/归属开头（`system_`、`infra_`、`platform_` 工程级），小写下划线。
- 每个迁移文件必须幂等安全的设计目标：重跑由 Flyway 历史表防重，文件内部不使用不可回退的破坏性语句，除非在文件头注释中显式声明影响与恢复方式。
- 逆向脚本：社区版不自动执行回滚；破坏性变更须在文件头注释登记人工回滚步骤，执行前核对数据。

## 3. 环境开关

| 环境 | 状态 |
|---|---|
| 基础配置（application.yaml） | `spring.flyway.enabled: false`（V1 基线迁移由 ZS-DB-004 交付后，在部署环境激活） |
| local/dev | 默认关闭；需要时经环境变量显式开启 |
| 部署模板 | `spring.flyway.enabled: ${ZSZJ_FLYWAY_ENABLED:false}`，连接默认回落应用数据源，可用 `ZSZJ_FLYWAY_URL/USER/PASSWORD` 注入专用迁移凭据 |

## 4. 检查入口

- 静态规范检查：`node scripts/db/verify-flyway-migrations.mjs`（命名/唯一性/配置断言）
- 真实库验收（B02）：空库全新执行、旧库 baseline 吸收、重跑幂等、篡改校验和阻止启动、低权限凭据启动——归 ZS-DB-003 的 B02 验收与 ZS-DB-005 升级规程。
