# 底座功能目录（ZS-CFG-003.A）

> 核对日期：2026-09-09；唯一事实来源：[ModuleCatalog](zszj-framework/zszj-common/src/main/java/cn/zszj/framework/common/catalog/ModuleCatalog.java)（由 `node scripts/eng/verify-module-whitelist.mjs` 校验与 POM/兜底路由一致）。
> 本目录回答"当前底座允许哪些功能运行"；运行时拦截链：Maven 依赖闭包（未启用模块不装配）→ DefaultController 兜底 501 → 租户套餐校验（不得引用关闭模块菜单）。

## 分层生效规则（交集模型）

1. **编译装配层**：只有 `ModuleCatalog.ENABLED_MODULES` 出现在 zszj-server 依赖中——未启用模块的 Bean/Job/Controller 不存在。
2. **接口兜底层**：未启用模块前缀由 DefaultController 返回 501 不可用响应，不发生业务写入。
3. **租户套餐层**：套餐 menuIds 经 `TenantPackageServiceImpl.validateTenantPackageMenus` 校验，引用未启用模块菜单即拒绝（错误码 1-002-016-004）；套餐回收时 `updateTenantRoleMenu` 会收敛租户角色权限。
4. **数据层**：基线迁移 V1（ZS-DB-004）只包含启用模块的菜单种子；关闭模块无可操作菜单。
5. **角色权限层**：接口鉴权独立于套餐/菜单（安全链 ZS-SEC-*），B03 联验"套餐回收后直调拒绝"。

## 变更规程

启用一个模块 = ① 根 pom modules 取消注释 + ② zszj-server 依赖引入 + ③ ModuleCatalog 清单迁移（DISABLED → ENABLED）+ ④ DefaultController 移除对应兜底 + ⑤ V1 后追加该模块菜单的增量迁移 + ⑥ 两道检查（ModuleWhitelistTest / verify-module-whitelist.mjs）通过。停用反向操作。任何一步缺失都会被上述检查拦截。
