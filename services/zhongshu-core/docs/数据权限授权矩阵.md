# 数据权限授权矩阵（ZS-PERM-002.A / ZS-PERM-002.B / ZS-PERM-004.B / ZS-PERM-003.A / ZS-FILE-004.B）

> 建立日期：2026-09-09。基线：ZS-DB-018（数据层技术租户隔离回归）与 ZS-SEC-012.A（真实安全链夹具）完成后。
> 性质：**技术租户内的部门/本人数据范围（dept 轴，§1~§6，ZS-PERM-002.A）** + **业务组织跨组织授权范围（org 轴，§7，ZS-PERM-002.B）** 双轴授权矩阵登记与通用对象级检查入口说明；两轴**正交并存**、互不替代。
> 复用边界：跨租户隔离（tenant_id 轴）由租户拦截器与 [ZS-DB-018](../../../scripts/db/run-db018-verify.mjs) 数据层回归覆盖，本矩阵不重复编写；此处只登记 dept_id / user_id 数据范围轴。

## 1. 现有数据范围机制（现状证据）

| 机制 | 代码入口 | 作用 | 局限 |
|---|---|---|---|
| 数据范围计算 | [PermissionServiceImpl#getDeptDataPermission](../zszj-module-system/src/main/java/cn/zszj/module/system/service/permission/PermissionServiceImpl.java) | 合并用户全部启用角色的数据范围，产出 `all/self/deptIds` | 仅产出范围，不做单对象判定 |
| SQL 静默过滤 | [DeptDataPermissionRule](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/rule/dept/DeptDataPermissionRule.java) | 对**已注册表/列**在 SQL 执行前追加 WHERE 条件 | 越权行被静默过滤，详情返回 null 无法区分「不存在/无权限」；批量越权项被静默丢弃而非拒绝；未注册表不追加条件 |
| 忽略数据权限 | [DataPermissionUtils#executeIgnore](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/util/DataPermissionUtils.java) / `@DataPermission(enable=false)` | 受控关闭数据范围（如登录、供给、字典翻译） | 关闭即全量，须显式受控且有据可查 |

数据范围枚举（[DataScopeEnum](../zszj-module-system/src/main/java/cn/zszj/module/system/enums/permission/DataScopeEnum.java)）：`ALL(1)`、`DEPT_CUSTOM(2)`、`DEPT_ONLY(3)`、`DEPT_AND_CHILD(4)`、`SELF(5)`。

### 1.1 多角色范围合并语义（getDeptDataPermission）

用户持有多个角色时按角色逐一合并（**并集**，非交集）：

| 角色数据范围 | 合并结果 |
|---|---|
| 任一角色 ALL | `all=true`（可查看全部，其余条件短路） |
| DEPT_CUSTOM | `deptIds += 角色自定义部门 + 本人所在部门` |
| DEPT_ONLY | `deptIds += 本人所在部门` |
| DEPT_AND_CHILD | `deptIds += 本人部门的子部门 + 本人所在部门` |
| SELF | `self=true` |
| 无启用角色 | 仅 `self=true`（只能看自己） |

> 合并语义的正确性由 `PermissionServiceTest#getDeptDataPermission_*`（system 模块既有 7 用例）覆盖，本矩阵不重复；检查器直接消费合并后的 `DeptDataPermissionRespDTO`，不自行重算。

## 2. 已启用表/列矩阵（现状注册）

来源：[DataPermissionConfiguration](../zszj-module-system/src/main/java/cn/zszj/module/system/framework/datapermission/config/DataPermissionConfiguration.java)（System 模块注册的 `DeptDataPermissionRuleCustomizer`）。

| 表 | 部门列（dept 范围） | 负责人列（self 范围） | 说明 |
|---|---|---|---|
| `system_users` | `dept_id` | `id` | 用户按所属部门过滤；SELF 时按用户 id 命中本人 |
| `system_dept` | `id` | —（未注册 user 列） | 部门以其自身 id 作为部门列；无负责人维度 |

**未注册即未适配**：除上述两表外，其余业务表未注册部门/负责人列，`DeptDataPermissionRule` 不会为其追加条件（现状为「不自动限制」）。这类路径若涉及对象授权，必须由业务代码显式调用第 3 节检查器，或在评审中按缺陷处理——不得默认「未注册=已授权全量」。

## 3. 通用对象级检查入口（ZS-PERM-002.A 新增）

新增 [DeptDataPermissionChecker](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/rule/dept/DeptDataPermissionChecker.java)（框架级 Bean，由 [ZszjDeptDataPermissionAutoConfiguration](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/config/ZszjDeptDataPermissionAutoConfiguration.java) 装配），作为 SQL 静默过滤的**显式拒绝**补充。它复用与 `DeptDataPermissionRule` 完全一致的范围语义，并共享其在 `LoginUser` 上下文中的数据权限缓存（同一 `CONTEXT_KEY`，不重复计算）。

| 入口方法 | 语义 | 适用路径 |
|---|---|---|
| `isObjectVisible(deptId, ownerUserId)` | 命中 ALL / 可见部门 / 本人任一即可见 | 只读判定，调用方自行处置 |
| `isDeptVisible(deptId)` | 仅按部门判定 | 部门维度对象 |
| `checkObjectVisible(deptId, ownerUserId)` | 不可见即抛 `FORBIDDEN(403)` | **单对象详情/读写**显式拒绝 |
| `checkBatchVisible(objects, deptGetter, ownerGetter)` | **任一对象越权即整批抛 `FORBIDDEN`** | **批量/导出/统计**混入拒绝 |

### 3.1 判定与护栏（与 DeptDataPermissionRule 对齐，非新增绕过面）

- ALL → 全部可见；命中 `deptIds` → 可见；`self=true` 且负责人为登录用户 → 可见；其余（含 100% 无权限）→ 不可见。
- 护栏一：**无登录用户**（系统内部/租户供给/定时任务上下文）不施加数据范围限制——与 `DeptDataPermissionRule#getExpression` 返回 null 一致；Web 请求恒有登录用户，故该分支仅对受信任系统级调用生效。
- 护栏二：**仅 ADMIN 类型**用户适用部门数据范围（MEMBER 对象授权属会员模块另一轴）——与 rule 一致。
- fail-closed：`getDeptDataPermission` 返回 null（取不到权限）时**拒绝**，不放行。

## 4. 访问路径覆盖矩阵

| 访问路径 | 覆盖机制 | 越权表现 | 状态 |
|---|---|---|---|
| 列表/分页（已注册表） | DeptDataPermissionRule SQL 过滤 | 越权行不出现（静默过滤，列表可接受） | 已覆盖（既有） |
| 单对象详情（已注册表） | SQL 过滤 → null；或 `checkObjectVisible` | 显式调用检查器时抛 FORBIDDEN | 检查器补齐 |
| 单对象详情（未注册表） | 业务代码显式调用 `checkObjectVisible` | 抛 FORBIDDEN | 须业务接入 |
| 批量读写/导出/统计 | `checkBatchVisible` | 混入任一越权 → 整批 FORBIDDEN | 检查器补齐 |
| 跨租户访问（tenant_id 轴） | 租户拦截器 + TenantSecurityWebFilter | 拒绝 | ZS-DB-018 / ZS-SEC-001.A / ZS-SEC-012.A 覆盖，本矩阵复用不重写 |

## 5. 验收对齐（05 文档 line 502）

- **同租户无对象权限**：`checkObjectVisible` 对不在 `deptIds`、非本人的对象抛 FORBIDDEN（`DeptDataPermissionCheckerTest` deptMiss/selfOther/noDeptNoSelf 三例）。
- **批量混入**：`checkBatchVisible` 一本部门 + 一越权部门整批拒绝（mixedIn 用例）。
- **已知 ID**：详情按 deptId/ownerUserId 判定，命中范围外即拒绝（不依赖「查得到=有权」）。
- **导出/统计**：走 `checkBatchVisible` 同一入口，越权即整批拒绝，合法汇总不夹带越权明细。
- **合法请求**：ALL / 命中部门 / 本人对象正常通过（all/deptHit/selfOwn/batch allVisible 用例）。
- **既有 DB 回归复用**：跨租户隔离轴复用 ZS-DB-018，不新增 SQL 套件。

## 6. 边界与待验收说明

1. 本矩阵与检查器只处理**技术租户内**的 dept/self 数据范围轴；`tenant_id` 隔离归 ZS-DB-018，HTTP 层租户/权限校验归 ZS-SEC-012.A/001.A。
2. 业务组织的**跨组织**授权范围、两组织互授/越界判定与**正向业务授权矩阵**已由 ZS-PERM-002.B（B08 Wave1，前置 ZS-PERM-002.A + ZS-IAM-002 + D-09）交付对象级检查入口 + 范围解析，见 **§7**；其 SQL 列表静默过滤规则（`OrgDataPermissionRule`）与业务表 `org_id` 列注册随各领域模块接入落地（§7.7）。
3. 检查器为**通用入口**，其对具体业务表/路径的接入（哪些 Controller/Service 调用 `checkObjectVisible`/`checkBatchVisible`）随各领域模块开发落地；本子项交付入口 + 现有 user/dept 对象矩阵 + 夹具，不代替各业务路径的逐一接入。
4. 检查器与 rule 共享 `LoginUser` 上下文缓存；`@DataPermission(enable=false)` / `executeIgnore` 关闭的是 SQL 过滤，**不影响**检查器的显式判定（检查器独立取 `getDeptDataPermission`），需忽略时由调用方在受控系统路径显式跳过。
5. 待验收：本子项以框架单测（56/56，含新增 13）证明检查器判定/拒绝/护栏/缓存语义；其在真实 PG + HTTP 端到端的对象授权联验随 ZS-SEC-012.B / ZS-SYS-001.A 在 B03 收口。

## 7. 组织级（跨组织）授权矩阵（ZS-PERM-002.B，org 轴）

> 建立日期：2026-09-20（B08 Wave1）。前置：ZS-PERM-002.A（dept 轴入口）+ ZS-IAM-002（组织/任职模型 + 服务端组织上下文）+ D-09（2026-09-10 确认）。
> 性质：在 §1~§6 的 dept 轴（技术租户内 `dept_id`/`user_id`）之外，新增**正交并存**的 org 轴（业务组织 `organization_id` 跨组织授权范围），落实 D-09「一期跨组织只允许显式平台角色」与 FND-AUTH-003/004「数据范围绑定服务端确认的组织上下文；即使已知他组织对象 ID 也不可读取/修改/下载/导出」。

### 7.1 org 轴范围枚举（[OrgDataScopeEnum](../zszj-module-system/src/main/java/cn/zszj/module/system/enums/permission/OrgDataScopeEnum.java)，独立于 dept 轴 DataScopeEnum）

| 范围 | 值 | 语义 | 对应主体（PILOT-REQ-009） |
|---|---|---|---|
| `ORG_ALL` | 1 | 可见租户内全部组织 | 平台人员（显式平台角色）/ 超级管理员 |
| `ORG_AND_CHILD` | 3 | 本组织 + 全部后代组织（组织树 `parent_id` 下钻） | 负责人看本组织（含下级门店/部门） |
| `ORG_ONLY` | 4 | 仅本组织（不含后代）——**保留位，一期未启用** | — |
| `ORG_SELF` | 5 | 仅本人（无组织上下文的最窄兜底） | 员工看本人 / 历史无组织账号降级 |

> 值 2（计划草案的 `ORG_ASSIGNED` 显式指派）一期**未启用**——D-09 明确临时跨组织授权（双人审批 + 到期回收）后置，一期跨组织只由平台角色派生 `ORG_ALL`，不发明指派范围。

### 7.2 范围派生（[OrgDataScopeResolver#resolve](../zszj-module-system/src/main/java/cn/zszj/module/system/service/permission/OrgDataScopeResolver.java)，只读消费组织/任职 Mapper）

| 序 | 条件 | 产出范围 |
|---|---|---|
| 1 | 超级管理员（启用态超管角色，复用 `isSuperAdminUser`） | `ORG_ALL`（all=true） |
| 2 | 账号编号非法（userId null/≤0） | `ORG_SELF`（self=true，fail-safe 不放大） |
| 3 | 有效任职命中 PLATFORM 类型组织 | `ORG_ALL`（D-09 显式平台角色） |
| 4 | 无任何有效任职 | `ORG_SELF` |
| 5 | 有有效任职（非平台） | `ORG_AND_CHILD`：各自组织子树并集（self=true） |

- **「有效任职」口径**（复用 IAM-002 `MembershipContextResolver`）：status=ACTIVE + validFrom 非 isAfter(now) + validTo 非 isBefore(now) + 组织存在且 `CommonStatusEnum.isEnable`。
- **组织树下钻**（`collectSelfAndDescendants`，BFS）：ArrayDeque + visited 去重防环 + `MAX_DESCENDANT_DEPTH=256` 双重 fail-safe；**后代组织须显式开启**（禁用组织既不入范围也不继续下钻，其子树 fail-closed 级联排除，codex r0 P2）。

### 7.3 三类主体授权范围（PILOT-REQ-009 / FND-AUTH-003）

| 主体 | 组织上下文 | org 轴范围 | 可见对象 |
|---|---|---|---|
| 员工 | 任职于某组织、无下级 | `ORG_AND_CHILD`（子树仅自身） | 本组织内对象 + 无组织列的本人对象 |
| 负责人 | 任职于门店/部门（有下级组织） | `ORG_AND_CHILD`（本组织 + 后代） | 本组织及下级组织对象 |
| 平台人员 | 任职于 PLATFORM 类型组织 | `ORG_ALL` | 租户内全部组织对象 |

> 组织上下文（orgId/orgType/membershipId）源于服务端签发 token userInfo，**客户端无法伪造**（IAM-002 结构性保证）；每请求由 OAuth2 `checkAccessToken` `organizationContextMatches` 三维比对 fail-closed 拦截 401。

### 7.4 两组织互访正反向矩阵（FND-AUTH-004 / FND-AUTH-008）

| 访问方范围 | 目标对象所属组织 | 判定 | 依据 |
|---|---|---|---|
| `ORG_ALL`（平台/超管） | 任意组织 | ✅ 可见 | all=true 短路 |
| `ORG_AND_CHILD`（org A 负责人） | org A 或 A 的启用后代 | ✅ 可见 | orgId ∈ 授权 orgIds |
| `ORG_AND_CHILD`（org A 负责人） | org B（非 A 子树） | ❌ 拒绝 FORBIDDEN | 越界，即使已知对象 ID |
| `ORG_AND_CHILD`（org A 负责人） | org B 对象但 owner=本人 | ❌ 拒绝 FORBIDDEN | **P1：对象一旦归属某组织即由组织范围独占裁决，本人所有权不得凌驾组织排除**（转岗/离任成员不可访问旧组织对象） |
| `ORG_AND_CHILD` | 无组织列对象（orgId=null）且 owner=本人 | ✅ 可见 | self 兜底仅对无组织列对象生效 |
| `ORG_SELF`（无组织上下文） | 任意有组织对象 | ❌ 拒绝 | orgIds 空，仅本人无组织列对象可见 |

### 7.5 对象级检查入口（[OrgDataPermissionChecker](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/rule/org/OrgDataPermissionChecker.java)，镜像 DeptDataPermissionChecker）

| 入口方法 | 语义 | 适用路径 |
|---|---|---|
| `isObjectVisible(orgId, ownerUserId)` | 命中 all / 授权 orgIds / 无组织列本人兜底任一即可见 | 只读判定 |
| `isOrgVisible(orgId)` | 仅按组织范围判定 | 组织维度对象 |
| `checkObjectVisible(orgId, ownerUserId)` | 不可见即抛 FORBIDDEN(403) | 单对象详情/读写显式拒绝 |
| `checkBatchVisible(objects, orgIdGetter, ownerGetter)` | 任一越权即整批抛 FORBIDDEN | 批量/导出/统计混入拒绝 |

- 护栏与 `DeptDataPermissionChecker` **完全一致**（无登录用户跳过、仅 ADMIN 适用、取不到权限 fail-closed）；复用 `LoginUser` 上下文缓存（**独立 `CONTEXT_KEY`**=`OrgDataPermissionChecker`，与 dept 轴 `DeptDataPermissionRule` 不串扰）。
- **与 dept 轴 self 的有意分歧**（codex r0 P1）：dept 轴 self 是租户内合法可见层（本人数据权限），可在可见部门集之外放行本人对象；org 轴受 D-09 FND-AUTH-004 约束——对象一旦归属某组织（orgId≠null）必须由组织范围裁决，self 兜底**仅对无组织列对象（orgId=null）生效**。

### 7.6 与 dept 轴 / tenant 轴的正交关系

| 轴 | 维度 | 机制 | 归属 |
|---|---|---|---|
| tenant 轴 | `tenant_id`（技术租户隔离） | 租户拦截器 SQL 改写 | ZS-DB-018 / ZS-SEC-001.A / ZS-SEC-012.A |
| dept 轴 | `dept_id` / `user_id`（技术租户内部门/本人） | DeptDataPermissionRule + DeptDataPermissionChecker | ZS-PERM-002.A |
| org 轴 | `organization_id`（业务组织跨组织） | OrgDataScopeResolver + OrgDataPermissionChecker | **ZS-PERM-002.B（本节）** |

> 三轴正交并存、互不替代。API 链：`PermissionCommonApi#getOrgDataPermission` → `PermissionApi` → `PermissionApiImpl`（透传）→ `PermissionServiceImpl`（`@DataPermission(enable=false)` 防递归，委托 `OrgDataScopeResolver`，超管豁免沿用 `isSuperAdminUser`）。

### 7.7 边界与待验收说明

1. **临时跨组织授权后置**（D-09）：双人审批 + 到期回收的临时跨组织授权不在一期，org 轴跨组织只由平台角色派生 `ORG_ALL`；`ORG_ONLY(4)`/值 2 为保留位未启用。

### 8. 动作与字段授权输出机制（ZS-PERM-003.A，B08 Wave3）

> 建立日期：2026-09-25（B08 Wave3）。前置：ZS-PERM-002.B / ZS-PERM-004.B（org 轴对象门与撤权一致性，§7）+ ZS-SEC-001.B（D6/D7 visit 收敛读取面）。
> 性质：**机制先行卡**——把各业务域手写的「visit → checker → fail-closed」编排（如 `NotifyMessageOrgAuthorizer`、`FileServiceImpl#isFileOrgAllowed`）标准化为统一「动作 / 字段」授权输出与执行共用机制；**字段等级目录（F0～F3 与具体商业字段名）归 ZS-PERM-003.B**，本卡不定义任何商业字段/等级、不接入业务域（后台服务端机制，无用户可见入口）。

#### 8.1 合同与语义

| 组件 | 语义 |
|---|---|
| `ObjectAuthorizationProvider`（SPI，[core/authorize](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/authorize/ObjectAuthorizationProvider.java)） | 业务域按对象类型声明：`getObjectType`（非空白且容器内唯一，装配 fail-fast）+ `getCandidateActions`/`getCandidateFields`（默认空集=未启用）+ `isActionAllowedInStatus`（状态维钩子，默认放行） |
| `ObjectAuthorizationRequest` | 裁决输入：对象类型（路由）+ orgId/ownerUserId（对象维）+ 业务对象实例（状态维）；**不承载用户身份、不暴露声明集合参数**（伪造通道在合同层不存在） |
| `ObjectAuthorizationRespDTO` | 输出：`allowedActions`（**恒非 null**；空集=无任何动作可用）+ `authorizedFields`（**null=未启用字段级输出**（provider 未声明候选字段，零变化）；非 null 可为空集=全部候选字段不可见） |
| `ObjectAuthorizationService` | 统一裁决服务：`authorize`（输出）+ `checkActionAllowed`/`checkFieldsAllowed`（执行侧，**内部复用 `authorize`**——输出=执行同核，前端伪造结果不生效） |

#### 8.2 裁决流水线（每次调用实时重算，无缓存）

1. **扩展点路由**：按 `objectType` 查找 provider；**未注册 → 返回 null**（未接入=零变化，不抛异常，支持业务域渐进接入；执行侧对 null fail-closed 拒绝）。
2. **对象维**：非 visit 请求 → org 轴 `OrgDataPermissionChecker#isObjectVisible`（§7）；**visit 请求（跨租户访问获批）经 `CrossOrgVisitScopeHolder#isObjectAllowed` 收敛**（无 scope 异常态 fail-closed，**不落 home 组织 checker**——目标范围与 home 范围语义不同）。不可见即 FORBIDDEN。
3. **动作维**：候选动作去重 → 状态钩子过滤 → 与功能权限取交集（`SecurityFrameworkService#hasAnyPermissions`；visit 请求由 `SecurityFrameworkServiceImpl` 收敛为 `visit.allowedActions`，D6）；恒返回非 null 集合。
4. **字段维**：provider 未声明候选字段 → null（未启用，零变化）；候选字段过滤 null/空白（与动作维 blank 口径对齐）；启用后非 visit 全候选（.A 零变化，字段等级归 .B）；**visit 请求逐字段经 `CrossOrgVisitScopeHolder#areFieldsAllowed` 收敛**（`allowedFields` 缺失 fail-closed 空集）。

#### 8.3 执行入口与装配

- `checkActionAllowed(request, action)`：blank / 未注册 / 不在输出集合（含前端伪造 allowedActions）→ FORBIDDEN；**每次调用实时重算**——撤权与对象状态流转后立即生效（无需清缓存，落实「授权变更后执行重新校验」）。
- `checkFieldsAllowed(request, fields)`：空请求=不校验字段维（与 `areFieldsAllowed` 同口径）；未启用字段级（null）或超出授权字段（含隐藏字段经详情/批量/导出/文件旁路）→ FORBIDDEN。
- 拒绝统一 FORBIDDEN + `log.warn`（错误信息不区分原因——不泄露对象/字段是否存在，防错误信息旁路）。
- 装配：`ZszjDeptDataPermissionAutoConfiguration` 新增 `objectAuthorizationService` Bean（参数 `SecurityFrameworkService`（`@Bean("ss")` 无条件装配）+ `OrgDataPermissionChecker` + `List<ObjectAuthorizationProvider>`；无 provider 时空转，恒返回 null）。

#### 8.4 边界

1. **字段等级目录（F0～F3 与具体商业字段名）归 ZS-PERM-003.B**——本卡不定义任何商业字段等级（docs/05 L533「不提前定义商业字段等级」）；`ObjectAuthorizationProvider` 配置化接入随 .B 与敏感域（报价/成本/佣金）接入。
2. 业务域存量手写编排（`NotifyMessageOrgAuthorizer` 等）本轮**不迁移**，随各域迭代接入统一机制；**前端消费（Web/移动端只消费结果、不自行推断）归 CLIENT-001.B**。
3. 夹具：`ObjectAuthorizationServiceTest`（biz-data-permission）**27 用例**覆盖：路由、空白 objectType 与重复注册 fail-fast / 对象维（checker 与 visit 双分支、无 scope fail-closed 且不落 home checker）/ 动作维（RBAC 交集、全拒空集、D6 收敛共用真实现、状态钩子）/ 字段维（未启用 null、空白候选过滤、非 visit 全部候选与候选内通过、visit 交集与 allowedFields 缺失 fail-closed）/ 执行侧（输出=执行同核、伪造动作拒绝、撤权与状态变更后重新校验、未注册 fail-closed、隐藏字段拒绝、空字段请求不校验）。真实 PG + HTTP 端到端（含字段裁剪经导出/文件旁路验收）随 B08 批次真实环境放行收口。
4. 主卡 ZS-PERM-003 维持**开发中**（.A 机制交付，字段目录与业务域接入随 .B），本记录不表示任何主任务已验收。
