# 数据权限授权矩阵（ZS-PERM-002.A）

> 建立日期：2026-09-09。基线：ZS-DB-018（数据层技术租户隔离回归）与 ZS-SEC-012.A（真实安全链夹具）完成后。
> 性质：**技术租户内的部门/本人数据范围**授权矩阵登记 + 通用对象级检查入口说明；业务组织（跨组织）授权范围待 D-09 批准后由 ZS-PERM-002.B 映射，本矩阵不含。
> 复用边界：跨租户隔离（tenant_id 轴）由租户拦截器与 [ZS-DB-018](../../../scripts/db/run-db018-verify.mjs) 数据层回归覆盖，本矩阵不重复编写；此处只登记 dept_id / user_id 数据范围轴。

## 1. 现有数据范围机制（现状证据）

| 机制 | 代码入口 | 作用 | 局限 |
|---|---|---|---|
| 数据范围计算 | [PermissionServiceImpl#getDeptDataPermission](../zszj-module-system/src/main/java/cn/zszj/module/system/service/permission/PermissionServiceImpl.java) | 合并用户全部启用角色的数据范围，产出 `all/self/deptIds` | 仅产出范围，不做单对象判定 |
| SQL 静默过滤 | [DeptDataPermissionRule](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/rule/dept/DeptDataPermissionRule.java) | 对**已注册表/列**在 SQL 执行前追加 WHERE 条件 | 越权行被静默过滤，详情返回 null 无法区分「不存在/无权限」；批量越权项被静默丢弃而非拒绝；未注册表不追加条件 |
| 忽略数据权限 | [DataPermissionUtils#executeIgnore](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/util/DataPermissionUtils.java) / `@DataPermission(enable=false)` | 受控关闭数据范围（如登录、供给、字典翻译） | 关闭即全量，须显式受控且有据可查 |

数据范围枚举（[DataScopeEnum](../zszj-module-system/src/main/java/cn/zszj/module/system/enums/permission/DataScopeEnum.java)）：`ALL(1)`、`DEPT_CUSTOM(2)`、`DEPT_ONLY(3)`、`DEPT_AND_CHILD(4)`、`SELF(5)`。

### 1.1 多角色范围合并语义（getDeptDataPermission）

用户持有多个角色时按角色逐一合并（**并集**，非交集）：

| 角色数据范围 | 合并结果 |
|---|---|
| 任一角色 ALL | `all=true`（可查看全部，其余条件短路） |
| DEPT_CUSTOM | `deptIds += 角色自定义部门 + 本人所在部门` |
| DEPT_ONLY | `deptIds += 本人所在部门` |
| DEPT_AND_CHILD | `deptIds += 本人部门的子部门 + 本人所在部门` |
| SELF | `self=true` |
| 无启用角色 | 仅 `self=true`（只能看自己） |

> 合并语义的正确性由 `PermissionServiceTest#getDeptDataPermission_*`（system 模块既有 7 用例）覆盖，本矩阵不重复；检查器直接消费合并后的 `DeptDataPermissionRespDTO`，不自行重算。

## 2. 已启用表/列矩阵（现状注册）

来源：[DataPermissionConfiguration](../zszj-module-system/src/main/java/cn/zszj/module/system/framework/datapermission/config/DataPermissionConfiguration.java)（System 模块注册的 `DeptDataPermissionRuleCustomizer`）。

| 表 | 部门列（dept 范围） | 负责人列（self 范围） | 说明 |
|---|---|---|---|
| `system_users` | `dept_id` | `id` | 用户按所属部门过滤；SELF 时按用户 id 命中本人 |
| `system_dept` | `id` | —（未注册 user 列） | 部门以其自身 id 作为部门列；无负责人维度 |

**未注册即未适配**：除上述两表外，其余业务表未注册部门/负责人列，`DeptDataPermissionRule` 不会为其追加条件（现状为「不自动限制」）。这类路径若涉及对象授权，必须由业务代码显式调用第 3 节检查器，或在评审中按缺陷处理——不得默认「未注册=已授权全量」。

## 3. 通用对象级检查入口（ZS-PERM-002.A 新增）

新增 [DeptDataPermissionChecker](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/core/rule/dept/DeptDataPermissionChecker.java)（框架级 Bean，由 [ZszjDeptDataPermissionAutoConfiguration](../zszj-framework/zszj-spring-boot-starter-biz-data-permission/src/main/java/cn/zszj/framework/datapermission/config/ZszjDeptDataPermissionAutoConfiguration.java) 装配），作为 SQL 静默过滤的**显式拒绝**补充。它复用与 `DeptDataPermissionRule` 完全一致的范围语义，并共享其在 `LoginUser` 上下文中的数据权限缓存（同一 `CONTEXT_KEY`，不重复计算）。

| 入口方法 | 语义 | 适用路径 |
|---|---|---|
| `isObjectVisible(deptId, ownerUserId)` | 命中 ALL / 可见部门 / 本人任一即可见 | 只读判定，调用方自行处置 |
| `isDeptVisible(deptId)` | 仅按部门判定 | 部门维度对象 |
| `checkObjectVisible(deptId, ownerUserId)` | 不可见即抛 `FORBIDDEN(403)` | **单对象详情/读写**显式拒绝 |
| `checkBatchVisible(objects, deptGetter, ownerGetter)` | **任一对象越权即整批抛 `FORBIDDEN`** | **批量/导出/统计**混入拒绝 |

### 3.1 判定与护栏（与 DeptDataPermissionRule 对齐，非新增绕过面）

- ALL → 全部可见；命中 `deptIds` → 可见；`self=true` 且负责人为登录用户 → 可见；其余（含 100% 无权限）→ 不可见。
- 护栏一：**无登录用户**（系统内部/租户供给/定时任务上下文）不施加数据范围限制——与 `DeptDataPermissionRule#getExpression` 返回 null 一致；Web 请求恒有登录用户，故该分支仅对受信任系统级调用生效。
- 护栏二：**仅 ADMIN 类型**用户适用部门数据范围（MEMBER 对象授权属会员模块另一轴）——与 rule 一致。
- fail-closed：`getDeptDataPermission` 返回 null（取不到权限）时**拒绝**，不放行。

## 4. 访问路径覆盖矩阵

| 访问路径 | 覆盖机制 | 越权表现 | 状态 |
|---|---|---|---|
| 列表/分页（已注册表） | DeptDataPermissionRule SQL 过滤 | 越权行不出现（静默过滤，列表可接受） | 已覆盖（既有） |
| 单对象详情（已注册表） | SQL 过滤 → null；或 `checkObjectVisible` | 显式调用检查器时抛 FORBIDDEN | 检查器补齐 |
| 单对象详情（未注册表） | 业务代码显式调用 `checkObjectVisible` | 抛 FORBIDDEN | 须业务接入 |
| 批量读写/导出/统计 | `checkBatchVisible` | 混入任一越权 → 整批 FORBIDDEN | 检查器补齐 |
| 跨租户访问（tenant_id 轴） | 租户拦截器 + TenantSecurityWebFilter | 拒绝 | ZS-DB-018 / ZS-SEC-001.A / ZS-SEC-012.A 覆盖，本矩阵复用不重写 |

## 5. 验收对齐（05 文档 line 502）

- **同租户无对象权限**：`checkObjectVisible` 对不在 `deptIds`、非本人的对象抛 FORBIDDEN（`DeptDataPermissionCheckerTest` deptMiss/selfOther/noDeptNoSelf 三例）。
- **批量混入**：`checkBatchVisible` 一本部门 + 一越权部门整批拒绝（mixedIn 用例）。
- **已知 ID**：详情按 deptId/ownerUserId 判定，命中范围外即拒绝（不依赖「查得到=有权」）。
- **导出/统计**：走 `checkBatchVisible` 同一入口，越权即整批拒绝，合法汇总不夹带越权明细。
- **合法请求**：ALL / 命中部门 / 本人对象正常通过（all/deptHit/selfOwn/batch allVisible 用例）。
- **既有 DB 回归复用**：跨租户隔离轴复用 ZS-DB-018，不新增 SQL 套件。

## 6. 边界与待验收说明

1. 本矩阵与检查器只处理**技术租户内**的 dept/self 数据范围轴；`tenant_id` 隔离归 ZS-DB-018，HTTP 层租户/权限校验归 ZS-SEC-012.A/001.A。
2. 业务组织的 SELF/ASSIGNED 等**跨组织**授权范围、两组织互授/越界判定与**正向业务授权矩阵**归 ZS-PERM-002.B（B08，前置 ZS-PERM-002.A + ZS-IAM-002，须 D-09）。
3. 检查器为**通用入口**，其对具体业务表/路径的接入（哪些 Controller/Service 调用 `checkObjectVisible`/`checkBatchVisible`）随各领域模块开发落地；本子项交付入口 + 现有 user/dept 对象矩阵 + 夹具，不代替各业务路径的逐一接入。
4. 检查器与 rule 共享 `LoginUser` 上下文缓存；`@DataPermission(enable=false)` / `executeIgnore` 关闭的是 SQL 过滤，**不影响**检查器的显式判定（检查器独立取 `getDeptDataPermission`），需忽略时由调用方在受控系统路径显式跳过。
5. 待验收：本子项以框架单测（56/56，含新增 13）证明检查器判定/拒绝/护栏/缓存语义；其在真实 PG + HTTP 端到端的对象授权联验随 ZS-SEC-012.B / ZS-SYS-001.A 在 B03 收口。
