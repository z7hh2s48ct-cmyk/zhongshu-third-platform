# 跨组织访问授权矩阵（ZS-SEC-001.B）

> 建立日期：2026-09-24（B08 Wave3）。基线：ZS-SEC-001.A（配置门控关闭旧放大链）+ ZS-IAM-002（组织/任职模型 + 服务端组织上下文）+ ZS-PERM-002.B（org 轴范围解析/对象检查入口）+ D-09（2026-09-10 确认）完成后。
> 性质：**获批跨组织访问（visit 上下文）的服务端授权记录/策略矩阵**——以持久化授权记录 + 10 步 fail-closed 判定序，取代 ZS-SEC-001.A 关闭的旧越权放大链（持 `system:tenant:visit` 即 `skipPermissionCheck()=true` 整体跳过功能权限），落实 docs/05 line330-331 与 D-09「一期跨组织只允许显式平台角色」。
> 与 [数据权限授权矩阵](数据权限授权矩阵.md) 的关系：本矩阵处理**跨组织 visit 上下文的功能权限收敛**（切换租户后「能做什么动作/看什么对象/读什么字段」由授权记录裁决）；数据权限授权矩阵处理**同租户内 dept 轴（§1~§6）/ org 轴（§7）的数据范围**。两者正交：visit 授权决定「是否放行进入目标租户上下文 + 放行哪些动作」，数据范围轴决定「上下文内可见哪些行」。数据范围轴在 visit 上下文的收敛见 §8 边界（随下游领域模块）。

## 1. 旧放大链问题（现状证据 · 为何替换）

| 环节 | 代码入口 | 旧行为（放大链） |
|---|---|---|
| 切换触发 | [TenantVisitContextInterceptor#preHandle](../zszj-framework/zszj-spring-boot-starter-biz-tenant/src/main/java/cn/zszj/framework/tenant/core/web/TenantVisitContextInterceptor.java)（全仓唯一 `setVisitTenantId` 生产点） | visit-enable=true 且持粗粒度权限 `system:tenant:visit` → `setVisitTenantId` + `TenantContextHolder.setTenantId` |
| 跳过判定 | [SecurityFrameworkUtils#skipPermissionCheck](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/util/SecurityFrameworkUtils.java) | `loginUser!=null && visitTenantId!=null && visitTenantId≠tenantId` → true |
| 权限放大 | [SecurityFrameworkServiceImpl](../zszj-framework/zszj-spring-boot-starter-security/src/main/java/cn/zszj/framework/security/core/service/SecurityFrameworkServiceImpl.java) | `hasAnyPermissions/hasAnyRoles/hasAnyScopes` 一律 `return true`（跳过全部功能权限） |

> **技术债**：即「持访问入口权限 = 自动获得目标租户全部动作/敏感字段」，违背 docs/05 line331「即使具备访问入口权限，也不能自动获得所有目标动作/敏感字段」。ZS-SEC-001.A 已默认关闭（`visit-enable=false` 时任何跨租户切换 403），但未改 `skipPermissionCheck`/`SecurityFrameworkServiceImpl`（显式留给 .B）。

## 2. 授权记录形态（`system_cross_org_visit_grant`，服务端授权记录/策略）

平台级跨租户表：[CrossOrgVisitGrantDO](../zszj-module-system/src/main/java/cn/zszj/module/system/dal/dataobject/permission/CrossOrgVisitGrantDO.java) `extends BaseDO` + `@TableName("system_cross_org_visit_grant")` + `@KeySequence` + `@TenantIgnore`（循 [TenantDO](../zszj-module-system/src/main/java/cn/zszj/module/system/dal/dataobject/tenant/TenantDO.java) 范式；跨租户查询不受 MyBatis-Plus 租户插件自动注入）。

| 列 | 语义 | fail-closed 缺省 |
|---|---|---|
| `visitor_user_id` / `visitor_tenant_id` | 原主体账号 + home 租户 | 空/非法 → `INVALID_REQUEST` |
| `target_tenant_id` | 目标租户 | 不存在/停用 → `TARGET_INVALID` |
| `target_org_ids`（text JSON） | 对象范围（可访问的目标组织集合） | **null = 目标租户内全部组织**（whole-tenant 放行对象维） |
| `allowed_actions`（text JSON） | 动作范围（权限串集合） | **空/null = 不允许任何动作**（fail-closed） |
| `allowed_fields`（text JSON） | 字段范围（敏感字段集合，机制交付、目录归 PERM-003） | **null = 不允许任何显式敏感字段** |
| `valid_from` / `valid_to` | 有效期 | `now ∉ [valid_from, valid_to]` → `GRANT_EXPIRED`（valid_to null 视为无固定期限） |
| `status`（int2） | 0=ACTIVE / 1=REVOKED（[CrossOrgVisitStatusEnum](../zszj-module-system/src/main/java/cn/zszj/module/system/enums/permission/CrossOrgVisitStatusEnum.java)） | REVOKED → `GRANT_REVOKED`（逻辑状态翻转不改历史） |
| `reason`（varchar500） | 授权理由 | — |

- 索引：`idx_(visitor_user_id, target_tenant_id)`；序列 `system_cross_org_visit_grant_seq START 100000`。
- 迁移：[V20260924.001__system_cross_org_visit_grant.sql](../zszj-server/src/main/resources/db/migration/V20260924.001__system_cross_org_visit_grant.sql)（PG）；H2 测试 schema `create_tables.sql` + `clean.sql`。

## 3. 10 步 fail-closed 判定序（[CrossOrgVisitServiceImpl#authorizeVisit](../zszj-module-system/src/main/java/cn/zszj/module/system/service/permission/CrossOrgVisitServiceImpl.java)，正向矩阵核心）

任一不满足即 DENY + 写审计 + 返回 [CrossOrgVisitDenyReasonEnum](../zszj-module-system/src/main/java/cn/zszj/module/system/enums/permission/CrossOrgVisitDenyReasonEnum.java)：

| 步 | 判定 | 不满足 reason | 验收锚点（docs/05 line330-331 / §16.1 line1014） |
|---|---|---|---|
| 1 | 参数校验：visitorUserId/targetTenantId 合法 | `INVALID_REQUEST` | 空主体非法 |
| 2 | 取 (visitor, target) 的 ACTIVE-候选记录（未删除）；无记录即拒 | `NO_GRANT` | **取代旧 `system:tenant:visit` 粗粒度权限**：无记录即拒，不再因持旧权限放大 |
| 3 | `status != REVOKED` | `GRANT_REVOKED` | 撤销拒绝 |
| 4 | `now ∈ [valid_from, valid_to]` | `GRANT_EXPIRED` | 过期拒绝 |
| 5 | D-09 平台角色资格：`getOrgDataPermission(visitorUserId).all == true` | `NOT_PLATFORM_ROLE` | **须 D-09**：跨组织只允许显式平台角色；平台任职过期/撤销 → all=false → 拒绝（与步 4 双层兜底） |
| 6 | 目标状态：目标租户存在且启用（`CommonStatusEnum.isEnable`）；`target_org_ids` 非空时逐一校验组织存在且启用（`TenantUtils.execute` 跨目标租户查） | `TARGET_INVALID` / `TARGET_ORG_INVALID` | 停用/无效目标拒绝 |
| 7 | 动作维（req.action 非空）：`action ∈ allowed_actions` | `ACTION_NOT_ALLOWED` | **不能自动获得所有目标动作** |
| 8 | 对象维（req.objectOrgId 非空且 target_org_ids 非空）：`objectOrgId ∈ target_org_ids` | `OBJECT_OUT_OF_SCOPE` | **错对象拒绝**（target_org_ids null=全租户组织，此维放行） |
| 9 | 字段维（req.requestedFields 非空）：`requestedFields ⊆ allowed_fields` | `FIELD_NOT_ALLOWED` | **错字段拒绝** |
| 10 | 全部通过 → GRANTED，返回授权范围快照（target_org_ids/allowed_actions/allowed_fields） | `AUTHORIZED` | 正常授权有效 |

## 4. 正向授权矩阵（验收对齐 §16.1 line1014 / docs/05 line331）

| 场景 | 输入 | 判定 | reason | 覆盖用例（`CrossOrgVisitServiceImplTest`） |
|---|---|---|---|---|
| 正常授权有效 | ACTIVE grant + 平台角色 + 启用目标 + 窗口内 + 动作/对象/字段在范围 | GRANTED | `AUTHORIZED` | 正常授权 / 限定组织范围 |
| 过期拒绝 | grant.valid_to 已过 | DENY | `GRANT_EXPIRED` | 过期 |
| 未生效拒绝 | grant.valid_from 未到 | DENY | `GRANT_EXPIRED` | 未生效 |
| 撤销拒绝 | grant.status=REVOKED | DENY | `GRANT_REVOKED` | 撤销 / 撤销后拒绝 |
| 非平台角色 | 无 PLATFORM 任职（all=false） | DENY | `NOT_PLATFORM_ROLE` | 非平台角色（须 D-09） |
| 平台任职失效 | 平台 membership 过期/撤销 → all=false | DENY | `NOT_PLATFORM_ROLE` | （步 5 与步 4 双层兜底） |
| 目标停用 | 目标租户 status 停用 | DENY | `TARGET_INVALID` | 目标停用 |
| 目标不存在 | 目标租户缺失 | DENY | `TARGET_INVALID` | 目标不存在 |
| 目标组织无效 | target_org_ids 含禁用/不存在组织 | DENY | `TARGET_ORG_INVALID` | 目标组织无效 |
| 无授权记录 | 持旧 `system:tenant:visit` 但无 grant | DENY | `NO_GRANT` | 无记录（不将旧能力当授权） |
| 错动作 | action ∉ allowed_actions | DENY | `ACTION_NOT_ALLOWED` | 错动作（不能自动获得所有目标动作） |
| 空动作 | allowed_actions 空 + req.action 非空 | DENY | `ACTION_NOT_ALLOWED` | 空动作 |
| 错对象 | objectOrgId ∉ target_org_ids | DENY | `OBJECT_OUT_OF_SCOPE` | 错对象 |
| 错字段 | requestedFields ⊄ allowed_fields | DENY | `FIELD_NOT_ALLOWED` | 错字段 |
| 字段在范围 | requestedFields ⊆ allowed_fields | GRANTED | `AUTHORIZED` | 字段在范围 |
| 同租户非法 | visitorTenantId == targetTenantId | DENY | `INVALID_REQUEST` | 同租户非法 |
| 空主体非法 | visitorUserId 空/≤0 | DENY | `INVALID_REQUEST` | 空主体非法 |
| 上下文清理 | afterCompletion | scope cleared | — | `CrossOrgVisitScopeHolderTest` clear 不残留 |

**发放/撤销矩阵**（`createGrant`/`revokeGrant`，人工非双人审批）：发放成功 / 发放拒绝（非平台·目标无效·窗口非法）/ 撤销后拒绝 / 撤销不存在 / 审计留痕（原主体·目标·理由·结果）。

**功能权限收敛矩阵**（`SecurityFrameworkServiceImplCrossOrgVisitTest`，D6）：visit 内动作放行（不触 RBAC）/ visit 外动作拒绝（**关键回归护栏**）/ 多动作任一放行 / 无 scope fail-closed / authorized=false fail-closed / 空 allowedActions fail-closed / hasAnyRoles·hasAnyScopes fail-closed / 非 visit 照常委托 RBAC。

**端到端夹具矩阵**（`CrossTenantVisitEnabledFixtureTest`，visit-enable=true）：获批切换 / 范围内动作放行（`/perm/user-query`）/ 范围外动作 403（`/perm/user-create`，**回归护栏**：旧放大会返 200）/ 无记录拒绝不切换。

## 6. 与三轴数据权限的正交关系

| 轴/层 | 维度 | 机制 | 归属 |
|---|---|---|---|
| **visit 授权层（本矩阵）** | 跨组织 visit 上下文「能否进入 + 放行哪些动作/对象/字段」 | CrossOrgVisitService 10 步判定 + CrossOrgVisitScopeHolder 三维裁决 | **ZS-SEC-001.B** |
| tenant 轴 | `tenant_id`（技术租户隔离） | 租户拦截器 SQL 改写 | ZS-DB-018 / ZS-SEC-001.A / ZS-SEC-012.A |
| dept 轴 | `dept_id` / `user_id`（技术租户内部门/本人） | DeptDataPermissionRule + DeptDataPermissionChecker | ZS-PERM-002.A |
| org 轴 | `organization_id`（业务组织跨组织数据范围） | OrgDataScopeResolver + OrgDataPermissionChecker | ZS-PERM-002.B |

> visit 授权层是**功能权限门**（决定切换与动作放行），三轴是**数据范围门**（决定上下文内可见行）。步 5 D-09 平台角色资格复用 org 轴 `getOrgDataPermission(...).all`（平台角色/超管判定入口），两者在「显式平台角色」口径上对齐、职责不重叠。

## 7. 审计（每次判定落审计）

`CrossOrgVisitServiceImpl#recordVisitAudit` 经 [AuditPort#record](../zszj-framework/zszj-common/src/main/java/cn/zszj/framework/common/biz/system/audit/AuditPort.java)（`JdbcAuditPort` 落 `audit_event`）：

| 判定 | eventType | result | 事务 |
|---|---|---|---|
| GRANTED | `CROSS_ORG_VISIT_GRANTED` | SUCCESS | 随调用方事务 |
| DENIED | `CROSS_ORG_VISIT_DENIED` | DENIED | **REQUIRES_NEW 独立事务**（业务回滚不丢拒绝留痕） |

审计字段：actorType=ADMIN，actorId=visitorUserId，action=req.action（或 "VISIT"），bizType="CROSS_ORG_VISIT"，bizId=targetTenantId，reason=deny reason / "AUTHORIZED"，detail={visitorTenantId,targetOrgIds,objectOrgId,requestedFields}（脱敏，无敏感明文），tenantId=visitorTenantId，traceId=`TracerUtils.getTraceId()`——覆盖 docs/05 line330「记录原主体、目标、理由和结果」。缺 visitorUserId 时 `log.warn` + return，**不吞拒绝**（拒绝判定仍生效）。

## 8. 边界与待验收说明（登记，防越界）

1. **双人审批 + 到期自动回收工作流**后置（D-09 line94 / PERM-002.B §7.7 / PERM-004.B §6）——本卡交付记录式受控授权（人工发放/撤销 + 有效期 + 状态 + 审计），不建审批流/回收 JOB。
2. **字段目录 + 序列化层脱敏**归 ZS-PERM-003（字段目录待获批）——本卡交付字段维度**判定机制**（allowed_fields/requestedFields）+ 矩阵用例，不接生产字段目录、不改序列化。
3. **数据范围（dept/org 轴 SQL 过滤）在 visit 上下文的收敛**（CodeReview P2-1，`DataPermissionRuleHandler#L33-35` pre-existing 代码本 PR 未改）+ **各业务路径逐一接入** `CrossOrgVisitScopeHolder` 对象/字段判定，随下游领域模块 FILE-001.B/MSG-003.C/CLIENT-002.B 落地（同 PERM-002.A/B「入口先行」口径）。
