## 2. 不得在二开中改变的边界

1. 后端保持 JDK 17 模块化单体；公共能力按领域边界复用，不按运营、设计、工程等部门重建用户、文件、消息或任务中心。
2. PostgreSQL 是唯一核心关系数据库；不得先以 MySQL 跑通后再迁移，也不得用 H2 代替真实 PostgreSQL 验收。
3. Flowable 负责路由、任务和待办；领域服务保存正式业务状态，流程结束不能直接等同付款、发布或验收成功。
4. 完整业务源码可保留但默认不启用；`yudao-module-ai`、CRM、Mall、ERP、WMS、Pay 等未获批模块不得因源码存在而暴露接口或后台任务。
5. 设计供体的 `account`、`user_session`、`design_access_grant` 属于设计 C 端语义，不得直接替换 `system_users`，也不得据此宣布全平台“一账号多身份”。
6. D-09 未决前，只完成既有 System 技术账号链和身份扩展接口，不创建未经批准的多组织任职表、不上线身份切换。
7. D-07 未决前，只定义首链接入规范，不把“加盟商开通—首条线索闭环”写成批准范围。
8. D-10、D-11 后置；当前不新增收费假设，不启用真实微信支付或 AI Provider，不把本地 Stub/模拟回调当外部验收。

## 4. 12 个实施批次

每批先写失败测试或验收夹具，再改代码；只有正向和反向验收均通过，才能进入依赖它的下一批。下列“执行入口”是该批必须交付的可重复命令或测试类；除 B00 已存在入口外，其余入口需要在对应批次创建后执行，当前不能当作已通过。

同一主任务跨批次时，按 [05 清单第 16.1 节](05-底座模块分析与开发任务清单.md#161-跨批次子项与开工前置) 的稳定子项分别验收；早期批次只等待本批交付，不等待该主任务未来扩展。夹具可用、合同确定与整项验收是不同前置，不形成后端改造与客户端联验互等；全部适用子项验收后才关闭主任务。B01 的前端类型/依赖基线在 ZS-CLIENT-005.A 交付，不能推迟到 B06 功能完成。

后端未写前缀的路径以 `services/zhongshu-core` 为根；Web 以 `apps/zhongshu-admin-web` 为根；移动端以 `apps/zhongshu-miniapp` 为根。供体路径以 `reference/donors/zhongshu-design` 为根。通配路径用于定位范围，不代表该范围内所有文件都要修改。

B01～B03 是共同前置。B03 后，B04～B06 技术闭环可以与 D-09 的业务决策并行；B07 只有 D-09 批准后实施。B08 汇合文件机制与组织权限，B09/B10 再用获批首链证明底座能承接业务。不能因为等待组织决策就停掉全部技术准备，也不能借技术准备提前决定组织规则。

品牌与代码命名专项属于下列既有批次的必交付范围，不新建一套顺序，也不等业务系统建完再改名。任务和具体前置以 05 第 15.2/16.1 节为准：

- B01：ZS-BRAND-001 冻结原图/名称/映射与例外；002 改后端模块/包类/配置/产物；003.A 改两端静态品牌及包名；006.A 接入残留检查。不要求在此完成真实 PG、会话和页面 E2E。
- B02：ZS-BRAND-004.A 验新装/升级中的配置、种子及实际持久化旧名；005 验代码生成模板不带回旧名，兼容验证不得通过清库重建冒充。
- B03：ZS-BRAND-004.B 验 Redis/浏览器缓存、登录会话和新旧键切换；不得复活已撤销凭据或扩大权限。
- B05：ZS-BRAND-004.C 验任务/消息的持久化类名和路由切换、恢复及重放，不因改名丢失任务或重复执行。
- B06：ZS-BRAND-003.B 验真实页面中的 Logo/名称、响应式/主题及登录导航；006.B 汇总兼容、生成器、功能和文档回归。App 真机/上架按 B11 原门禁，不自动修改外部注册标识。

### B03：System 技术账号、会话和稳定 API

### B04：文件、对象授权和审计基础

- 前置：B03。
- 修改：`yudao-module-infra/**/file/**`、System 操作日志；参考供体 `yudao-module-infra/**/zhongshu/{audit,delivery}/**` 与 `yudao-module-design/**/asset/**`，评审后按需迁入主编译。
- 交付：公开素材与私有附件分流；上传锁定确切版本校验后发布不可变正式资产，原上传凭证不能覆盖正式内容；按技术主体/tenant 绑定文件与对象；一次性票据兑换主体/登录会话绑定的下载会话，实际取流经后端鉴权，不向私有附件用户返回可绕过授权的短时或长期存储 URL；同库审计、脱敏和保留期。文件任务的 .A 子项先闭环，D-09 后由 .B 扩展业务组织/字段权限；自动补偿在 B05，不反向阻塞 B04。
- 正向验收：合法技术主体可上传、预览、下载和导出，审计可关联主体、对象、动作、结果、版本和 trace；此时不宣称完成业务组织与字段权限。
- 反向验收：技术租户 B 或无授权账号使用 A 的文件 ID、URL、批量参数或票据均失败；确认前/发布并发/确认后重用上传凭证不能改变正式资产；下载地址/会话转发、兑换后撤权/退出/过期失败，合法 Range 和断线续传可用。在途撤权按批准且实测的重检上限停止后续输出，不承诺撤回已下载字节；普通账号不能修改审计历史。跨组织服务授权在 B08 另验。
- 执行入口：新增 `PrivateFileAuthorizationIntegrationTest`、`DeliveryTicketConcurrencyTest`、`AuditImmutabilityTest`，并补上传确认后覆盖、版本竞争、下载转发/撤权/Range/续传测试。存储兼容性独立验证，不支持安全直传时使用受控服务端上传。

### B05：任务、异步幂等、可靠事件和站内待办

## 7. 批次放行规则

每个批次的任务卡必须包含：关联 WP/FND 编号、前置批次、目标模块和文件、失败测试、实现、正向结果、反向结果、数据库迁移/回滚、文档同步和未验证项。

每次模块分析必须在 [05 任务清单](05-底座模块分析与开发任务清单.md) 中记录“众墅要求 → 现有代码证据 → 需要调整/补建/验证/决策的内容”，分配稳定 ZS 编号并关联本批次。跨模块发现的同一问题更新原任务，不重复登记；每项保留优先级、状态、依赖与正反向验收。M01～M12 全 12 个底座模块现已完成静态分析，含新增品牌命名专项累计 91 项主任务（83 待开发、2 待决策、6 待前置），不代表任何批次已实现或放行。

评审及用户新增要求现已包含 ZS-SYS-001 和 ZS-BRAND-001～006；25 个主任务的 57 个子项只用于分批开工与验收，不计入主任务总数。实现文档检查器时需验证子项引用、批次倒置/循环、FND 功能用例覆盖和改名后的当前代码链接，不能只校验编号是否存在。

下一阶段仍按本文批次推进：B01/B02 工程与 PG 基线 → B03 登录/API/安全合同 → B04 文件审计、B05 事件待办、B06 两端闭环。D-09 后进入 B07/B08，D-07 后以 B09/B10 首链和真实接入验证；B11 后置能力单独验收。技术测试准备可以拆项先行，但不绕过批次依赖或把移动构建当成真机发布证据。05 的分析模块编号不是替代 WP-01～24 或 B00～B11 的新开发顺序。

满足以下条件才可标记该批“完成”：变更文件可追溯；目标测试、lint/typecheck/build 通过；真实 PG 或外部条件按批次提供证据；密钥扫描无真实凭据；`git diff` 自审无调试残留；回滚路径明确；README、01、02 和本文的范围/状态无冲突。

任何跨批次工作包必须分项登记。例如 B04 的存储机制通过，不代表 B08 的私有对象授权已通过；B06 的移动构建通过，不代表 B11 的 iOS 真机、微信或发布已通过。
