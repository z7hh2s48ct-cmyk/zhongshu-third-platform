# 仓库结构与开发入口地图

> 版本：V1.0（2026-10-02）
> 维护规则：目录/入口的增删必须同步本图；本文只描述「结构与入口」，需求与任务状态见 [05 清单](05-底座模块分析与开发任务清单.md)，批次门禁见 [03 标准](03-底座二次开发顺序与验收标准.md)。

## 1. 顶层目录

| 目录 | 入库 | 职责 |
|---|---|---|
| `apps/` | ✅ | 两端前端：`zhongshu-admin-web`（Vue3 管理台）+ `zhongshu-miniapp`（Admin UniApp 多端） |
| `services/zhongshu-core/` | ✅ | 后端单体（Maven 多模块），唯一业务服务 |
| `docs/` | ✅ | 需求/任务/验收文档（01～10 + reviews/ 评审与验收档案） |
| `scripts/` | ✅ | 门禁与验证编排器（Node，本地与 CI 同规则） |
| `tools/` | ✅ | 工具链自引链：JDK 17 / Maven 3.9.9（脚本内绝对路径解析，worktree 需 junction） |
| `third_party/` | ✅ | 源码迁入证据：`source-copy-manifest.json`（固定 SHA）、净化/测试汇总 |
| `reference/donors/` | ✅ | 供体设计文档存档（如众墅之家设计小程序，PROPOSED 状态，不构成开工依据） |
| `outputs/` | ❌ gitignore | 本地运行证据目录（门禁/PG 套件/真实 server 日志与报告）；**保留约定**见 §7 |
| `.omx/plans/` | ❌ | 历史开发计划草稿（过程件，权威状态一律以 docs/05 为准） |

## 2. 后端 `services/zhongshu-core/`

- **启用业务模块**（`ModuleCatalog.ENABLED_MODULES` = system / infra / bpm / firstchain）：新增业务代码只进这四个模块 + framework starters。
- **冻结上游模块**（mp / mall / erp / wms / pms / crm / mes / im / report / pay / ai / iot 及 `zszj-ui/`）：源码迁入策略的**有意保留**（供体参考件，不删除、不修改、不装配），由 `ModuleWhitelistTest` + `scripts/eng/verify-module-whitelist.mjs` 守护——这是「结构性保留」而非重复代码；新增功能禁止落入冻结件。
- **权威入口单一化**：
  - Flyway 迁移唯一目录 = `zszj-server/src/main/resources/db/migration/`（`V<yyyyMMdd>.<NNN>__<描述>.sql`）；`sql/postgresql/` 是 V1 基线的**来源证据与夹具供给**（`env-setup-test.sql` 被全部 PG 套件消费、`init-admin.sql.example` 初始化管理员），**不是第二迁移入口**（G8 校验）。
  - 模块启用清单单一事实源 = `zszj-common` 的 `ModuleCatalog`（服务端白名单/移动端模块门共用）。
  - firstchain 域内编号合同单一事实源：菜单 `FirstchainMenus`、通知模板 `FirstchainNotifyTemplates`（与迁移种子不得漂移）。
- 方言红线（G8 第 6 项机械守护）：基线表 `deleted int2` → 手写 SQL 用 `deleted = 0`；`@TableName` 绑定且 deleted 为 boolean 的表，DO 必须字段级覆写 `@TableLogic(value = "FALSE", delval = "TRUE")`。

## 3. 前端 `apps/`

- **admin-web**：路由 = 后端 `system_menu` 驱动（`component` 字符串 → `src/views/**` 经 `import.meta.glob` 子串匹配，新页面落文件即达，无需注册）；API 层 `src/api/<模块>/<域>/index.ts`；按钮权限 `v-hasPermi`；纪律：禁裸用 `ElMessage`（用 `useMessage()`），新文件须 0 vue-tsc 新增（G10 基线按文件|错误码计数比对）。
- **miniapp**：分包在 `vite.config.ts` 的 `UniPages.subPackages` 注册（`pages.json` 构建生成、不入 git）；授权注册表单一真相源 = `src/pages/index/menu.json`（url→permission），模块门 `KNOWN_MODULES`（`src/router/access.ts`）对齐服务端 ModuleCatalog；守卫单测 `tests/unit/router-access.spec.ts`（G13 全量消费）；API 走 `src/http/http.ts`（CommonResult 解包）。

## 4. 门禁与验证 `scripts/`

| 入口 | 覆盖 |
|---|---|
| `ops/run-local-gates.mjs`（`--fast` 10 项 / 全量 17 项） | G1～G10/G13～G16 本地基线门禁；G14/G15/G16 为 slow+exclusive（Docker 重负载串行）；计数断言单测 `run-local-gates.test.mjs` |
| `ops/run-pg-regression.mjs` | 真实 PG 技术回归 22 套件（每套件自管理一次性容器，验后强清） |
| `ops/run-b09-joint-gate.mjs`（G16） | 串联 bpm001 + bpm003 + firstchain 三套件（批次放行证据入口） |
| `db/run-*-verify.mjs`（22 个） | 各卡 PG 验收编排器（首批 = `run-firstchain-verify.mjs`） |
| `sys001/`、`client005b/` | G14 七类矩阵 51 用例 / G15 双端 E2E 21 用例（自举真实 server 夹具） |
| `gov/verify-docs.mjs`、`gov/task-stats.mjs` | 文档一致性（版本/统计三方一致）与卡片状态权威聚合 |

放行轮标准动作（循 B09/FC/FC003 报告形态）：full 门禁 15/15（G11/G12 为 CI 通道）+ PG 回归 22/22 + 相关模块定向测试 → `docs/reviews/acceptance-*.md` 收口报告 → docs/05 翻卡。

## 5. `outputs/` 本地证据约定（不入库）

- **保留**：各验收报告头部点名的日志与产物（如 `acceptance/`、`b09-gate/`、`bpm-001|003/`、`firstchain/`、`brand006b/`、`client005b/`、`sys001/`、`fc-release-*`、`fc003-release-*`、`firstchain-verify-r*`、`pend004-*`）。
- **随用随清**：会话期 scratch（`tmp-*`、`_*`、单次调试日志）。2026-10-02 已做一次清理（867→20 项，142MB→16MB）。
- 报告引用 `outputs/` 路径时须在报告头注明「本地保留，不入库」。
