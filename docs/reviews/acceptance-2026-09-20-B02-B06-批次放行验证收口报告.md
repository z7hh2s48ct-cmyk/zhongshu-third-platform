## 3. 验收期发现与处置（如实登记）

### 3.1 G11/G12 首跑环境性失败（非产品缺陷）
首跑中 G11/G12 在 ~150ms 内 FAIL，失败输出为 `WSL ERROR: execvpe(/bin/bash) failed`：门禁脚本经 `spawn('bash')` 注入 `tools/env.sh`，而本机 PATH 上 `bash` 解析到 `C:\windows\system32\bash.exe`（WSL 无发行版）。处置：将 `C:\Program Files\Git\bin` 前置 PATH 后按门禁同命令清洁重跑，G11 exit 0（infra 490/0 失败）、G12 57/57 全绿。另登记一次 G12 流式用例（`streamingEndpointWithTokenStreamsFully`）在与 G14/G15 并行时段的偶发 500，单方法、内部类、全命令三次重跑均绿，判定为资源竞争偶发，不阻塞放行。

### 3.2 G14 首跑 47/49：SYS-001.A 用例与 SEC-009.B 合同失配（测试侧修复）
`SYS-MENU-P2`、`SYS-NOTICE-P2` 失败根因：ZS-SEC-009.B 全局 ID→string 合同激活（提交 `86d70290`）后，导航树/列表项 `id` 序列化为字符串，而两用例仍按数值严格相等断言（`navIds.includes(100)`、`n.id === enabledId`），且负向断言因类型失配被弱化失真。服务端行为本身正确（套餐内 100 可见/102 不可见、状态过滤一致，见失败 note）。处置：按合同对比较两侧做 `String()` 归一（其余用例 `post.mjs`/`user.mjs` 已有同款归一），修复后清洁重跑 **49/49 PASS**。该修复属验证适配，不改产品代码。
