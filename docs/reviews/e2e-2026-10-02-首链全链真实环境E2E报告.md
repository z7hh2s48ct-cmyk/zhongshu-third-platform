# 首链全链真实环境 E2E 报告（2026-10-02）

> 范围：首链业务模块（ZS-FC-001/002/003）经 **REST 在真实 server（`java -jar` 打包产物）+ 真实 PG17 + 真实安全链 + 真实 Flowable 引擎**端到端走通；此前仅有 H2 单测与「Stub 流程端口」的服务层 PG 套件。
> 入口：`scripts/firstchain/run-firstchain-e2e.mjs`（35 用例），由 G15 门禁（`run-b06-joint-gate.mjs`）在自举夹具上顺带运行；本地与 CI 同规则。
> 结论：**首轮实跑即暴露 10 项缺陷（9 项真实环境复现 + 1 项代码阅读预判），全部修复并以回归锚点固化；修复后 35/35 通过**。另登记 1 项未处置的产品缺口（平台组织/任职无创建途径）。

## 1. 为什么此前所有验收都没发现

这些缺陷有同一个共性：**只在「打包成 fat jar 运行 + 真实 PG 方言 + 真实装配的 Bean/监听器 + 真实权限引擎」同时存在时才出现**，而既有验证各自缺一块：

| 既有验证 | 缺的一块 |
|---|---|
| H2 单测 | PG 方言（空参数类型、boolean/int、Timestamp 类型）；权限服务等被 mock |
| 服务层 PG 运行期套件（G16 P1~P3） | 在 `mvn test` 类路径下运行（非 fat jar）；Stub 流程端口/Stub 校验器；只注册探针监听器，不装配 BPM 的上游监听器与自定义行为工厂；不经 REST/安全链 |
| G14/G15 既有用例 | 无任何 firstchain 用例（G15 仅有我上一轮补的申请创建/读取/附件 3 例） |
| 静态风险排查（`risk-review-2026-10-02.md`） | 「方言一致性」等面以静态扫描判定无风险，未触达运行期装配 |

## 3. 未处置的产品缺口（本轮登记，不在修改范围）

**产品内没有任何途径创建 PLATFORM 组织与平台运营任职**：迁移只把历史部门回填为 DEPARTMENT 组织；`system` 模块没有组织/任职的 REST 或管理工具；唯一创建组织/任职的代码是首链开通（FRANCHISEE）与建员工。但**审批申请、下发线索都要求操作人具备 PLATFORM 有效任职**。结果：全新部署后，没有任何账号能完成第一次审批，首链在真实环境**无法启动**，除非有人手工向库里插数据。

本 E2E 以 SQL 种子（`system_organization` type=1 + `system_membership`）绕过，并在脚本头注释与 S1 用例名中显式标注。需要产品决策：①迁移种子（每租户一个平台组织）+ 管理员默认平台任职；②补组织/任职管理 REST（D-09 B07 的管理面）；③一次性运维脚本。另：平台运营角色（含 `firstchain:application:*` 与 `firstchain:lead:distribute`）也没有种子，目前依赖超管绕过。

## 5. 覆盖与边界

- **覆盖**：申请→提交（真实流程部署/实例/绑定/待办）→审批开通（幂等、一次性密码、默认角色/任职、审计）→负责人/员工登录与权限面→员工创建与成员列表→线索下发/分配/领取/跟进/转商机/无效（含并发版本冲突与终态锁定）→三视角与 D-12 字段裁剪（负责人完整、员工尾四位脱敏）→指标同源→站内通知与落点授权→跨组织隔离→审批拒绝/撤回→停用即失权。
- **不覆盖**：Web/UniApp 页面渲染与交互（B10 真机 UAT）；多实例并发；线索导出（一期不做）；`NotifySendLog`/`NotifyTodo` 的 MP 直读路径无 REST 面（由 G8 第 6 项与 DO 字面量单测守护）。
- **已知既有问题（与本轮无关）**：`BpmFormServiceTest.testGetFormPage` 在 HEAD 即失败。

## 6. 经验沉淀

1. **夹具真实性**：单测事件/行数据必须取自真实引擎与驱动的形态（本轮 #2、#8 的首版单测夹具恰好掩盖了缺陷）。
2. **「无风险」结论的证据等级**：静态扫描只能证明「没有已知反模式」，不能证明「真实装配下可用」；首链这类跨模块链路须有真实 server 端到端用例才能放行。
3. **开发期热替换不可行**：夹具（`--serve`）依赖 server 子进程维持事件循环，server 重启即触发夹具清理；本轮采用整套重建（约 7 分钟/次）迭代。
