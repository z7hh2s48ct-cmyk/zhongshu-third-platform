## 1. 清单职责与维护规则

本清单回答：基于众墅之家底座要求，现有代码具体需要调整什么、为什么调整、在哪里调整、如何验收。

- 02 文档管理需求和决策；03 文档管理 WP 工作包与 B00～B11 实施批次；本文管理逐模块分析产生的细化任务，不另建一套需求或实施顺序。
- 每次模块分析必须同时记录“众墅要求 → 现状证据 → 差距 → 修改任务 → 验收标准”。可直接复用的能力也应说明验证边界；尚未核验不能写成已发现缺陷。
- 每项使用稳定的 ZS 主任务编号。跨批次工作使用原编号加 .A/.B 等稳定子项，不重排主编号、不重复计数；子项继承主任务的 FND/WP、优先级、改造依据与范围，按第 16.1 节独立记录状态/证据和验收，后续新增问题优先补入原任务。
- 每项必须有关联 FND/WP/B 编号、优先级、类别、状态、前置条件、代码位置、调整范围和正反向验收。进入开发时补充失败测试、实际变更、迁移/恢复和验证证据。
- 优先级：P0 是所在批次放行前的必要项；P1 是底座完整验收或对应能力启用前完成的增强/验证项；P2 是后置项。P0 不表示可以绕过决策或依赖立即编码。
- 类别：改造、补建、验证适配、决策。状态：待开发、待决策、待前置、开发中、待验收、已验收、暂缓。状态变化必须有日期和依据；“分析完成”不能将任务标为“已验收”。
- 本版所有任务的实现、自动化测试、独立环境和发布证据均为“未实施/未执行”，负责人暂未分配。静态代码位置只是差距证据，不是修复证据。
- D-07、D-09 仍待决；D-10、D-11 仍后置。账号/身份/组织规则不得借数据库技术改造提前固化；本清单不授权连接或改动生产数据库。
- 已验收任务应回填固定提交、测试命令/报告、环境版本、正反向结果、恢复路径和未验证项，并按 02 文档第 9.3 节登记需求状态。无数据库变更或外部验收时写明不适用原因。

## 5. M03：接口与安全链路

### 5.1 现有调用主干与可复用能力

按源码声明，主干为：CORS → Trace → JSON 请求体缓存 → 租户上下文 → API 访问日志 → Spring Security/Token → 租户安全校验 → MVC 跨租户访问拦截器 → Controller 参数/方法权限 → Service/Mapper → 响应与日志。此处省略可选过滤器，不代表运行时装配、异步派发或 AOP 内部顺序已经测试；顺序依据见 [WebFilterOrderEnum][E53]。

| 层次 | 已有机制与代码入口 | 众墅适配边界 |
|---|---|---|
| 接口归类 | [Web 自动配置][E32] 按 Controller 包补充前缀；[WebProperties][E54] 默认 admin-api/app-api | 前缀区分接口/用户类型，不是 Web/小程序终端边界；员工移动端不能因终端不同被自动改成 MEMBER |
| 认证 | [Token 过滤器][E30] 调用 OAuth2TokenCommonApi 校验，构造 LoginUser 并比对 URL 对应的用户类型 | 无效 Token 可按匿名继续，最终由公开/受保护规则决定；这是现有设计，不等于认证绕过；mock 另见 ZS-ENG-004 |
| 请求授权 | [Security 配置][E29] 开启方法安全，汇总 PermitAll/配置/模块规则，其余请求需认证 | authenticated 只证明已登录；[UserController][E48] 用 PreAuthorize 保护管理动作，公共选择器等例外需逐项说明；方法权限也不自动代替对象/字段授权 |
| 普通租户校验 | [TenantSecurityWebFilter][E33] 比对请求租户与登录租户，必要时验证租户有效性 | 不能声称任意 tenant-id 都可越权；匿名及忽略 URL 要分别测试 |
| 跨租户访问 | [TenantVisitContextInterceptor][E34] 检查 system:tenant:visit 后切换目标租户 | [安全服务][E35] 与 [数据权限处理器][E36] 随后有跳过检查路径；需改成众墅批准范围内的受控访问，不能直接等同已确认组织模型 |
| 响应与异常 | [CommonResult][E42] 提供 code/msg/data；[异常处理器][E37] 有参数/业务/权限错误处理；[响应处理器][E38] 记录结果而非自动包装所有返回值 | HTTP 状态、过滤器错误、畸形 JSON、文件/SSE 例外与前端行为需合同测试；不能只看注释“返回 401” |
| 日志与追踪 | [访问日志][E39] 记录耗时、结果及部分脱敏；[TraceFilter][E40] 返回 trace-id | 错误日志原文、脱敏失败回退和过滤器失败误记成功存在代码缺口；[TracerUtils][E41] 在无有效 Span 时返回空串 |

## 6. M04：登录与会话

职责是建立、刷新、撤销服务端技术主体的会话。主干：[AdminAuthServiceImpl](../services/zhongshu-core/zszj-module-system/src/main/java/cn/zszj/module/system/service/auth/AdminAuthServiceImpl.java) 校验密码/验证码和用户状态 → [OAuth2TokenServiceImpl](../services/zhongshu-core/zszj-module-system/src/main/java/cn/zszj/module/system/service/oauth2/OAuth2TokenServiceImpl.java) 创建 Access/Refresh Token → PG 持久化与 Redis 缓存 → 认证过滤器检查 → 退出/管理员撤销。可复用多种登录入口、密码编码、登录日志和禁用用户时的撤销调用；不将这些代码等同生产登录安全已验收。

关键差距：Refresh Token 能降级转换为 Access Token；刷新复用原刷新凭据，未见该路径的并发领取/轮换防重；改密和删除与禁用的撤销路径不一致；令牌落库与 Redis 写入不是同一原子事务。D-09 之前只建设既有技术账号会话，不实现多身份切换。关联 ZS-SEC-003/010/012 和 ZS-DB-014/015，不重复登记传输、限流、清理任务。
