# B04 Wave 2 开发计划：ZS-FILE-002（上传用途、内容校验和唯一对象键）

> 前置 FILE-001.A ✅、SEC-008 ✅；他区仅 bpm-001-a 无冲突。

## 现状勘查

- `PATH_SUFFIX_TIMESTAMP_ENABLE=false`（硬编码静态字段）：同日同名上传生成相同 path → local/S3 同键覆盖旧文件（验收红线）。
- createFile：调用方传 type 时不重新探测（Tika 已有）→ 扩展名/MIME 伪装可上传。
- 无大小/类型用途限制（仅 spring multipart 16MB 兜底）；无危险内容隔离。
- S3FileClient 按 path putObject → 唯一键问题与 path 一体解决。

## 交付

1. **唯一对象键**：PATH_SUFFIX_TIMESTAMP_ENABLE 改 true（时间戳+5位随机，目录式后缀），同日同名并发不覆盖；测试两线程同名并发断言 path 不同且两文件均回读一致。
2. **服务端类型探测**：createFile 始终 Tika 探测；调用方声明 type 仅与探测结果一致性校验——探测可解析出扩展名且与文件名扩展名不符 → FILE_TYPE_MISMATCH（伪装拒绝）；octet-stream（无法判定）跳过。
3. **配置合同 FileProperties（zszj.file）**：max-size（默认 16MB 对齐 multipart）、danger-extensions（exe/dll/bat/cmd/sh/js/vbs/msi/com，双扩展名按最终扩展名命中 → FILE_DANGEROUS_CONTENT）、public-allowed-types（默认 image/*、application/pdf、text/plain；update-scope 转 PUBLIC 时校验 → FILE_PUBLIC_TYPE_NOT_ALLOWED）。
4. **大小限制**：service 层显式校验 FILE_SIZE_EXCEED（不依赖 multipart 兜底）。
5. **yaml** 显式登记 zszj.file 段（限额进配置合同）。
6. **TDD**：FileUploadHardeningTest：并发同名不覆盖×2 文件回读一致 / PNG 伪装 .txt 拒 / 危险扩展拒 / 超限拒 / 正常回读散列一致 / 转 PUBLIC 类型白名单校验 / 合法附件全通过。

## 边界

- 危险内容隔离区与外部存储超时重试 → FILE-003 凭证化一并设计（临时区隔离更自然）；本批以「拒绝上传=隔离」语义交付并登记。
- 内存占用：上传仍走 byte[]（16MB 上限下可接受），流式化归 FILE-003 直传改造。
