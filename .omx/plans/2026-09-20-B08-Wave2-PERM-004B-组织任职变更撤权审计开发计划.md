## 1. 勘查结论（2026-09-20，main 90f81155）

### 1.1 PERM-004.B 的显式范围来源
- docs/05 §16.1 line1028：`ZS-PERM-004.B | B08 | 前置 ZS-PERM-004.A、ZS-IAM-004、ZS-PERM-002.B | 本批交付：组织任职变更后的撤权审计 | 退出条件：任职失效及时拒绝，恢复不自动恢复越界授权`。
- docs/05 line566（ZS-PERM-004 主卡验收）：「撤权后旧 Token、旧菜单和缓存不能继续执行受限动作；缓存故障不扩大权限；**合法恢复可重新取权**；**审计包含操作者、目标、变更、结果与 trace**」。
- docs/05 line568（PERM-004.A 开发记录末）：「**撤权审计字段归 ZS-PERM-004.B（B08）**」——.A 只交付 role/menu 缓存驱逐的技术一致性，org 轴撤权审计一致性留给 .B。

### 1.2 org 轴授权「按构造即正确」——本卡的核心勘查发现
- `PermissionServiceImpl#getOrgDataPermission(userId)`（line385-390）**无 `@Cacheable`**：直接委托 `orgDataScopeResolver.resolve(userId, isSuperAdminUser(userId))`，**每请求实时**从 `MembershipMapper.selectListByUserId` + `OrganizationMapper.selectById/selectListByParentId` 读取，无跨请求缓存。
- `OrgDataScopeResolver.resolve`（PERM-002.B）以 `isEffective`（状态 ACTIVE + valid_from 已到 + valid_to 未过 + 组织存在且 `CommonStatusEnum.isEnable`）过滤，任一不满足即排除（fail-closed）；后代下钻同样施加 `isEnable`（禁用组织子树级联排除）。
- `OrgDataPermissionChecker` 的唯一缓存是**请求级** `LoginUser` 上下文（`CONTEXT_KEY = OrgDataPermissionChecker.class.getSimpleName()`），随请求结束销毁，不跨请求存活。
- **推论**：任职失活/转岗/组织禁用后，**下一次请求**的 org 轴范围即时反映变更，无陈旧缓存窗口。这是「任职失效及时拒绝」的结构性保证——但**尚无端到端一致性测试坐实**，是本卡首要交付。
- 唯一带跨请求缓存的是 `isSuperAdminUser → getUserRoleIdListByUserIdFromCache`（`USER_ROLE_ID_LIST`，由 `assignUserRole`/`processUserDeleted` 驱逐）——属 RBAC 轴，PERM-004.A 已覆盖其一致性；org 轴范围本身不经此缓存。

### 1.3 IAM-004 已交付的失权与审计（本卡只读复用，验证其 org 轴后果）
- **会话级失权**：`MembershipServiceImpl#changeStatus` 在 `shouldRevokeSessions`（默认任职失活，或变更后无任何 ACTIVE 任职，或复职默认任职）为真时调 `revokeSessions → OAuth2TokenService.removeAccessToken(userId, ADMIN)`，在 `@Transactional` 内（撤销失败回滚状态变更）。
- **每请求上下文复验**（IAM-002）：`checkAccessToken` 比对 token 内嵌 orgId/orgType/membershipId vs `MembershipContextResolver.resolve` 当前解析，不一致即 401——转岗默认任职后旧 token 被拒，强制重登。
- **审计**：`MembershipServiceImpl` 的 create/transfer/changeStatus 均带 `@LogRecord`（`SYSTEM_MEMBERSHIP_*`，承载操作者/时间/trace-id/reason）+ 每次流转写 `MembershipHistoryDO` 流水（只增不改，承载结构化历史归属：action/from-to org/from-to status/operator/reason/tenant）。

### 1.4 既有测试覆盖与本卡增量 GAP
- `OrgDataScopeResolverTest`（13 用例）：测解析器对**静态 DB 快照**的派生（超管/平台/子树/多组织并集/无任职/非在职/过期/未生效/组织禁用）——**不驱动生命周期流转**。
- `MembershipServiceImplTest`（10 用例）：测生命周期**操作侧**（create/transfer/changeStatus + shouldRevokeSessions）——**不断言 org 轴数据授权后果**。
- `PermissionCacheConsistencyTest`（5 用例，PERM-004.A）：测 role/menu 缓存驱逐一致性（RBAC 轴），已 `@Import(OrgDataScopeResolver.class)` 但未测 org 轴生命周期一致性。
- **GAP（本卡填补）**：**任职生命周期变更 × org 轴数据授权的端到端一致性**无人覆盖——「changeStatus/transfer 提交后 `getOrgDataPermission` 是否即时收缩、复职是否只恢复当前有效授权而非越界、组织在停用期间被禁用后复职是否 fail-closed、审计流水是否完整」。

## 2. 设计决策

### D1. 本卡性质：一致性验证卡（verification-first），最小改动闭合真实缺陷
- org 轴授权按构造即时反映任职变更（§1.2），故本卡**主体是端到端一致性回归套件**，锁定「任职失效及时拒绝、恢复不自动恢复越界授权」保证，防未来回归（如有人给 `getOrgDataPermission` 加 `@Cacheable`、或改 `isEffective` 口径、或让复职走缓存旧值）。
- RED 阶段若坐实**真实缺陷**（某流转后范围未及时收缩 / 复职恢复了越界授权 / 审计缺字段），以**最小改动**闭合，不重构已收敛的 PERM-002.B/IAM-004 语义。

### D2. 一致性套件的验收维度（对齐 §16.1 退出条件 + 主卡 line566）
1. **任职失效及时拒绝**：seed 账号在组织 A（STORE，含子树）在职默认任职 → `getOrgDataPermission` 含 A 子树、`OrgDataPermissionChecker.isObjectVisible(A对象)` 为真；经 `MembershipService.changeStatus(SUSPEND/TERMINATE/EXPIRE)` 提交后 → 范围**即时**收缩（不再含 A 子树，收敛 ORG_SELF）、A 对象 `checkObjectVisible` 抛 FORBIDDEN。
2. **转岗及时改授权**：`transferMembership(A→B)` 提交后 → 范围排除 A 子树、纳入 B 子树；A 对象拒绝、B 对象放行。
3. **恢复不自动恢复越界授权**：失活后复职（`changeStatus→ACTIVE`）→ 范围按**当前**有效任职 + **实时**组织启用态重派生；关键反向——**停用期间组织 A 被禁用**，复职后范围**不得**恢复 A（`isEnable` fail-closed），即「恢复只回当前合法授权，不复活越界」。
4. **缓存故障不扩大权限**（主卡 line566）：org 轴无跨请求缓存，故以「重复调用 `getOrgDataPermission` 不产生陈旧命中」+「请求级 CONTEXT_KEY 缓存不跨请求存活」坐实；若 `isSuperAdminUser` 的 `USER_ROLE_ID_LIST` 缓存与 org 范围交互有扩大面，RED 暴露后处置。
5. **审计完整性**（主卡 line566「操作者、目标、变更、结果与 trace」）：每次致 org 授权变更的生命周期流转，断言 `MembershipHistoryDO` 流水写入正确（action/from-to org/from-to status/operatorId/reason/tenantId），且 `@LogRecord` 审计常量承载操作者/目标/变更/结果/trace（trace-id 由 LogRecord 框架注入，验证常量语义覆盖「结果」——会话失效/授权收缩）。

### D3. 审计「结果」字段的处置口径
- 现状 `SYSTEM_MEMBERSHIP_CHANGE_STATUS_SUCCESS` 已含「若致默认任职上下文丧失…则其全部登录会话已失效」——承载**会话侧结果**。
- 本卡验证：org 轴**数据授权侧结果**（范围收缩/越界回收）是否需显式入审计。**决策**：优先以「流水 + 会话失效日志 + 每请求实时重派生（无陈旧授权可残留）」三者合成完整审计链即满足 line566；若 RED/评审坐实「授权侧结果」缺失导致审计不可溯源，则以**最小增量**扩充 LogRecord 常量文案（不改流转逻辑、不改 trace 机制），登记为 .B 交付。

### D4. 测试落点与夹具
- 新增 `OrgDataPermissionRevocationConsistencyTest`（module-system test，`BaseDbAndRedisUnitTest`：真实 H2 + 内嵌 Redis + 真实 Spring Cache/事务），`@Import({ZszjCacheAutoConfiguration, PermissionServiceImpl, OrgDataScopeResolver, MembershipServiceImpl, OrganizationServiceImpl, RoleServiceImpl})`，`@TestPropertySource(spring.main.allow-circular-references=true)`（循 PermissionCacheConsistencyTest 范式）。
- 驱动流转经**真实** `MembershipService.changeStatus/transferMembership`（非直接改 DB），断言经**真实** `PermissionService.getOrgDataPermission` + `OrgDataPermissionChecker`（后者以 `MockedStatic<SecurityFrameworkUtils>` 注入 LoginUser，或用真实 PermissionCommonApi 桥接）。
- 审计断言经 `MembershipHistoryMapper.selectListByMembershipId` 校验流水行。
- 复用 `RandomUtils.randomPojo` seed 组织/账号；`TransactionTemplate` 控制提交边界（镜像 PERM-004.A 的提交后断言）。
