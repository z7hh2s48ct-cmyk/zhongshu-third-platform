### 0.3 关键新交互（勘查发现，执行前须知）

1. **幂等键设计**：`eventId` 由调用方生成（业务事件号，如 `FILE_UPLOADED_<fileId>_<version>`），同一 `eventId` + 同一收件人 + 同一渠道 → DB 唯一索引硬兜底；**重试不重复生成消息**（返回既有 `sendLogId` + `DUPLICATE_IGNORED` 状态）。
2. **事务边界**：`NotifyDispatcher.dispatch` 必须在调用方事务内（`@Transactional` REQUIRED）；业务回滚 → 消息 + 发送日志 + Outbox 事件一并回滚（复用 JOB-002 `ReliableEventPort` 的 MANDATORY 事务参与保证）。
3. **收件人上下文校验**：B05 只用 `AdminUserApi.validateUserList`（校验存在 + 未禁用）+ `TenantContextHolder` 比对租户；**不查任职关系**（D-09 前）；校验失败 → 明确状态（不抛异常），供调用方查询。
4. **模板渲染复用**：`NotifyTemplateService.formatNotifyTemplateContent` 已就绪，直接复用；禁用模板 → `DISABLED_TEMPLATE` 状态（不生成消息，不入 Outbox）。
5. **无渠道处理**：`channels` 为空或不含 `INBOX` → `NO_CHANNEL` 状态（B05 只支持 INBOX；SMS/EMAIL/PUSH 待 MSG-004 + D-10）。
6. **Outbox 事件合同**：`eventType=NOTIFY_DISPATCHED`（MSG-002/004 消费方按此订阅）；`payload` 含 `eventId/recipientType/recipientId/channel/status/templateCode/messageId`；`actorType/actorId/traceId` 取自 `NotifyCommand`。
7. **主树中文路径**：`mvn`/`java` 无法经 PATH 查找，须绝对路径调用（§1.2 铁律 5）；worktree（ASCII junction 路径）内可正常 `mvn`。

### 2.1 数据模型（V20260915.003__system_notify_send_log.sql）

```sql
-- ZS-MSG-001：统一通知发送日志——幂等硬约束 + 明确状态 + 绑定 Outbox 事件。
-- 由 NotifyDispatcher 在业务事务内经 JdbcTemplate 写入；主键由 DB 生成（SEQUENCE + DEFAULT nextval）。
-- tenant_id 取自 TenantContextHolder（不默认 0，循 JOB-002 outbox_event 先例）；无 deleted/updater/update_time（只追加、不改写）。
CREATE SEQUENCE IF NOT EXISTS system_notify_send_log_seq START 1;
CREATE TABLE IF NOT EXISTS system_notify_send_log (
    id int8 NOT NULL DEFAULT nextval('system_notify_send_log_seq'),
    event_id varchar(128) NOT NULL,              -- 业务事件号（幂等键）
    recipient_type varchar(16) NOT NULL,         -- ADMIN / MEMBER
    recipient_id int8 NOT NULL,
    channel varchar(16) NOT NULL,                -- INBOX / SMS / EMAIL / PUSH（B05 只支持 INBOX）
    template_code varchar(64) NOT NULL,
    template_id int8 NULL,                       -- 成功时关联 system_notify_template.id
    biz_type varchar(64) NULL,
    biz_id varchar(128) NULL,
    biz_version varchar(64) NULL,
    status varchar(32) NOT NULL,                 -- SUCCESS / DISABLED_TEMPLATE / NO_CHANNEL / RECIPIENT_INVALID / RECIPIENT_TENANT_MISMATCH / TEMPLATE_PARAM_MISSING / TEMPLATE_NOT_FOUND / DUPLICATE_IGNORED
    status_reason varchar(512) NULL,             -- 脱敏后的状态原因（不落敏感字段原文）
    message_id int8 NULL,                        -- 成功时关联 system_notify_message.id
    outbox_event_id int8 NULL,                   -- 成功时关联 outbox_event.id（供 MSG-004 回执对账）
    actor_type varchar(16) NOT NULL,
    actor_id varchar(64) NULL,
    trace_id varchar(64) NULL,
    tenant_id int8 NOT NULL,
    create_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    CONSTRAINT uk_notify_send_log_idempotent UNIQUE (tenant_id, event_id, recipient_type, recipient_id, channel),
    CONSTRAINT ck_notify_send_log_status CHECK (status IN ('SUCCESS','DISABLED_TEMPLATE','NO_CHANNEL','RECIPIENT_INVALID','RECIPIENT_TENANT_MISMATCH','TEMPLATE_PARAM_MISSING','TEMPLATE_NOT_FOUND','DUPLICATE_IGNORED'))
);
CREATE INDEX IF NOT EXISTS idx_notify_send_log_event ON system_notify_send_log (event_id);
CREATE INDEX IF NOT EXISTS idx_notify_send_log_recipient ON system_notify_send_log (recipient_type, recipient_id);
CREATE INDEX IF NOT EXISTS idx_notify_send_log_biz ON system_notify_send_log (biz_type, biz_id);
CREATE INDEX IF NOT EXISTS idx_notify_send_log_tenant ON system_notify_send_log (tenant_id);
CREATE INDEX IF NOT EXISTS idx_notify_send_log_trace ON system_notify_send_log (trace_id);
```

**H2 schema 同步**（`create_tables.sql` 末尾追加）：等价 H2 语法（`bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY` + `varchar` + `timestamp` + `UNIQUE` + `CHECK`）。

### 2.3 服务接口

```java
public interface NotifyDispatcher {
    /**
     * 统一通知派发入口——事务内幂等：同一 eventId + 收件人 + 渠道重试不重复生成消息。
     * 必须在调用方事务内（@Transactional REQUIRED）；业务回滚 → 消息 + 日志 + Outbox 事件一并回滚。
     */
    List<NotifyDispatchResult> dispatch(NotifyCommand command);
}
```

**实现要点（`NotifyDispatcherImpl`）：**

1. **前置校验**：`eventId` 必填（空 → 抛 `NOTIFY_DISPATCH_EVENT_ID_REQUIRED`）；`recipients` 非空；`channels` 非空（空 → 全部返回 `NO_CHANNEL`）。
2. **模板解析**：`NotifyTemplateService.getNotifyTemplateByCodeFromCache(templateCode)`；不存在 → 全部返回 `TEMPLATE_NOT_FOUND`；禁用 → 全部返回 `DISABLED_TEMPLATE`。
3. **模板参数校验**：缺失 → 全部返回 `TEMPLATE_PARAM_MISSING`（不抛异常，供调用方查询）。
4. **逐收件人 × 逐渠道处理**：
   - 渠道 != INBOX → `NO_CHANNEL`（B05 只支持 INBOX）
   - 收件人上下文校验（`NotifyRecipientContextResolver`）：不存在/禁用 → `RECIPIENT_INVALID`；租户不匹配 → `RECIPIENT_TENANT_MISMATCH`
   - 幂等检查：`SELECT ... FROM system_notify_send_log WHERE tenant_id=? AND event_id=? AND recipient_type=? AND recipient_id=? AND channel=?`；已存在 → 返回既有 `sendLogId` + `DUPLICATE_IGNORED`
   - 渲染内容：`NotifyTemplateService.formatNotifyTemplateContent`
   - 生成消息：`NotifyMessageService.createNotifyMessage` → `messageId`
   - 写发送日志：`INSERT INTO system_notify_send_log ...` → `sendLogId`
   - 追加 Outbox：`ReliableEventPort.append(OutboxEventMessage{eventType=NOTIFY_DISPATCHED, ...})` → `outboxEventId`
   - 回填 `outbox_event_id` 到发送日志（`UPDATE`）
   - 返回 `SUCCESS` + `messageId` + `sendLogId` + `outboxEventId`
5. **fail-closed**：DB 写入失败 → 抛异常（事务回滚）；Outbox append 失败 → 抛异常（事务回滚，复用 JOB-002 保证）。

### 2.4 收件人上下文解析（`NotifyRecipientContextResolver`）

```java
public interface NotifyRecipientContextResolver {
    /**
     * 解析收件人上下文——B05 只解析 System 用户（AdminUserApi），校验存在/未停用/租户匹配。
     * 不查任职关系（D-09 前）；校验失败返回明确状态（不抛异常）。
     */
    NotifyRecipientContext resolve(NotifyRecipient recipient);
}

@Value
public class NotifyRecipientContext {
    NotifyRecipient recipient;
    boolean valid;
    NotifyDispatchStatus invalidStatus;  // RECIPIENT_INVALID / RECIPIENT_TENANT_MISMATCH / null（valid=true）
    String invalidReason;                // 脱敏后的原因
    Long tenantId;                       // 收件人所属租户（valid=true 时非空）
}
```

**实现（`AdminUserNotifyRecipientContextResolver`）：**
- `AdminUserApi.getUser(id)` → 不存在 → `RECIPIENT_INVALID`
- `user.status == DISABLE` → `RECIPIENT_INVALID`
- `user.tenantId != TenantContextHolder.getTenantId()` → `RECIPIENT_TENANT_MISMATCH`
- 否则 → `valid=true`
