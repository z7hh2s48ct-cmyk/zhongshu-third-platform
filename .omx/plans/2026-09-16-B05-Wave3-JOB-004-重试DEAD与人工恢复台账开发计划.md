### 0.3 关键新交互（勘查发现，执行前须知）

1. **恢复台账 = 双轨（表 + 审计）**：循 CFG-004——`outbox_recovery_log` 表存恢复动作事实（前后状态/理由/操作者/重试序号），`AuditPort` 存跨模块审计轨迹（`OUTBOX_EVENT_RETRIED`/`SKIPPED`）。二者互补：台账供恢复控制台回查「恢复前后关联」，审计供 WP-13 追踪「有权人员恢复后状态和审计可追踪」。
2. **重试语义（DEAD→PENDING）**：`retryDeadEvent` 将 status 复位 PENDING、`next_retry_at` 置为即时（`now`）以便下轮 `dispatchOnce` 重领、**保留 `retry_count` 历史但受 `manual_retry_seq` 护栏约束**（避免复位后立即再 DEAD 掩盖问题）；`claimed_by`/`claim_token`/`claim_expires_at` 清空（释放租约）。**payload/headers/event_type 字节不变**（不允许编辑掩盖历史）。
3. **跳过语义（DEAD→SKIPPED）**：`skipDeadEvent` 将 status 置 SKIPPED（新终态），不再被 `CLAIM_SELECT_SQL`（`WHERE status='PENDING'`）领取；理由必填落台账；SKIPPED 为**人工放弃终态**，与 DISPATCHED（成功）/DEAD（自动失败上限）并列。
4. **无限重试护栏**：`manual_retry_seq` = 该 event_id 在 `outbox_recovery_log` 中 `action='RETRY'` 的累计次数 +1；超过 `OutboxHealthProperties.maxManualRetry`（默认 3）→ 拒 `OUTBOX_RECOVERY_RETRY_LIMIT_EXCEEDED`（提示改用 skip 放弃或排查根因）。此即验收「无限重试被拒」。
5. **修改历史被拒（结构性）**：恢复 API **无 payload/headers/event_type 编辑入口**——retry/skip 只接受 `eventId` + `reason`，SQL 只 `UPDATE status/next_retry_at/claim_*`，从不 `SET payload`。测试断言 retry/skip 后 payload 字节完全一致（验收「修改历史被拒」+「不允许直接编辑 payload 掩盖历史」）。
6. **无权重放被拒**：retry/skip 经 controller `@PreAuthorize("@ss.hasPermission('infra:job:recover')")`；服务层再校验 operator 上下文，越权 → `AuditPort.record(ACCESS_DENIED, 独立事务)` + 抛 `ServiceException`（业务拒绝结果原样返回，吞审计自身失败并告警，循 ConfigChangeRecorder DENIED 范式）。此即验收「无权重放被拒」。
7. **异常脱敏升级（L227 归本卡）**：`describeThrowable` 现产 `{errorClass,messageLength}`（已是受控摘要，**不改其不落原文的红线**）；本卡「升级」= 恢复控制台**呈现层**将 last_error 解析为受控 `errorCategory`（我方常量码如 `NO_SINK_SUPPORTS_EVENT_TYPE` 直显，未知异常显 errorClass + 长度），供运维判断，**绝不回退到落异常原文**。
8. **敏感 payload 脱敏**：`getRecoveryDetail` 回查展示 payload 时，对命中敏感键模式的字段掩码（复用 `LogSanitizeUtils` 按敏感键掩码 / `ConfigSensitiveClassifier` 秘密键判定范式）；列表/导出同样逐条脱敏（循 ConfigController `getMaskedConfigRespVO`）。
9. **租户强制 + 隔离**：`pageDeadEvents`/`getRecoveryDetail`/`retryDeadEvent`/`skipDeadEvent` 全量取 `TenantContextHolder`（缺失 fail-closed，循 JOB-002/MSG-002 先例，不默认 0）；DEAD 事件查询/恢复按租户过滤，跨租户不可见/不可恢复。
10. **健康监测阈值实测回填（反模式规避）**：`OutboxHealthProperties` 默认值仅为**保守占位**（如 backlogWarn=1000），代码/文档明确标注「待 WP-19 实测回填」；验收「告警阈值经实测回填而非凭空声称容量达标」——**禁止在计划/代码注释/文档编造「支持 N 万 TPS」类未经实测的容量断言**；测试断言监测逻辑正确计算 + 越阈告警，**不断言具体生产阈值数值**。
11. **主树中文路径**：`mvn`/`java` 无法经 PATH 查找，须绝对路径调用（§1.2 铁律 5）；worktree（ASCII junction 路径）内可正常 `mvn`。

### 2.1 数据模型（V20260915.021__infra_outbox_recovery.sql）

```sql
-- ZS-JOB-004：Outbox 人工恢复台账 + DEAD 跳过终态。
-- 循 V20260914.010 audit_event / V20260915.001 outbox_event 惯用法：SEQUENCE 主键 + DEFAULT nextval、
-- timestamp（时间比较应用参数化）、无 BaseDO 逻辑删除（台账为不可变事实，只增不改）。
-- 铁律：恢复动作永不改 outbox_event.payload/headers（历史不可掩盖）。

-- (1) outbox_event.status 扩展 SKIPPED（人工放弃终态）
ALTER TABLE outbox_event DROP CONSTRAINT ck_outbox_event_status;
ALTER TABLE outbox_event ADD CONSTRAINT ck_outbox_event_status
    CHECK (status IN ('PENDING', 'DISPATCHED', 'DEAD', 'SKIPPED'));

-- (2) 恢复台账：每次人工 retry/skip 一行，保留恢复前后关联
CREATE SEQUENCE IF NOT EXISTS outbox_recovery_log_seq START 1;
CREATE TABLE IF NOT EXISTS outbox_recovery_log (
    id int8 NOT NULL DEFAULT nextval('outbox_recovery_log_seq'),
    event_id int8 NOT NULL,                    -- 关联 outbox_event.id
    action varchar(16) NOT NULL,               -- RETRY / SKIP
    reason varchar(512) NOT NULL,              -- 人工理由（必填，脱敏，不落敏感原文）
    before_status varchar(16) NOT NULL,        -- 恢复前状态（DEAD）
    after_status varchar(16) NOT NULL,         -- 恢复后状态（PENDING / SKIPPED）
    before_retry_count int4 NOT NULL,          -- 恢复前自动重试计数（前后关联）
    manual_retry_seq int4 NOT NULL DEFAULT 1,  -- 本事件第几次人工重试（无限重试护栏依据）
    operator_type varchar(16) NOT NULL,        -- ADMIN / SYSTEM
    operator_id varchar(64) NULL,
    tenant_id int8 NOT NULL,
    trace_id varchar(64) NULL,
    create_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    CONSTRAINT ck_outbox_recovery_action CHECK (action IN ('RETRY', 'SKIP')),
    CONSTRAINT ck_outbox_recovery_reason CHECK (char_length(reason) > 0)
);
CREATE INDEX IF NOT EXISTS idx_outbox_recovery_event ON outbox_recovery_log (event_id, id);
CREATE INDEX IF NOT EXISTS idx_outbox_recovery_tenant ON outbox_recovery_log (tenant_id);
```

**H2 schema 同步**（`zszj-module-infra/src/test/resources/sql/create_tables.sql`）：①编辑 L278 `outbox_event` 内联 CHECK 增 `'SKIPPED'`；②末尾追加 `outbox_recovery_log` 等价 H2 DDL（`bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY` + `varchar` + `timestamp` + 内联 `CHECK`，`char_length`→H2 兼容）。`clean.sql` 增 `outbox_recovery_log` 清理。

### 2.3 服务接口

```java
public interface OutboxRecoveryService {

    /** 查看 DEAD 事件分页（租户过滤，逐条脱敏）；status 默认 DEAD，可含 SKIPPED。 */
    PageResult<OutboxEventRecoveryDetail> pageDeadEvents(OutboxEventPageReqVO query);

    /** 回查单事件详情：payload 敏感键掩码 + last_error 受控摘要（errorCategory/errorClass/messageLength，无原文）+ 恢复台账历史。 */
    OutboxEventRecoveryDetail getRecoveryDetail(long eventId);

    /**
     * 授权人工重试：DEAD→PENDING，重置退避（next_retry_at=now）、清租约，写 recovery_log(RETRY)，
     * AuditPort.record(OUTBOX_EVENT_RETRIED, SUCCESS 随事务)。护栏：非 DEAD/不存在→未生效；
     * manual_retry_seq > maxManualRetry→拒 OUTBOX_RECOVERY_RETRY_LIMIT_EXCEEDED；越权→ACCESS_DENIED 独立事务留痕。
     * payload/headers/event_type 字节不变（铁律 9）。
     */
    OutboxRecoveryResult retryDeadEvent(OutboxRecoveryCmd cmd);

    /** 授权人工跳过：DEAD→SKIPPED（人工放弃终态），写 recovery_log(SKIP)，AuditPort.record(OUTBOX_EVENT_SKIPPED)。理由必填；payload 不变。 */
    OutboxRecoveryResult skipDeadEvent(OutboxRecoveryCmd cmd);
}

public interface OutboxHealthMonitor {
    /** 计算健康快照：积压/最长等待/失败率/租约健康 + 越阈清单；越阈 WARN 日志（阈值经 OutboxHealthProperties，待实测回填）。 */
    OutboxHealthMetrics snapshot();
}
```

**实现要点（`OutboxRecoveryServiceImpl`，JdbcTemplate + AuditPort，循 ConfigChangeRecorder）：**

1. **retryDeadEvent**：租户强制（缺失→`OUTBOX_RECOVERY_TENANT_REQUIRED`）；reason 必填（空→`OUTBOX_RECOVERY_REASON_REQUIRED`）；载入事件（不存在/跨租户→`OUTBOX_EVENT_NOT_FOUND`）；**状态守卫**：仅 `status='DEAD'` 可重试（否则 changed=false，outcome=NOT_DEAD）；**无限重试护栏**：查 `outbox_recovery_log` 该 event RETRY 累计 +1 = `manual_retry_seq`，`> maxManualRetry`→拒 `OUTBOX_RECOVERY_RETRY_LIMIT_EXCEEDED`；乐观并发 `UPDATE outbox_event SET status='PENDING', next_retry_at=?, claimed_by=NULL, claim_token=NULL, claim_expires_at=NULL WHERE id=? AND status='DEAD' AND tenant_id=?`（返回 0→并发已处置，changed=false）；写 `outbox_recovery_log(RETRY, before=DEAD, after=PENDING, before_retry_count, manual_retry_seq)`；`AuditPort.record(OUTBOX_EVENT_RETRIED, reason, detail 脱敏摘要, SUCCESS 随事务)`。
2. **skipDeadEvent**：同上，`UPDATE ... SET status='SKIPPED' WHERE id=? AND status='DEAD'`；写 `outbox_recovery_log(SKIP)`；`AuditPort.record(OUTBOX_EVENT_SKIPPED)`。
3. **越权 DENIED 留痕**：controller `@PreAuthorize` 已拦无权；服务层若检出 operator 上下文异常 → `AuditPort.record(ACCESS_DENIED, 独立事务 REQUIRES_NEW)` + 抛 `ServiceException`（吞审计自身失败并告警，业务拒绝原样返回，循 ConfigChangeRecorder）。
4. **payload 只读**：所有 UPDATE 语句**不含** `SET payload/headers/event_type`；`getRecoveryDetail` 读 payload 后脱敏输出，不回写。
5. **脱敏**：`getRecoveryDetail` 解析 `last_error` JSON → `errorCategory`（常量码直显 / 未知显 errorClass+messageLength）；payload 敏感键掩码（`LogSanitizeUtils`/`ConfigSensitiveClassifier`）。
6. **`OutboxHealthMonitorImpl.snapshot`**：`SELECT count(*) FILTER (WHERE status='PENDING')`, `count(*) FILTER (WHERE status='DEAD')`（H2 用 `SUM(CASE WHEN...)` 兼容）；`longestWaitSeconds` = `now - MIN(next_retry_at)`（PENDING）；`failureRatePercent` = DEAD /（DISPATCHED+DEAD+SKIPPED）；`staleLeaseCount` = `dispatcher_lease WHERE lease_expires_at < now`；比对 `OutboxHealthProperties` 阈值得 `breaches`，非空 → WARN。
