### 1.2 D-09 授权口径（docs/02 §3 line94 / §5.3 line356）
- 「一期跨组织**只允许显式平台角色**；临时跨组织授权（双人审批 + 到期回收）**后置**」（PEND-003 采纳 A）。
- FND-AUTH-003（line212）：数据范围绑定服务端确认的登录主体、身份和组织上下文；员工、负责人、平台人员得到各自授权范围；客户端不能伪造上下文。
- FND-AUTH-004（line213）：对象级授权必须验证——**已知其他组织的对象 ID 也不能读取、修改、下载或导出**。
- PILOT-REQ-009（line343）：员工看本人、负责人看本组织、平台人员看授权范围；对象 ID 越权被拒绝。

### 1.3 IAM-002 已交付的组织上下文（本卡的地基，只读复用）
- `LoginUser`（starter-security）已扩展 `getOrgId()`/`getOrgType()`/`getMembershipId()`——源于服务端签发 token userInfo（`INFO_KEY_ORG_ID/ORG_TYPE/MEMBERSHIP_ID`），**客户端无法伪造**（结构性保证：`MembershipContextResolver.resolve(userId)` 方法签名不含 orgId 入参）。

- `MembershipDO`（`system_membership`）：`userId` + `organizationId` + `roleIds`（Set<Long>，JacksonTypeHandler）+ `status`（`MembershipStatusEnum` ACTIVE/SUSPENDED/EXPIRED/TERMINATED）+ `validFrom/validTo` + `isPrimary`。
- `OrganizationContext`（module-system）：`{orgId, orgType, membershipId}` + `empty()`/`isEmpty()`（无默认任职降级）。
- 只读 Mapper 原语：`MembershipMapper.selectListByUserId(userId)`/`selectPrimaryByUserId`；`OrganizationMapper.selectById`/`selectListByType`。

## 2. 设计决策

### D1. 组织级授权范围模型（org 轴，与 dept 轴正交并存）
新增 `OrgDataScopeEnum`（module-system，独立于 `DataScopeEnum`，语义为**组织树**而非部门树）：
| 范围 | 值 | 语义 | 对应角色（PILOT-REQ-009） |
|---|---|---|---|
| `ORG_ALL` | 1 | 可见租户内全部组织 | 平台人员（显式平台角色） |
| `ORG_ASSIGNED` | 2 | 可见显式指派组织集合（含自身组织） | 平台人员受指派跨组织（一期由平台角色派生，见 D2） |
| `ORG_AND_CHILD` | 3 | 本组织 + 全部后代组织（组织树 parent_id 下钻） | 负责人看本组织（含下级门店/部门） |
| `ORG_ONLY` | 4 | 仅本组织（不含后代） | 负责人看本组织（本级） |
| `ORG_SELF` | 5 | 仅本人归属组织内、且负责人为本人的对象 | 员工看本人 |

### D2. 「显式平台角色」的判定（D-09 一期口径，不发明临时授权）
- D-09 明确「一期只允许显式平台角色跨组织；临时跨组织授权后置」。现无 PLATFORM 角色码。
- **决策**：以 `LoginUser.getOrgType() == OrganizationTypeEnum.PLATFORM`（会员所属组织为平台类型）作为「显式平台角色」的**结构性判定**——平台组织内在职任职即具跨组织授权资格，映射 `ORG_ALL`（一期平台人员看授权范围=全租户组织）。**不新增**双人审批/到期回收的临时跨组织授权（D-09 后置，登记为边界）。
- 非平台组织（BRAND/FRANCHISEE/STORE/SUPPLIER/DEPARTMENT）：默认 `ORG_AND_CHILD`（负责人语义，本组织+后代）；SUPER_ADMIN 角色 → `ORG_ALL`（与既有超管全量语义一致，复用 `RoleCodeEnum.isSuperAdmin`，不新增角色码）。
- 无组织上下文（`orgId==null`，历史无部门账号降级）：`ORG_SELF`（最窄，仅本人对象），fail-safe 不放大。

### D3. 范围解析落点（module-system，additive，不改 IAM-002/004 文件）
- `PermissionCommonApi` 新增 `OrgDataPermissionRespDTO getOrgDataPermission(Long userId)`（framework-common，**纯增量接口方法**）。
- `PermissionServiceImpl` 新增 `getOrgDataPermission` 实现：**只读**消费 `LoginUser` orgId/orgType + `MembershipMapper.selectPrimaryByUserId`（取 roleIds 判超管）+ `OrganizationMapper`（ORG_AND_CHILD 时递归下钻组织树收集后代 orgId，深度上限 fail-safe 循 `MAX_ANCESTOR_DEPTH=256` 范式），产出 `{all, self, orgIds, scopeType}`。**不调用** `MembershipServiceImpl`/`OrganizationServiceImpl` 的写方法，避免与 IAM-004 冲突。
- 组织树后代收集：新增 `OrganizationMapper.selectListByParentId`（若不存在则加只读查询）或复用现有查询在内存 BFS；优先复用既有 Mapper，缺失才增（additive）。

### D4. 对象级检查入口（framework，镜像 DeptDataPermissionChecker）
- 新增 `OrgDataPermissionChecker`（biz-data-permission，由 `ZszjDeptDataPermissionAutoConfiguration` 增 Bean 装配，additive）：
  - `isOrgVisible(Long orgId)`：命中 `all` / `orgIds` 任一即可见。
  - `isObjectVisible(Long orgId, Long ownerUserId)`：`all` 可见；`orgIds` 含 orgId 可见；`self==true` 且 ownerUserId==登录用户可见；其余不可见。
  - `checkObjectVisible(orgId, ownerUserId)`：不可见抛 `FORBIDDEN(403)`（详情/单对象读写显式拒绝，践行 FND-AUTH-004「已知他组织对象 ID 不能读写」）。
  - `checkBatchVisible(objects, orgIdGetter, ownerGetter)`：任一越权整批拒绝（批量/导出/统计混入拒绝）。
  - 护栏与 `DeptDataPermissionChecker` **完全一致**（无登录用户跳过、仅 ADMIN 适用、取不到权限 fail-closed），复用 `LoginUser` 上下文缓存（独立 `CONTEXT_KEY`，不与 dept 轴串扰）。
- **两组织互授/越界判定** = org 轴跨组织边界规则：org A 用户访问 org B 对象，B∉A 的授权 orgIds（且非 all/self 命中）→ 越界拒绝。平台组织（ORG_ALL）例外。此为 `isObjectVisible` 的自然语义，测试以「两组织互访矩阵」正反向用例坐实。

### D5. SQL 列表过滤规则（org 轴，镜像 DeptDataPermissionRule）——本卡登记为边界，暂不实现
- 卡标题含「查询」，但当前**无业务表注册 org_id 列**（PERM-002.A 也仅注册 user/dept）。列表 SQL 过滤规则 `OrgDataPermissionRule` + 业务表 org_id 列注册，随各领域模块（B08 下游 SEC-001.B/PERM-004.B/FILE-001.B/MSG-003.C/CLIENT-002.B）接入时落地。
- 本卡交付**对象级检查入口 + 范围解析 + 正向业务授权矩阵文档 + 夹具**（与 PERM-002.A 同口径：入口先行，业务表逐一路径接入随后）；列表静默过滤规则登记为 §16.1 后续子项/边界，不在本卡（避免无注册表的空转 + 控制与 IAM-004 的冲突面）。

### D6. 正向业务授权矩阵（文档交付）
- 扩展 `services/zhongshu-core/docs/数据权限授权矩阵.md`：新增「§7 组织级（跨组织）授权矩阵（ZS-PERM-002.B）」——登记 org 轴范围枚举、平台/负责人/员工三类的授权范围、两组织互访正反向矩阵、与 dept 轴/tenant 轴的正交关系、边界（临时跨组织授权后置 D-09、SQL 列表过滤随后、业务表接入随领域模块）。§6.2 的「归 ZS-PERM-002.B」待办项更新为「已由本卡交付对象级入口 + 范围解析」。
