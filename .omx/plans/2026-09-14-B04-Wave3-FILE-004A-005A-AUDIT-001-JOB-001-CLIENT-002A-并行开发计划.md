## 1. 通用工作流

### 1.1 单任务 9 步周期（与 B03 Wave1~5 / B04 Wave1~2 一致）

1. `node scripts/ops/worktree-orchestrate.mjs plan <slug>` 预演 → `create <slug>`（worktree+分支+junction 供给 tools/）。
2. **写失败测试/夹具（RED）**：按各任务 §2~§5 设计。
3. 跑确认 RED。
4. 最小实现（GREEN），DRY/YAGNI。
5. 跑确认 GREEN（0 failures 0 errors）。
6. 模块全量 + `run-local-gates.mjs --fast` 10/10 + PG 回归复跑（涉及 DB/迁移时）。
7. codex 评审闭环：0×P0/P1 才收口；P2/P3 依 `docs/reviews/README`「后续处理约定」登记去向。评审产物 `docs/reviews/codex-<TASK>.md` **只在主树文档同步阶段写**。
8. worktree 提交：`git commit -m "feat(<slug>): <一句话> [ZS-<...>]"`（中文用 `-F` UTF-8 文件）。
9. `node scripts/ops/worktree-orchestrate.mjs merge <slug>` → 主树文档串行同步（§7）→ cleanup。

### 1.2 铁律（不可违反）

1. **代码并行、文档串行**：worktree 内禁改 `docs/**`、`README`；全部文档同步在主树 §7 串行做。
2. **不连接/改动生产数据库**：一律一次性 Docker PG17/Redis 夹具（容器名/端口随机唯一、退出自动清理、失败非零、缺 Docker 退出码 3）。
3. **状态不越级**：本 Wave 产出为「待验收」（首轮开发完成 + 自动化证据），非「已验收」；已验收须对应批次真实环境放行。
4. **版本号跨会话并行**：close-task 时取 `docs/05` 当时最大版本 +1（本计划暂记 V1.47~V1.50，以实际入库顺序为准，**不得跳号/回退**）。

5. **导出技术重检**：生成与交付时重检筛选/对象权限（技术授权范围）；公开素材走已批准公开通道。

### 2.2 FILE-005.A：删除/发布中间态、引用保护和人工对账入口

**现状勘查：**
- [FileServiceImpl](../../services/zhongshu-core/zszj-module-infra/src/main/java/cn/zszj/module/infra/service/file/FileServiceImpl.java) 先上传对象再插元数据；删除先删存储再删记录，批量逐项执行；DB 事务不能自动回滚对象存储副作用。

**交付：**
1. **可恢复状态机**：文件状态增 `DELETING/ORPHAN` 中间态；删除先标记 `DELETING` → 删存储 → `DELETED`（中段失败可查可重试，不假报成功）。
2. **补偿记录**：删除/发布中段失败入补偿表 `infra_file_compensation`（迁移 `V20260914.005`），记录可恢复。
3. **引用保护**：删除前核验业务引用，被引用文件拒删或软删；保留引用文件删除规则。
4. **人工对账入口**：管理端点（`@PreAuthorize infra:file:query`）预览孤儿对象/半完成删除，受控清理不跨技术租户。
5. **批量逐项结果**：`deleteFileList` 逐项记录成功/失败并返回明细，避免半完成伪报全成功。
6. **错误码**：infra `ErrorCodeConstants` 增 `FILE_DELETE_*`/`FILE_ORPHAN_*`。

**边界（.A 不做）：** 自动补偿与孤儿对象清理 → FILE-005.B（B05，依赖 JOB-002 Outbox）；过期上传/导出按用途保留期清理策略登记。

**TDD（FileDeletionRecoveryTest，H2）：** 注入存储超时/DB 写失败/批量中段失败后可查可重试 / 重试不误删仍引用文件 / 清理范围可预览不跨租户 / 恢复后记录与对象一致 / 批量逐项结果不伪报全成功。

**codex 评审要点：** ①删除是否先标记后删存储（非先删存储）②中段失败是否可查可重试不假报成功 ③引用保护是否真核验 ④对账是否跨租户隔离 ⑤是否误依赖 Outbox（.A 无 Outbox）。
