### 0.3 关键设计决策（收口论证）

1. **轮询补偿 vs Outbox 事件补偿——选轮询（两选一）**：①补偿对象是「已落库的 DELETING 记录」，状态在 DB 即事实源，周期扫描零漂移；②Outbox 重试上限 5 次即 DEAD 转人工——存储故障通常持续，事件会烧完重试退回人工，恰与「自动补偿最终收敛」相反；轮询每轮重读最新状态，天然无限次退避重试（有效重试节奏 = max(扫描间隔, grace)）；③崩溃恢复天然（无内存态，重启下轮重扫）；④删除失败发生在业务事务外，「事务内先写事件」合同无挂载点。JOB-002 Outbox 职责边界不动。
2. **并发补偿串行化——DB 条件 CAS（非 dispatcher_lease 表）**：领取即「推进 deleting_time 到 now」的条件更新，一次往返同时完成「租约 + 退避点推进」；无需新表/新列。慢执行者的残余动作无害：对象删除幂等且引用安全（DELETING 拒绝新建兑换，引用集不增长），记录移除条件化（status=DELETING 才删）。与人工 `reconcileCleanupFile` 的交错同理论收敛（双删同对象无害、双移记录条件化后单效）。
3. **补偿复用 `.A` 对账路径，不另写清理逻辑**：领取后直接调 `reconcileCleanupFile(id)`——引用保护、确认缺失仅移记录、路径校验全部继承，补偿在语义上就是「定时的人工对账」，不可能绕过 `.A` 已闭合竞态。
4. **孤儿判定必须跨租户全局**（executeIgnore）：若引用存在性检查被租户过滤，他租户记录在同 config+path 下会被本租户管理员视为孤儿——正是「不跨技术租户误删」的反面；全局核验 + 系统级权限（`infra:file:query`/`infra:file:delete` 与 .A reconcile 一致）双保险。
5. **temp/ 在途上传保护**：`temp/` 前缀对象可能对应未过期 WAITING 凭证（在途直传）——仅按「无 infra_file 记录」判孤儿会误删在途上传；补 `infra_file_upload_credential` 活跃凭证核验（WAITING ∧ 未过期）。
6. **s3 清点不实装（保守红线）**：不可实测的清点实现若有前缀/边界缺陷，直接放大为孤儿误删——与「不误删」退出条件冲突；本地/DB 实装已足以交付完整两步流程与证据，s3 登记边界。
7. **超时语义**：`grace-minutes` 兼作「领取租约时长」与「重试退避」——领取推进 deleting_time，使同一记录最快 grace 后才可再领取；亦避免与在途原始删除请求（转移后对象删除进行中）竞争。

## 2. 测试设计（验收映射）

| 用例（H2） | 断言 → 验收 |
|---|---|
| 补偿收敛：超时 DELETING + 存储恢复 → compensate() | 记录移除、对象删除恰一次 → 超时补偿收敛 |
| 存储仍失败：compensate() 不上抛、记录保留 DELETING、deleting_time 前推 | 失败可见可重试、不假报成功 |
| 引用保护：DELETING + 活跃 REDEEMED 会话 → 补偿跳过 | 对象未删、记录保留 → 补偿不得绕过引用保护 |
| CAS 串行：同一候选两次领取 affected=1/0；已领取(时间新鲜)→ compensate 跳过 | 并发补偿被 CAS 串行化 |
| 重复补偿：成功后再次 compensate() | 无候选、delete 总次数=1 → 重复清理不误删 |
| 开关关闭：enabled=false → 全程 no-op | 配置门控生效 |
| 存量 NULL deleting_time 不被扫描（迁移回填职责） | 超时语义确定性 |
| 孤儿预览：仅列出「无全局引用 ∧ 过保留期 ∧ temp 无活跃凭证」；跨租户引用排除；truncated 如实 | 清点范围可预览且不跨租户 |
| 清点不支持：UnsupportedOperationException → 034 错误码 | 保守降级不假报 |
| 清理重核验：预览后被引用的 path 跳过不删；逐项成败记录；批量超限 035；存储失败逐项隔离不伪报全成功；重复清理幂等 | 清理前核验引用、重复清理不误删 |
| LocalFileClient.listObjects：相对路径/排序/有界 | 真实清点实现可用 |

| PG17 定向（run-file005b-verify.mjs） | 验收 |
|---|---|
| P1 迁移重放：deleting_time 列 + 回填 + 索引 | 真实 PG 结构收敛 |
| P2 并发 claim CAS 串行化（双 psql 并发领取同一行，恰一 affected=1） | 并发补偿串行化（真实 PG 行锁） |
| P3 超时补偿收敛 SQL 形状：转移→领取→条件删除→行消失；重复条件删除 affected=0 | 超时/重复清理不误删 |
| P4 引用保护数据路径：REDEEMED 未过期谓词命中（同 .A 查询形状） | 引用保护在 PG 可用 |
| P5 回退清空 deleting_time（条件转移/回退形状） | 中间态可恢复 |
| P6 最终对账一致：处理后 DELETING=0；孤儿候选 SQL（file_content 无 infra_file 记录的 path）恰为无引用集 | 恢复后记录与对象一致 |
