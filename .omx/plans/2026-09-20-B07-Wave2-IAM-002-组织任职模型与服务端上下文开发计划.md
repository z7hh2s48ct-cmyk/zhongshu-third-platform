## 1. 目标与范围

按 D-09 最小模型（一个 Account 可含多个 Membership，每任职绑定组织与有效期；用户表仅承载登录身份）落地**组织/任职数据模型 + 服务端上下文解析与校验 + 历史技术账号迁移映射**，满足 docs/05 ZS-IAM-002 验收：「批准的组织/任职关系可创建查询；伪造或过期上下文拒绝；双组织隔离通过；未批准多身份时无切换入口；历史技术账号可迁移且不误合并」。

**关联 FND-IAM 待确认验收点落地映射：**
| FND-IAM | 待确认验收 | 本卡落地 |
|---|---|---|
| 001 | 关系基数、唯一性、默认身份、失效规则 | Account(1)↔Membership(N)；每账号唯一 primary 任职（部分唯一索引）；失效=status/valid_to |
| 002 | 平台/品牌/加盟商/门店/供应商组织类型与层级 | `system_organization` 单表 `type` 枚举 + `parent_id` 自引用树 |
| 003 | 停用/过期/转岗/离职的访问与历史保留 | `system_membership` 状态机 + `system_membership_history` 流水留痕，逻辑删除保历史 |
| 004 | 服务端可验证当前账号/身份/组织；客户端不能切换到未授权身份 | 组织上下文源于服务端签发的 token userInfo（非客户端入参），签发与解析时校验任职有效性 |

**范围内：** `system_organization` / `system_membership` / `system_membership_history` 三表建表与约束；既有 `system_dept`+`system_users.dept_id/post_ids`+`system_user_role` 向组织/任职的**迁移映射**（历史技术账号可迁移不误合并）；组织/任职领域对象 DO/Mapper/Service（CRUD + 状态流转 + 历史留痕）；服务端组织上下文解析器 `MembershipContextResolver` 与登录 token userInfo 注入；伪造/过期上下文拒绝、双组织隔离；错误码新段 1-002-033（组织）/ 1-002-034（任职）。

**范围外（明确边界）：**
- **不实现运行时身份切换 API**（用户主动切当前身份 + 切换审计 FND-IAM-005）——归后置 ZS-IAM-004（前置正是本卡）。B07 反向验收「若 D-09 未批准多身份则不提供切换」；本卡即便建模支持多任职，也**只暴露 primary 任职上下文，不提供切换入口**（符合 docs/05「未批准多身份时无切换入口」的最小增量口径——切换的批准与审计在 IAM-004 收口）。
- 不做组织级/字段级/动作级授权（归 B08 ZS-PERM-002.B/003/004.B）。
- 不动 `system_dept` 既有 CRUD 与数据权限（保持向后兼容，`ref_dept_id` 桥接）。
- 不改 `system_users` 唯一约束（DB-010 领域，避免同文件同方法区冲突）。
- 不做临时跨组织授权（D-09 M5 后置，双人审批+到期回收）。

## 2. 关键设计决策（决策完整，实施者无需再抉择）

### D1 组织表迁移 `V20260921.001__system_organization.sql`

**建表 `system_organization`（继承 TenantBaseDO 语义列）：**
```sql
CREATE TABLE system_organization (
    id int8 NOT NULL,
    name varchar(64) NOT NULL,
    code varchar(64) NOT NULL DEFAULT '',
    type int2 NOT NULL,                 -- OrganizationTypeEnum
    parent_id int8 NOT NULL DEFAULT 0,  -- 自引用树根为 0
    ref_dept_id int8 NULL DEFAULT NULL, -- 仅 DEPARTMENT 类型回填桥接 system_dept.id，其余为 NULL
    sort int4 NOT NULL DEFAULT 0,
    leader_user_id int8 NULL DEFAULT NULL,
    status int2 NOT NULL DEFAULT 0,     -- CommonStatusEnum 0正常 1停用
    remark varchar(500) NULL DEFAULT NULL,
    creator varchar(64) NULL DEFAULT '',
    create_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updater varchar(64) NULL DEFAULT '',
    update_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    deleted int2 NOT NULL DEFAULT 0,
    tenant_id int8 NOT NULL DEFAULT 0
);
ALTER TABLE system_organization ADD CONSTRAINT pk_system_organization PRIMARY KEY (id);
CREATE INDEX idx_system_organization_parent ON system_organization (parent_id);
CREATE INDEX idx_system_organization_type ON system_organization (type);
-- 组织编码租户内唯一（逻辑删除后可重用，复用 DB-010/CFG-002.A partial 范式）
CREATE UNIQUE INDEX uk_system_organization_code ON system_organization (code, tenant_id) WHERE deleted = 0 AND code <> '';
CREATE SEQUENCE system_organization_seq START 100000;
```

**`OrganizationTypeEnum`（新建 `enums/organization/OrganizationTypeEnum.java`，实现 `IntArrayValuable`）：**
PLATFORM(1,平台)、BRAND(2,品牌)、FRANCHISEE(3,加盟商)、STORE(4,门店)、SUPPLIER(5,供应商)、DEPARTMENT(6,部门)。

**历史部门回填（保留上游技术主体映射，`parent_id` 直映）：**
```sql
-- 复用 dept.id 作为 DEPARTMENT 类型组织 id，parent_id 直接沿用 dept 树，ref_dept_id 桥接回 system_dept
INSERT INTO system_organization (id, name, code, type, parent_id, ref_dept_id, sort, leader_user_id, status, remark, creator, create_time, updater, update_time, deleted, tenant_id)
SELECT id, name, '', 6, parent_id, id, sort, leader_user_id, status, NULL, creator, create_time, updater, update_time, deleted, tenant_id
FROM system_dept;
```
- 序列 `START 100000` 高于既有 dept id（dept_seq START 118，实际占用远小于 10 万），保证回填 id 与后续新建 id 不撞。
- `system_dept` 不删不改；DEPARTMENT 类型组织与 dept 一一对应，双写期由 Service 层保证（本卡只建映射，dept CRUD 联动归后续卡，避免范围膨胀）。

### D2 任职表迁移 `V20260921.002__system_membership.sql`

**建表 `system_membership`：**
```sql
CREATE TABLE system_membership (
    id int8 NOT NULL,
    user_id int8 NOT NULL,               -- 账号（system_users.id），仅承载登录身份
    organization_id int8 NOT NULL,       -- 绑定的组织
    post_ids varchar(255) NULL DEFAULT NULL,   -- 岗位集合（JSON，沿用 AdminUserDO.postIds 存储范式）
    role_ids varchar(255) NULL DEFAULT NULL,   -- 角色集合（JSON）
    status int2 NOT NULL DEFAULT 1,      -- MembershipStatusEnum
    valid_from timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    valid_to timestamp NULL DEFAULT NULL,-- NULL=无固定期限
    is_primary int2 NOT NULL DEFAULT 0,  -- 1=默认任职（服务端上下文取此）
    creator varchar(64) NULL DEFAULT '',
    create_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updater varchar(64) NULL DEFAULT '',
    update_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    deleted int2 NOT NULL DEFAULT 0,
    tenant_id int8 NOT NULL DEFAULT 0
);
ALTER TABLE system_membership ADD CONSTRAINT pk_system_membership PRIMARY KEY (id);
CREATE INDEX idx_system_membership_user ON system_membership (user_id);
CREATE INDEX idx_system_membership_org ON system_membership (organization_id);
-- 每账号至多一个 primary 任职（FND-IAM-001 默认身份唯一性）
CREATE UNIQUE INDEX uk_system_membership_primary ON system_membership (user_id) WHERE deleted = 0 AND is_primary = 1;
-- 同账号同组织不重复在职（逻辑删除后可重建）
CREATE UNIQUE INDEX uk_system_membership_user_org ON system_membership (user_id, organization_id) WHERE deleted = 0 AND status IN (1,2);
CREATE SEQUENCE system_membership_seq START 100000;
```

**`MembershipStatusEnum`（新建 `enums/membership/MembershipStatusEnum.java`）：**
ACTIVE(1,在职)、SUSPENDED(2,停用)、EXPIRED(3,过期)、TERMINATED(4,离职)。
`MembershipActionEnum`（历史流水动作）：CREATE(1,入职)、TRANSFER(2,转岗)、SUSPEND(3,停用)、RESUME(4,复职)、TERMINATE(5,离职)、EXPIRE(6,过期)、UPDATE(7,变更)。

**建表 `system_membership_history`（转岗/离职/停用留痕，只增不改）：**
```sql
CREATE TABLE system_membership_history (
    id int8 NOT NULL,
    membership_id int8 NOT NULL,
    user_id int8 NOT NULL,
    action int2 NOT NULL,                -- MembershipActionEnum
    from_organization_id int8 NULL,
    to_organization_id int8 NULL,
    from_status int2 NULL,
    to_status int2 NULL,
    operator_id int8 NULL DEFAULT NULL,  -- 操作者（服务端上下文取，非客户端入参）
    reason varchar(500) NULL DEFAULT NULL,
    creator varchar(64) NULL DEFAULT '',
    create_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updater varchar(64) NULL DEFAULT '',
    update_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    deleted int2 NOT NULL DEFAULT 0,
    tenant_id int8 NOT NULL DEFAULT 0
);
ALTER TABLE system_membership_history ADD CONSTRAINT pk_system_membership_history PRIMARY KEY (id);
CREATE INDEX idx_system_membership_history_mid ON system_membership_history (membership_id);
CREATE INDEX idx_system_membership_history_user ON system_membership_history (user_id);
CREATE SEQUENCE system_membership_history_seq START 100000;
```

**历史技术账号回填（不误合并——按 user_id 逐一映射，不跨账号聚合）：**
```sql
-- 每个 deleted=0 且有 dept_id 的用户，映射其部门为组织、生成一条 primary ACTIVE 任职
INSERT INTO system_membership (id, user_id, organization_id, post_ids, role_ids, status, valid_from, valid_to, is_primary, creator, create_time, updater, update_time, deleted, tenant_id)
SELECT nextval('system_membership_seq'), u.id, u.dept_id, u.post_ids,
       (SELECT string_agg(r.role_id::text, ',') FROM system_user_role r WHERE r.user_id = u.id AND r.deleted = 0),
       1, u.create_time, NULL, 1, u.creator, u.create_time, u.updater, u.update_time, 0, u.tenant_id
FROM system_users u
WHERE u.deleted = 0 AND u.dept_id IS NOT NULL
  AND EXISTS (SELECT 1 FROM system_organization o WHERE o.id = u.dept_id AND o.deleted = 0);
-- role_ids 以逗号串暂存（与 post_ids JSON 存储差异见 D3 说明：Service 层读写统一 JSON，回填用逗号串兼容聚合，读取时归一）
```
- **不误合并保证**：回填以 `u.id` 为主键驱动，一用户一行 primary 任职，绝不按 username/mobile 聚合（那是 DB-010 的唯一性职责，本卡不触碰）。
- 无 dept_id 的用户不生成任职（保留登录身份，符合 D-09「用户表仅承载登录身份」；无任职则上下文解析走 D4 的无组织降级分支）。

### D3 领域对象与 Service（module-system，参照 PostDO/PostServiceImpl CRUD 范式）

**DO（`dal/dataobject/organization/` + `dal/dataobject/membership/`）：**
- `OrganizationDO extends TenantBaseDO`：`@TableName("system_organization") @KeySequence("system_organization_seq")`；字段 id/name/code/type/parentId/refDeptId/sort/leaderUserId/status/remark。
- `MembershipDO extends TenantBaseDO`：`@TableName(value="system_membership", autoResultMap=true)`；`postIds`/`roleIds` 用 `@TableField(typeHandler = JacksonTypeHandler.class) Set<Long>`（沿用 AdminUserDO.postIds 范式）。
- `MembershipHistoryDO extends TenantBaseDO`：`@TableName("system_membership_history")`。
- Mapper 各继承 `BaseMapperX`，提供 `selectByParentId`/`selectByUserId`/`selectPrimaryByUserId` 等。

**Service：**
- `OrganizationService`/`Impl`：create/update/delete（校验父子不成环、有子或有任职不可删）、get、list-by-type、validate-organization-enabled。
- `MembershipService`/`Impl`：
  - `createMembership`：校验组织存在且启用、同账号同组织不重复、首个任职自动 is_primary=1；写 history(action=CREATE)。
  - `transferMembership(membershipId, toOrgId, operatorId, reason)`：转岗——写 history(action=TRANSFER, from/to org)，更新 organization_id。
  - `suspend/resume/terminate/expire`：状态流转 + history 留痕（TERMINATE/EXPIRE 保留行，逻辑删除仅在显式删账号时）。
  - `getPrimaryMembership(userId)`：取 is_primary=1 且 deleted=0。
- **post_ids/role_ids 存储归一**：回填用逗号串，Service 读取时经 JacksonTypeHandler；为避免二义，回填后追加一条 `UPDATE system_membership SET role_ids = ... ` 规范化为 JSON 数组串（`[1,2]`）——GREEN 阶段以单测断言读写一致。

### D4 服务端组织上下文解析（FND-IAM-004 核心）

**原则：组织/身份上下文源于服务端签发的 token userInfo（签名保护），绝不接受客户端入参（header/param）指定的组织——从根上杜绝「客户端切换到未授权身份」。**

- **`MembershipContextResolver`（新建 `service/membership/MembershipContextResolver.java`）：**
  - `resolve(userId, tenantId)` → `OrganizationContext`（orgId/orgType/membershipId/status）。
  - 用 `DataPermissionUtils.executeIgnore` 关闭数据权限（保留租户过滤）加载 primary 任职。
  - **校验链（任一不过抛稳定错误码，fail-closed）：**
    1. 无 primary 任职 → 返回「无组织上下文」降级（orgId=null），由调用方按业务决定放行/拒绝（登录本身不因无任职失败，兼容历史无 dept 账号）。
    2. 任职 status ≠ ACTIVE → `MEMBERSHIP_INVALID_STATUS`（1_002_034_002）。
    3. valid_to 非空且 < now → `MEMBERSHIP_EXPIRED`（1_002_034_003）（过期上下文拒绝）。
    4. 组织不存在或 status=停用 → `MEMBERSHIP_ORGANIZATION_DISABLED`（1_002_034_007）。
- **token userInfo 注入（登录签发时，`AdminAuthService`/`AdminAuthServiceImpl` 登录成功构建 OAuth2AccessToken 的 userInfo 处）：** 调 `MembershipContextResolver.resolve` 得 primary 上下文，写入 userInfo：`orgId`/`orgType`/`membershipId`。`LoginUser.info` 天然承载（Map<String,String>），无需改框架层 LoginUser 结构。
- **LoginUser 便捷读取（框架层 `LoginUser` 增 INFO_KEY 常量，不改结构）：** `INFO_KEY_ORG_ID="orgId"`、`INFO_KEY_ORG_TYPE="orgType"`、`INFO_KEY_MEMBERSHIP_ID="membershipId"`（与既有 INFO_KEY_NICKNAME/INFO_KEY_DEPT_ID 同风格）。
- **双组织隔离：** 用户 A 仅有 org1 的 primary 任职 → 上下文恒为 org1；请求携带的 org2 header 被忽略；Service 层数据访问以 token 上下文的 orgId 为准（本卡提供上下文与校验，授权拦截归 B08）。

## 7. 风险与回滚

- **风险 1：回填 id 空间耦合 dept.id** → 组织序列 START 100000 远高于 dept 实际占用；R2-P2 断言映射一一对应；如 dept id 超 10 万（现实不可能）则迁移 fail-loudly（PK 冲突）。
- **风险 2：post_ids/role_ids 存储二义（JSON vs 逗号串）** → 回填后规范化为 JSON，R1 归一测试 + R2 读取断言双证。
- **风险 3：H2 不支持 partial/expression 唯一索引** → R1 只测 Service/Resolver 逻辑（不依赖 DB 约束），真实约束行为由 R2 真实 PG 验证（沿用 DB-010 分层策略）。
- **风险 4：无 dept 历史账号登录断链** → Resolver 无 primary 任职走 orgId=null 降级分支，不抛异常，登录不受影响；R1 覆盖。
- **风险 5：与 DB-010 合并位移** → 见 §4，段位/版本号物理隔离，套件名去重；合并前 merge main 一次。
- **回滚**：迁移前向即 `DROP TABLE system_membership_history/system_membership/system_organization`（新表，无既有数据依赖）；system_dept/system_users 未改，回滚零副作用。
