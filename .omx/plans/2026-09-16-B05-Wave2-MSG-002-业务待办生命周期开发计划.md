### 0.3 关键新交互（勘查发现，执行前须知）

1. **待办 vs 站内信是两类实体**：站内信（NotifyMessageDO）= 通知载体，只有已读语义；业务待办（NotifyTodoDO）= 业务任务投影，有处理状态/版本/失效原因。二者经 `message_id` 松耦合关联（待办可无消息，消息可无待办）。**阅读消息 ≠ 完成业务任务**（验收核心）。
2. **可靠事件更新待办 = Inbox 幂等消费**：`applyTransition` 必须在业务事务内（Inbox `tryBegin` MANDATORY）；处理键 = 租户 + consumer(`notify_todo`) + eventKey(命令 eventId)；同事件重复投递 → `DUPLICATE_COMPLETED` 返回首次结果不重复副作用；乱序旧版本 → `checkVersionStale=true` + `bizVersion` 经水位表拒绝 `STALE_VERSION`（**不复活已失效待办**）。
3. **终态守卫（机制级，非 DB 约束）**：COMPLETED/WITHDRAWN/INVALID 为终态；后到的 COMPLETE/WITHDRAW/REASSIGN 事件作用于终态待办时**不改状态**（返回未生效 + 原因），避免「已失效待办被复活」。此守卫在应用层（非 DB CHECK 状态流转约束），循 D-07「不把流转条件写成不可逆 DB 约束」。
4. **转派语义**：REASSIGN 更新 `assignee_type/assignee_id`；状态是否转 REASSIGNED 或保持 PENDING（换人不改处理态）由 `TodoStatusMapper`/命令决定——B05 默认 REASSIGN 更新 assignee 且 status→REASSIGNED（可继续被 COMPLETE 推进，REASSIGNED 非终态）。
5. **版本护栏适用范围**：`checkVersionStale` 仅对可解析为整数的 `bizVersion` 生效（循 JOB-003）；无版本事件按等值重试处理，不拒绝。
6. **Sink 事务语义**：`NotifyTodoEventSink.deliver` 由 `OutboxDispatcherService` 在投递路径调用；Inbox 要求 MANDATORY 事务——执行时须核实 dispatcher 是否为 deliver 提供事务上下文（若无，Sink 内以 `TransactionTemplate`/`@Transactional` 包裹 applyTransition，或登记为 D-07 接线时补齐；本卡以直接调用 `applyTransition`（测试内 TransactionTemplate 包裹）证明机制，Sink 作为中性适配层）。
7. **租户强制**：registerTodo/applyTransition 全量取 `TenantContextHolder`（缺失 fail-closed 抛异常，循 MSG-001/JOB-002 先例，不默认 0）。
8. **主树中文路径**：`mvn`/`java` 无法经 PATH 查找，须绝对路径调用（§1.2 铁律 5）；worktree（ASCII junction 路径）内可正常 `mvn`。

### 2.1 数据模型（V20260915.004__system_notify_todo.sql）

```sql
-- ZS-MSG-002：业务待办——独立于站内信已读语义的业务任务投影。
-- 稳定任务 ID(todo_key) + 业务来源(source_type) + 通用处理状态(status) + 版本(biz_version) + 失效原因(status_reason)。
-- 由 NotifyTodoService 在业务事务内经 MyBatis-Plus 写入；主键由 DB 生成（SEQUENCE + DEFAULT nextval）。
-- tenant_id 取自 TenantContextHolder（不默认 0，循 MSG-001/JOB-002 先例）。
-- D-07 红线：status 为通用机制级枚举（循 JOB-003 inbox_event status CHECK 机制先例），
--            不含 D-07 试点业务态（加盟商申请/线索状态），业务态映射经 TodoStatusMapper 扩展点。
CREATE SEQUENCE IF NOT EXISTS system_notify_todo_seq START 1;
CREATE TABLE IF NOT EXISTS system_notify_todo (
    id int8 NOT NULL DEFAULT nextval('system_notify_todo_seq'),
    todo_key varchar(128) NOT NULL,              -- 稳定业务任务 ID（幂等键，与 source_type+tenant 唯一）
    source_type varchar(32) NOT NULL,            -- 业务来源：BPM / FILE / GENERIC …（机制级，非试点业务态）
    biz_type varchar(64) NULL,
    biz_id varchar(128) NULL,
    biz_version varchar(64) NULL,                -- 对象版本（乱序护栏依据，Inbox 水位比较）
    title varchar(256) NULL,
    message_id int8 NULL,                        -- 关联站内信 system_notify_message.id（可空，松耦合）
    recipient_type varchar(16) NOT NULL,         -- ADMIN / MEMBER
    recipient_id int8 NOT NULL,
    assignee_type varchar(16) NULL,              -- 转派目标类型（可空）
    assignee_id int8 NULL,                       -- 转派目标 ID（可空）
    status varchar(24) NOT NULL,                 -- 通用机制状态：PENDING/COMPLETED/WITHDRAWN/REASSIGNED/INVALID
    status_reason varchar(512) NULL,             -- 失效/状态原因（脱敏，不落敏感原文）
    todo_version int8 NOT NULL DEFAULT 0,        -- 乐观锁：状态流转递增，防并发覆盖
    tenant_id int8 NOT NULL,
    creator varchar(64) DEFAULT '',
    create_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updater varchar(64) DEFAULT '',
    update_time timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    deleted boolean NOT NULL DEFAULT FALSE,
    PRIMARY KEY (id),
    CONSTRAINT uk_notify_todo_key UNIQUE (tenant_id, source_type, todo_key),
    CONSTRAINT ck_notify_todo_status CHECK (status IN ('PENDING','COMPLETED','WITHDRAWN','REASSIGNED','INVALID'))
);
CREATE INDEX IF NOT EXISTS idx_notify_todo_recipient ON system_notify_todo (recipient_type, recipient_id, status);
CREATE INDEX IF NOT EXISTS idx_notify_todo_biz ON system_notify_todo (biz_type, biz_id);
CREATE INDEX IF NOT EXISTS idx_notify_todo_message ON system_notify_todo (message_id);
CREATE INDEX IF NOT EXISTS idx_notify_todo_tenant ON system_notify_todo (tenant_id);
CREATE INDEX IF NOT EXISTS idx_notify_todo_assignee ON system_notify_todo (assignee_type, assignee_id);
```

**H2 schema 同步**（`create_tables.sql` 末尾追加）：等价 H2 语法（`bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY` + `varchar` + `timestamp` + `UNIQUE` + `CHECK`）。`clean.sql` 增 `system_notify_todo` 清理。

### 2.2 值对象/合同

| 类 | 字段 | 说明 |
|---|---|---|
| `NotifyTodoStatus`（enum） | PENDING, COMPLETED, WITHDRAWN, REASSIGNED, INVALID | 通用机制状态；`isTerminal()` = COMPLETED/WITHDRAWN/INVALID |
| `TodoTransitionType`（enum） | COMPLETE, WITHDRAW, REASSIGN, INVALIDATE, REOPEN(预留不启用) | 事件驱动的流转类型（机制级） |

### 2.3 服务接口

```java
public interface NotifyTodoService {

    /** 幂等注册业务待办（PENDING）；同 (tenant, source, todoKey) 重复注册返回既有，不重复建。事务内。 */
    Long registerTodo(NotifyTodoRegisterCmd cmd);

    /**
     * 事件驱动更新待办生命周期——事务内经 ConsumerInboxPort.tryBegin 幂等 + 版本护栏：
     * 重复事件返回首次结果不改状态；乱序旧版本 STALE_VERSION 拒绝；终态待办不被后到事件复活。
     * 必须在业务事务内（Inbox MANDATORY）。
     */
    NotifyTodoTransitionResult applyTransition(NotifyTodoTransitionCmd cmd);

    NotifyTodoDO getTodo(Long id);

    /** 按收件人 + 状态列待办（如未完成清单），id 升序有界。 */
    List<NotifyTodoDO> listByRecipient(Integer recipientType, Long recipientId, NotifyTodoStatus status, int limit);

    long getUnfinishedCount(Integer recipientType, Long recipientId);
}
```

**实现要点（`NotifyTodoServiceImpl`）：**

1. **registerTodo**：校验 todoKey/recipient 必填（空→抛 `NOTIFY_TODO_KEY_REQUIRED`/`NOTIFY_TODO_RECIPIENT_REQUIRED`）；租户强制（缺失→`NOTIFY_TODO_TENANT_REQUIRED`）；按唯一键查既有→存在返回既有 id（幂等）；否则 INSERT PENDING（撞唯一键并发→复判返回既有）。
2. **applyTransition**：
   - 校验 eventId 必填（`NOTIFY_TODO_EVENT_ID_REQUIRED`）；租户强制。
   - 构造 `InboxCommand{consumer="notify_todo", eventKey=eventId, payloadHash=SHA-256(cmd 关键字段), bizType, bizId, bizVersion, checkVersionStale=(bizVersion 可解析整数), traceId}`。
   - `inboxPort.tryBegin(cmd)`：
     - `CLAIMED`/`RETRIED_CLAIMED` → 载入待办（不存在→`fail` + 返回未生效 NOT_FOUND）；**终态守卫**：若待办已终态且本次非幂等重放→不改状态，`complete`（记录 TERMINAL_GUARDED，changed=false）；否则按 transitionType 应用（COMPLETE→COMPLETED、WITHDRAW→WITHDRAWN、INVALIDATE→INVALID、REASSIGN→更新 assignee + REASSIGNED），`todo_version+1`，写 status_reason，`inboxPort.complete(inboxId, resultJson)`，changed=true。
     - `DUPLICATE_COMPLETED` → 返回首次结果，changed=false，不副作用。
     - `DUPLICATE_IN_FLIGHT`/`DUPLICATE_RESULT_UNKNOWN` → changed=false，返回对应 outcome（不盲目重处理）。
     - `PARAM_CONFLICT` → changed=false，抛/记录参数冲突（同键不同指纹）。
     - `STALE_VERSION` → changed=false，outcome=STALE_VERSION（乱序旧版本不复活）。
   - 技术异常（DB 写失败）→ `inboxPort.fail` + 抛 `NOTIFY_TODO_WRITE_FAILED`（事务回滚，可重试不占终态）。
3. **已读独立**：本服务**不触碰** NotifyMessageDO 的 readStatus/readTime；站内信已读仍由 NotifyMessageService 独立管理。
4. **fail-closed**：DB 写入失败抛异常回滚；Inbox 抢位随业务事务回滚（JOB-003 保证）。
