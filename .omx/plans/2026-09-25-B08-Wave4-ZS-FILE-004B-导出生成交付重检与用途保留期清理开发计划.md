## 2. 设计决策（收口论证）

### D1 落点与服务划分（infra 模块，依赖零变更）
- 新包同一既有 `cn.zszj.module.infra.service.file`，两个新服务：
  1. **`FileExportDeliveryService`**（生成通道——导出能力主体）：生成时重检 + 私有落盘，**内部 Java API 无 HTTP 端点**（防「任意内容落盘」攻击面：内容必须由服务端业务代码生成后传入，客户端不可直达）。
  2. **`FileExportRetentionService`**（保留期清理——两步人工授权）：preview + cleanup 2 个管理端点。
- 论证：交付复用 FILE-004.A 四端点（purpose=export 已支持，零新交付代码）；两个新服务分别对应「生成侧」与「治理侧」，改动面隔离，不与 FileOrphanService（语义不同：存储清点 vs 记录查询）互相侵入。

### D2 生成通道 API 与内部 VO（`controller/admin/file/vo/file/` 包，循既有 VO 惯例）
```java
// FileExportGenerateReqVO（内部服务入参，无 HTTP 端点暴露；javadoc 明示）
private byte[] content;        // 导出内容（服务端生成；禁客户端直达）
private String name;           // 文件名（可空=内容散列兜底，循 doCreateFile）
private String type;           // MIME 声明（服务端纯内容探测为准，声明不信任）
private String objectType;     // 授权对象类型（必填=导出通道接入契约）
private Long orgId;            // 源对象组织归属（可 null=无组织列对象）
private Long ownerUserId;      // 源对象负责人（可 null；org 轴本人维谓词）
private Object object;         // 源对象实例（状态维；可 null）
private Set<String> fields;    // 本次导出的敏感字段声明（可空=不声明；非空=重检）
```
```java
// FileExportGenerateRespVO
private Long fileId;   // 导出件编号（供票据 /issue 签发交付）
private String name; private String path; private Long size;
```
- 服务接口：`FileExportGenerateRespVO generateExportFile(FileExportGenerateReqVO reqVO, LoginUser loginUser);`（无分页/无列表）。

### D3 生成时重检流水线（消费 PERM-003.A；fail-closed）
1. `loginUser == null` 或 `objectType` 空白 → **拒绝**（登录主体必须存在；导出通道接入契约=声明对象类型）。
2. **机制可用性**：`ObjectAuthorizationService` 以 `@Autowired(required=false)` 注入（循 `FileServiceImpl#orgDataPermissionChecker` 先例）；未装配（biz-data-permission 缺失的窄上下文）→ **fail-closed 拒绝**。
3. **统一裁决**：`ObjectAuthorizationRespDTO auth = objectAuthorizationService.authorize(request)`，`request = ObjectAuthorizationRequest.of(objectType, orgId, ownerUserId, object)`：
   - `auth == null`（对象类型未注册 provider）→ **FORBIDDEN**（导出通道只服务已接入域；未接入域继续走既有同步导出，不在本卡范围——新通道 fail-closed 不改变任何既有行为）；
   - `auth != null` → **对象维已过**（authorize 内部 `checkObjectVisible`：非 visit 走 org 轴 `OrgDataPermissionChecker`〔不可见=FORBIDDEN〕，visit 请求经 `CrossOrgVisitScopeHolder` 收敛〔无 scope fail-closed〕）——即「业务组织导出重检」落点。
4. **字段维**（`fields` 非空时）：「按批准字段裁剪或拒绝」之**拒绝路径**——`auth.getAuthorizedFields() == null`（域未启用字段级却声明敏感字段）或 `!auth.getAuthorizedFields().containsAll(fields)`（超出授权字段）→ **FORBIDDEN**；全部命中 → 通过。
5. 拒绝统一 `FORBIDDEN`（`GlobalErrorCodeConstants`）+ 服务端 `log.warn`（不泄露字段/对象存在性）；**每次调用实时裁决**（无缓存）。
- 与 `checkFieldsAllowed` 的合同对齐论证：语义一致（未注册/未启用+非空=Fail-closed；超权=FORBIDDEN）；本服务先 `authorize` 取对象维+输出（对象维在 `fields` 为空时也必须执行，故不能只调 `checkFieldsAllowed`——其空请求直接返回）。

### D4 导出件落盘语义（复用 FileService 落盘校验，新增导出专用入口）
- **FileService 新增方法**（避免导出件 owner/org 被当前登录上下文覆盖）：
  ```java
  Long createExportFile(byte[] content, String name, String type,
                        Long ownerUserId, Long organizationId, LocalDateTime retentionExpireTime);
  ```
  - 内部复用 `doCreateFile` 同一校验链（大小上限/纯内容类型探测/危险扩展名黑名单/散列/存储写入），owner/organizationId/purpose='export'/retention_expire_time 显式写入；`directory` 固定 `export`（人工可辨识前缀）。
  - 上传并发许可（`uploadPermits`）同路径复用（导出生成与上传同预算）。
- **导出件字段语义**：`scope=PRIVATE`（交付不返回存储 URL）、`ownerUserId=登录主体`、`organizationId=reqVO.orgId`（**源对象组织**——交付时 org 门重检的依据，「生成/交付间撤权不泄露」的载体）、`tenantId=登录主体租户`、`purpose='export'`、`retention_expire_time=now+配置保留期`。
- 论证：`organizationId` 取**源对象组织**而非登录用户组织——若取后者，转岗后交付会误放行（用户新组织在范围内）或误拒；取源对象组织，则「生成时可见 → 交付时（转岗/离任/组织停用）不可见」精确收敛（FND-AUTH-004：本人所有权不凌驾组织排除）。

### D5 交付复用与「拒绝 vs 裁剪」口径（零新交付代码）
- 交付走 FILE-004.A 既有链：`/issue?purpose=export`（签发前 `validateFileReadable`：owner+org 门+tenant）→ `/redeem`（CAS 全谓词+行锁+DELETING 拒绝）→ `/chunk`（逐块重检身份/会话/撤权/过期/读授权）→ `/revoke`。
- **「生成/交付间撤权不泄露」为结构保证**：导出件 `organizationId` 继承源对象组织（D4）→ 生成后转岗/离任/停用 → 兑换/分块链路 `validateFileReadable` 的 org 门拒绝；显式撤权 → `revoke`/DELETING 拒绝。
- **裁剪口径**：机制输出 `authorize` 结果（Web/移动端与调用方只消费输出）；本次导出内容由调用方在**生成内容之前**消费 `authorizedFields` 做列裁剪，生成通道再做「声明字段 ⊆ 授权字段」的**拒绝**校验（双保险）。本卡测试同时断言输出（裁剪证据）与拒绝（执行证据）。
- 公开素材：`scope=PUBLIC` 的导出件不适用（导出件一律 PRIVATE；公开素材走已批准公开通道=既有 PUBLIC 文件的下载端点，非本卡改动面）。

### D6 保留期清理（循 FILE-005.B 两步人工授权框架）
- **preview**（只读）：候选 = `purpose='export' ∧ status='PUBLISHED' ∧ retention_expire_time <= now`（租户内；`LIMIT` 上限 + `truncated` 如实标注）→ 返回 fileId/name/path/size/retentionExpireTime/orgId。
- **cleanup**（显式授权）：入参显式 `fileIds`（有界批次 ≤ 上限，超限错误码）；**执行前逐项重核验**（重读记录：仍是 export ∧ 仍 PUBLISHED ∧ 仍过期；命中任一保护即记失败跳过、不伪报全成功）→ 调 `fileService.deleteFile(id)`（引用保护〔活跃交付会话=FILE_DELETE_REFERENCED〕+ DELETING 中间态 + 补偿框架全继承）；逐项成败明细返回。
- 论证：不绕过 `deleteFile`（一切既有保护继承，与 FILE-005.B「补偿复用 .A 对账路径」同一思想）；不做自动定时（保守先例）；批上限+逐项重核验（防预览-清理窗口变化与假成功）。

### D7 迁移/配置/错误码
- **迁移 `V20260925.002__infra_file_export_retention.sql`**：`ALTER TABLE infra_file ADD COLUMN purpose varchar(32) DEFAULT NULL`（用途；null=普通上传）+ `ADD COLUMN retention_expire_time timestamp DEFAULT NULL`（保留期到期）+ 索引 `(purpose, retention_expire_time)`（候选查询）；H2 `create_tables.sql` 同步两列。
- **配置**：新类 `FileExportProperties`（`@ConfigurationProperties(prefix = "infra.file.export")`）注册于 `FileConfiguration`：
  - `retention-days`（导出件保留期天数，保守占位 `7`——**注明明待实测回填，禁解读为时效承诺**）；
  - `cleanup-max-ids`（单次清理批次上限，占位 `100`）。
- **错误码**（1_001_003_038/039）：`FILE_EXPORT_RETENTION_BATCH_EXCEED`（单次清理数量超上限）；`FILE_EXPORT_FORBIDDEN`（导出生成重检拒绝的统一业务口径——与 FORBIDDEN 并存说明：对象维/字段维拒绝复用全局 FORBIDDEN〔不泄露原因〕，本错误码用于「未装配/参数契约」类失败）。

### D8 端点与权限（2 个新端点挂 FileController）

## 5. 登记边界（红线，收口如实声明）

1. **字段等级目录 F0～F3 与按等级裁剪归 ZS-PERM-003.B**（前置=敏感业务字段目录获批）；本卡字段维=声明字段的拒绝校验 + 输出供裁剪，**不定义任何商业字段名/等级**。
2. **25+ 既有同步 Excel 导出端点不做改造**：业务域逐域接入导出生成通道随领域模块落地（循入口先行）；本卡以测试内技术夹具证明机制全链路。
3. **导出生成通道为内部 Java API（无 HTTP 端点）**：内容必须由服务端业务代码传入；裁剪由调用方消费 `authorize` 输出实现（服务不解析内容字节）。
4. **保留期清理为两步人工授权流程**（preview 只读 + cleanup 显式 ids 重核验），无自动定时清理；定时化归 OPS-002.C（B11）评估。
5. **`retention-days`/`cleanup-max-ids` 为保守占位配置**，待实测回填；禁解读为时效/容量承诺。
6. **撤权生效上限配置实测、CDN/缓存/重定向暴露面**归环境批次（循 FILE-004.A 计划 L108 原样）；**真实 PG+HTTP 端到端联验随 B08 批次真实环境放行**。
7. **s3/ftp/sftp 存储的导出件交付/清理未实测**：循 FileClient 既有边界（local/db 可测）。
8. **导出件 MIME 声明不信任**（服务端纯内容探测为准）；危险扩展名黑名单/大小上限与上传同策；导出件一律 PRIVATE（公开素材走既有已批准通道）。
9. **主卡 ZS-FILE-004 维持「开发中」**（.A/.B 均子项交付；主卡验收须 B08 批次真实环境放行）；第 2 节统计不变（`0/21/2/0/2/66`，合计 91）——由 `task-stats.mjs` 复核；**本卡不改变任何主任务验收状态**。
10. **清理不跨技术租户**：候选查询与清理均在当前租户上下文（循 orphan 同策）；清理走 `deleteFile` 既有保护（引用/中间态/补偿），不新增绕过面。
