## 2. 现状（勘查证据）

- 放大链：`TenantVisitContextInterceptor.preHandle`（biz-tenant，全仓唯一 `setVisitTenantId` 点）→ visit-enable=true 且持 `system:tenant:visit` → `loginUser.setVisitTenantId` + `TenantContextHolder.setTenantId` → `SecurityFrameworkUtils.skipPermissionCheck()`（visitTenantId≠tenantId 即 true）→ `SecurityFrameworkServiceImpl.hasAnyPermissions/hasAnyRoles/hasAnyScopes` **一律 return true**（跳过全部功能权限）→ 数据范围不追加。
- SEC-001.A 已默认关闭（`visit-enable=false` 时任何跨租户切换 403），但**未改** `skipPermissionCheck`/`SecurityFrameworkServiceImpl`（显式留给 .B）。

  - `MembershipHistoryDO`（`extends TenantBaseDO`，只增不改）= 审计流水 DO 范式。

## 3. 关键设计决策（决策完整，实施者无需再抉择）

### D1. 授权记录形态：新增持久化 `system_cross_org_visit_grant`（服务端授权记录/策略）
- 平台级跨租户表：`extends BaseDO` + `@TableName("system_cross_org_visit_grant")` + `@KeySequence` + `@TenantIgnore`（循 `TenantDO` 范式；跨租户查询不受 MP 租户插件自动注入）。
- 列：`id`、`visitor_user_id`（原主体账号）、`visitor_tenant_id`（原主体home租户）、`target_tenant_id`（目标租户）、`target_org_ids`（对象范围，text JSON；**null=目标租户内全部组织**）、`allowed_actions`（动作，text JSON 权限串集合；**空/null=fail-closed 不允许任何动作**）、`allowed_fields`（字段，text JSON；**null=不允许任何显式敏感字段**，机制交付，字段目录归 PERM-003）、`valid_from`、`valid_to`（有效期，valid_to null=无固定期限）、`status`（int2，0=ACTIVE/1=REVOKED）、`reason`（理由，varchar500）+ BaseDO（creator/create_time/updater/update_time/deleted）。
- 索引：`idx_(visitor_user_id, target_tenant_id)`；序列 `system_cross_org_visit_grant_seq START 100000`。

### D2. 授权判定 `CrossOrgVisitService#authorizeVisit(req) → decision`（正向矩阵核心，fail-closed）
判定顺序（任一不满足即 DENY + 写审计 + 返回 reason）：
1. 参数校验：visitorUserId/targetTenantId 非法 → `INVALID_REQUEST`。
2. 取该 (visitor, target) 的 ACTIVE-候选授权记录（未删除）；无记录 → `NO_GRANT`（**取代旧 `system:tenant:visit` 粗粒度权限**：无记录即拒，不再因持旧权限放大）。
3. `status==REVOKED` → `GRANT_REVOKED`（**撤销拒绝**）。
4. `now` 不在 `[valid_from, valid_to]` → `GRANT_EXPIRED`（**过期拒绝**；valid_to null 视为未过期）。
5. D-09 平台角色资格：`permissionService.getOrgDataPermission(visitorUserId).all != true` → `NOT_PLATFORM_ROLE`（**须 D-09**：跨组织只允许显式平台角色；平台任职过期/撤销 → all=false → 拒绝，与 D2.4 双层兜底）。
6. 目标状态校验：目标租户不存在/停用（`CommonStatusEnum.isEnable`）→ `TARGET_INVALID`；`target_org_ids` 非空时逐一校验组织存在且启用，任一禁用/不存在 → `TARGET_ORG_INVALID`（**停用/无效目标拒绝**）。
7. 动作维度（req.action 非空时）：`action ∉ allowed_actions` → `ACTION_NOT_ALLOWED`（**不能自动获得所有目标动作**）。
8. 对象维度（req.objectOrgId 非空且 target_org_ids 非空时）：`objectOrgId ∉ target_org_ids` → `OBJECT_OUT_OF_SCOPE`（**错对象拒绝**；target_org_ids null=全租户组织，此维放行）。
9. 字段维度（req.requestedFields 非空时）：`requestedFields ⊄ allowed_fields` → `FIELD_NOT_ALLOWED`（**错字段拒绝**）。
10. 全部通过 → `AUTHORIZED`（GRANTED），返回 grantedScope（target_org_ids/allowed_actions/allowed_fields）。
- **每次判定（GRANTED/DENIED）都写审计**（`AuditPort.record`）：eventType=`CROSS_ORG_VISIT_GRANTED`/`CROSS_ORG_VISIT_DENIED`，actorType=ADMIN，actorId=visitorUserId，action=req.action（或 "VISIT"），bizType="CROSS_ORG_VISIT"，bizId=targetTenantId，reason=deny reason / "AUTHORIZED"，result=SUCCESS/DENIED，detail={visitorTenantId,targetOrgIds,objectOrgId,requestedFields}（脱敏，无敏感明文），tenantId=visitorTenantId，traceId=TracerUtils.getTraceId()。

### D3. 发放/撤销（人工，非双人审批工作流）
- `createGrant(reqVO)`：由获批管理员发放（校验 visitor 为平台角色、target 合法、valid 窗口合理）；写 `AuditEventTypes.OBJECT_CREATED`（bizType=CROSS_ORG_VISIT_GRANT）。
- `revokeGrant(id, reason)`：置 status=REVOKED（**撤销**，逻辑状态翻转不改历史），写审计（action=REVOKE）。到期自动回收 JOB + 双人审批工作流 = **边界**（D-09 后置，登记不实现）。

### D4. 框架 SPI `CrossOrgVisitApi`（framework-common，循 PermissionCommonApi/AuditPort 先例）
- 包 `cn.zszj.framework.common.biz.system.permission`。方法 `CrossOrgVisitDecisionDTO authorizeCrossOrgVisit(CrossOrgVisitCheckReqDTO req)`。
- DTO：`CrossOrgVisitCheckReqDTO`（visitorUserId/visitorTenantId/targetTenantId/action/objectOrgId/requestedFields）、`CrossOrgVisitDecisionDTO`（authorized/reason/grantedTargetOrgIds/grantedAllowedActions/grantedAllowedFields）、`CrossOrgVisitScopeDTO`（存 LoginUser.context 的授权范围快照）。
- system 模块 `CrossOrgVisitApiImpl`（facade，`@Service`）→ `CrossOrgVisitService`。

### D5. 拦截器接线（`TenantVisitContextInterceptor`）：授权记录取代粗粒度权限
- 注入 `ObjectProvider<CrossOrgVisitApi>`（可选 Bean，循框架 starter 不硬依赖 module 的分层）。
- visit-enable 门控（SEC-001.A 保留，最先）→ loginUser 空检查 → **替换** `hasAnyPermissions("system:tenant:visit")`：调 `crossOrgVisitApi.authorizeCrossOrgVisit(visitorUserId, visitorTenantId=当前租户, targetTenantId=visitTenantId, action=null 粗粒度目标级门)`。
  - provider 为空（无实现）+ visit-enable=true → **fail-closed DENY**（受控授权缺失即拒，不放大）。
  - DENY → 抛 403（reason 文案）+ **不切换**（不设 visitTenantId、不切 TenantContextHolder；审计已由 service 落）。
  - GRANT → `setVisitTenantId` + `TenantContextHolder.setTenantId` + 将 `CrossOrgVisitScopeDTO` 存入 `LoginUser.context`（key=`CrossOrgVisitScopeDTO`），供功能权限/对象/字段访问层消费。
- `ZszjTenantAutoConfiguration.tenantVisitContextInterceptor` Bean 签名增 `ObjectProvider<CrossOrgVisitApi>`。

### D6. 收敛放大：功能权限不再整体跳过（`SecurityFrameworkServiceImpl`）
- `hasAnyPermissions(perms)`：将 `if (skipPermissionCheck()) return true;` 改为 `if (skipPermissionCheck()) return crossOrgVisitAllows(perms);`——从 LoginUser.context 读 `CrossOrgVisitScopeDTO`，`perms` 任一 ∈ `allowedActions` 才 true；无 scope（异常态）→ **fail-closed false**（不再整体跳过）。
- `hasAnyRoles/hasAnyScopes`：visit 上下文（skipPermissionCheck()=true）→ **fail-closed false**（一期跨组织授权只发放动作/权限维度，不发放角色/scope；登记边界）。
- `skipPermissionCheck()` 语义不变（仍 visitTenantId≠tenantId），但**后果**由「整体跳过」收敛为「按授权记录范围裁决」——落实 line331「不能自动获得所有目标动作」。
- 新增 `CrossOrgVisitScopeHolder`（security starter util）：读写 LoginUser.context 的 scope（`set/get/clear`），`afterCompletion` 清理上下文时一并 clear（**上下文清理有效**）。

### D7. 对象/字段访问入口（`CrossOrgVisitScopeChecker`，"入口先行"，循 PERM-002.B OrgDataPermissionChecker）
- 框架级 Bean（data-permission starter，与 OrgDataPermissionChecker 并列）：`isActionAllowed(permission)`、`isObjectAllowed(orgId)`、`areFieldsAllowed(fields)`、`checkXxx`（不可见抛 FORBIDDEN）。读 LoginUser.context scope；无 visit scope 时委托既有轴（不新增绕过面）。
- 各业务路径逐一接入 = **边界**（随下游领域模块 FILE-001.B/MSG-003.C/CLIENT-002.B，同 PERM-002.B「入口先行」）。

## 5. 正向授权矩阵（验收对齐 §16.1 line1014 / docs/05 line331）

| 场景 | 输入 | 判定 | reason | 验收项 |
|---|---|---|---|---|
| 正常授权有效 | ACTIVE grant + 平台角色 + 启用目标 + 窗口内 + 动作/对象/字段在范围 | GRANTED | AUTHORIZED | 正常授权有效 |
| 过期拒绝 | grant.valid_to 已过 | DENY | GRANT_EXPIRED | 过期拒绝 |
| 撤销拒绝 | grant.status=REVOKED | DENY | GRANT_REVOKED | 撤销拒绝 |
| 非平台角色 | 无 PLATFORM 任职（all=false） | DENY | NOT_PLATFORM_ROLE | 须 D-09 |
| 平台任职失效 | 平台 membership 过期/撤销 → all=false | DENY | NOT_PLATFORM_ROLE | 过期/撤销 + D-09 |
| 目标停用 | 目标租户 status 停用 | DENY | TARGET_INVALID | 停用/无效目标拒绝 |
| 目标组织无效 | target_org_ids 含禁用组织 | DENY | TARGET_ORG_INVALID | 停用/无效目标拒绝 |
| 无授权记录 | 持旧 system:tenant:visit 但无 grant | DENY | NO_GRANT | 不将旧能力当授权 |
| 错动作 | action ∉ allowed_actions | DENY | ACTION_NOT_ALLOWED | 不能自动获得所有目标动作 |
| 错对象 | objectOrgId ∉ target_org_ids | DENY | OBJECT_OUT_OF_SCOPE | 错对象拒绝 |
| 错字段 | requestedFields ⊄ allowed_fields | DENY | FIELD_NOT_ALLOWED | 错字段拒绝 |
| 上下文清理 | afterCompletion | scope cleared | — | 授权撤销与上下文清理有效 |

## 6. 边界与登记（不实现，防越界）

1. **双人审批 + 到期自动回收工作流**后置（D-09 line94 / PERM-002.B §7.7 / PERM-004.B §6）——本卡交付记录式受控授权（人工发放/撤销 + 有效期 + 状态 + 审计），不建审批流/回收 JOB。
2. **字段目录 + 序列化层脱敏**归 ZS-PERM-003（待前置，字段目录待获批）——本卡交付字段维度**判定机制**（allowed_fields/requestedFields）+ 矩阵用例，不接生产字段目录、不改序列化。
3. **org 轴 SQL 列表静默过滤规则**（`OrgDataPermissionRule`）+ 业务表 org_id 列注册随下游领域模块（PERM-002.B §7.7）——本卡不建列表过滤规则。
4. **各业务路径逐一接入** `CrossOrgVisitScopeChecker`（哪些 Controller/Service 调用）随 FILE-001.B/MSG-003.C/CLIENT-002.B 落地——本卡"入口先行"（同 PERM-002.A/B 口径）。
5. **真实 PG + HTTP 端到端跨组织联验**随 B08 批次真实环境放行——本卡以 H2 + 内嵌 Redis 一致性套件 + 框架夹具坐实授权层语义。
6. 主卡 ZS-SEC-001 维持**开发中**（.A+.B 均交付后，须真实环境放行才转待验收）；本记录不表示任何主任务已验收。
