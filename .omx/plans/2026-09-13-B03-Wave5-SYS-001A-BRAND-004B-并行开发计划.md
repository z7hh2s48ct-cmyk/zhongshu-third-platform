## 1. 通用工作流

### 1.1 单任务 9 步周期（与 Wave 1~4 一致）

1. `node scripts/ops/worktree-orchestrate.mjs plan <slug>` 预演 → `create <slug>`（worktree+分支+junction 供给 tools/；worktree 为 ASCII 路径，mvn 可正常走 env.sh）。
2. **写失败测试/夹具（RED）**：按各任务 §2/§3 设计。
3. 跑确认 RED（SYS-001.A 的「RED」= 基线先行 + 缺口登记，见 §2.3）。
4. 最小实现（GREEN），DRY/YAGNI。
5. 跑确认 GREEN（0 failures 0 errors）。
6. 模块全量 + `run-local-gates.mjs --fast` 10/10 + PG 回归复跑。
7. codex 评审闭环：0×P0/P1 才收口；P2/P3 依 `docs/reviews/README`「后续处理约定」登记去向。评审产物 `docs/reviews/codex-<TASK>.md` **只在主树文档同步阶段写**。
8. worktree 提交：`git commit -m "feat(<slug>): <一句话> [ZS-<...>]"`（中文用 `-F` UTF-8 文件）。
9. `node scripts/ops/worktree-orchestrate.mjs merge <slug>` → 主树文档串行同步（§5）→ cleanup。

### 1.3 铁律（不可违反）

1. **代码并行、文档串行**：worktree 内禁改 `docs/**`、`README`；全部文档同步在主树 §5 串行做。
2. **不连接/改动生产数据库**：一律一次性 Docker PG17/Redis 夹具（容器名/端口随机唯一、退出自动清理、失败非零、缺 Docker 退出码 3）。
3. **状态不越级**：本 Wave 产出为「待验收」（首轮开发完成 + 自动化证据），非「已验收」；已验收须 B03 批次真实环境放行。
4. **版本号跨会话并行**：SEC-012.B 由并行会话收口，本 Wave 收口时版本**不预占**——close-task 时取 `docs/05` 当时最大版本 +1（本计划暂记 V1.38/V1.39，以实际为准）；§19 行按实际入库顺序登记。
5. **主树工具链**：`source tools/env.sh` 后 PATH 中文路径查找失效，主树内一律绝对路径调用：`"E:/众墅之家AI赋能平台底座/tools/apache-maven-3.9.9/bin/mvn"`（JAVA_HOME 同理）；worktree（ASCII junction 路径）内可正常 `mvn`。
