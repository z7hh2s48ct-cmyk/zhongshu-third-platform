## 2. 设计决策（收口论证）

### D1 落点与包（framework 层，依赖方向最小）
- 新包 `cn.zszj.framework.datapermission.core.authorize`（biz-data-permission starter，邻居 `core/rule/org`）。
- 论证：机制三维依赖 = `SecurityFrameworkService`（security starter bean）+ `OrgDataPermissionChecker`（本 starter）+ `CrossOrgVisitScopeHolder`（security）；security starter 不含 OrgDataPermissionChecker（反向依赖不可行），故落本 starter；与 checker 家族同装 `ZszjDeptDataPermissionAutoConfiguration`（PERM-002.A/B 先例）。

### D2 输出合同 `ObjectAuthorizationRespDTO`（统一响应合同）
```java
// cn.zszj.framework.datapermission.core.authorize.ObjectAuthorizationRespDTO
@Data
public class ObjectAuthorizationRespDTO {
    private Set<String> allowedActions;   // 允许动作（权限标识，恒非 null；空集=零允许动作）
    private Set<String> authorizedFields; // 授权字段；null=该对象类型未启用字段级输出；非 null=启用（可空集）
}
```
- 动作元素=权限标识（与 `@PreAuthorize` 权限串、D6 `allowedActions` 同一语义，前端可直接对齐既有按钮权限体系）。
- 字段空候选=未启用（null）与"启用但全部不可见"（空集）**语义区分**——防未启用域被前端误判全隐。
- 不引入任何商业字段等级常量（F0～F3 归 .B）。

### D3 SPI 扩展点 `ObjectAuthorizationProvider`
```java
// cn.zszj.framework.datapermission.core.authorize.ObjectAuthorizationProvider
public interface ObjectAuthorizationProvider {
    String getObjectType();                                                    // 对象类型唯一标识
    default Collection<String> getCandidateActions() { return Collections.emptyList(); } // 候选动作（权限标识）
    default Collection<String> getCandidateFields() { return Collections.emptyList(); }  // 候选字段；非空=启用字段级
    default boolean isActionAllowedInStatus(String action, Object object) { return true; } // 状态维（默认不限制）
}
```
- 一个对象类型一个 provider；`ObjectAuthorizationService` 构造时按 objectType 索引，**重复注册 fail-fast（IllegalStateException）**。
- 状态维契约：`object` 为 null 时照传，实现方自行保守（javadoc 明示建议——依赖状态约束的实现应对 null 返回 false）；默认 true=无状态约束。

### D4 输入 `ObjectAuthorizationRequest`
```java
// cn.zszj.framework.datapermission.core.authorize.ObjectAuthorizationRequest
@Data
public class ObjectAuthorizationRequest {
    private String objectType;   // 必填
    private Long orgId;          // 对象所属组织（可 null=无组织列对象）
    private Long ownerUserId;    // 对象负责人（可 null）
    private Object object;       // 业务对象实例（供状态维；可 null）
    public static ObjectAuthorizationRequest of(String objectType, Long orgId, Long ownerUserId) {...}
    public static ObjectAuthorizationRequest of(String objectType, Long orgId, Long ownerUserId, Object object) {...}
}
```

### D5 裁决流水线 `authorize`（输出侧；唯一裁决核心）
1. **provider 查找**：未注册 objectType → **返回 null**（未接入=零变化；不抛异常，调用方保持原有输出/行为）。
2. **对象维**（fail-closed，先于动作/字段）：
   - `SecurityFrameworkUtils.skipPermissionCheck()`（跨租户访问请求，**与 SecurityFrameworkServiceImpl 同一信号**）→ visit 裁决：`CrossOrgVisitScopeHolder.isObjectAllowed(orgId)`（无 scope/未获批/越界=fail-closed false；whole-tenant 放行）；**不落 home 组织 checker（无 home 范围混入）**；
   - 否则 → `OrgDataPermissionChecker.isObjectVisible(orgId, ownerUserId)`（三重护栏/缓存/fail-closed 全继承）；
   - 不通过 → **FORBIDDEN**（统一错误，不泄露原因细节）。
3. **动作维**：`candidates`（去重）→ `filter(provider.isActionAllowedInStatus(action, object))`（状态维）→ `filter(securityFrameworkService.hasAnyPermissions(action))`（**复用 @PreAuthorize 入口同一实现**：visit 请求经 D6 allowedActions 收敛、常规经 RBAC；无登录用户=false 为既有语义）。
4. **字段维**：候选空 → **null**（未启用）；非空 → visit 请求逐字段 `CrossOrgVisitScopeHolder.areFieldsAllowed(Set.of(f))`（D7 共用，fail-closed）；非 visit → **全候选**（.A 零变化，等级目录 .B 接入）。
5. 组装 Resp（allowedActions 恒非 null 集合）。

### D6 执行侧入口（与 authorize 共用同一裁决核心）
```java
public ObjectAuthorizationRespDTO authorize(ObjectAuthorizationRequest request);           // null=未接入
public void checkActionAllowed(ObjectAuthorizationRequest request, String action);          // 越权/未注册/blank → FORBIDDEN
public void checkFieldsAllowed(ObjectAuthorizationRequest request, Collection<String> fields); // 空请求通过；越权/未启用/未注册 → FORBIDDEN
```
- `check*` 内部**复用 authorize** 同一裁决方法 → 「输出与实际执行共用服务端策略」为**结构保证**（唯一裁决出处）。
- **每次调用实时重算**（无跨请求缓存、不信任任何外部/旧快照）→ 「前端伪造不生效」「变更后重新校验」为结构保证。
- **API 设计上不暴露"外部声明动作/字段集合"参数**（请求只含对象上下文）→ 伪造通道在合同层不存在。
- 拒绝统一 `FORBIDDEN` + 服务端 `log.warn`（错误信息不区分原因——不泄露对象/字段是否存在，防错误信息旁路）。
- `checkFieldsAllowed` 空请求=不校验字段维（与 `areFieldsAllowed` 同口径）；`checkActionAllowed` blank 动作=fail-closed 拒绝。

### D7 装配与「默认空=零变化」
- `ZszjDeptDataPermissionAutoConfiguration` 新增：
  ```java
  @Bean
  public ObjectAuthorizationService objectAuthorizationService(SecurityFrameworkService securityFrameworkService,
                                                               OrgDataPermissionChecker orgDataPermissionChecker,
                                                               List<ObjectAuthorizationProvider> providers) { ... }
  ```
  （`SecurityFrameworkService` bean `@Bean("ss")` 由 security starter 无条件装配，与 `PermissionCommonApi` 同级强依赖；`List` 注入空=空转，authorize 恒 null。）
- **不新增 AutoConfiguration 类、不改 imports**；除新增 bean 空转外无任何既有文件行为变更（零变化由模块全量测试与基线同源证明）。

### D8 文档登记（worktree 内，`services/zhongshu-core/docs/数据权限授权矩阵.md`）
- 标题行追加 `ZS-PERM-003.A`；新增 **§8 动作与字段授权输出机制（ZS-PERM-003.A）**：机制定位/合同语义（含 null 语义）/裁决流水线/执行入口/边界（字段等级归 .B、业务接入留后、前端消费归 CLIENT-001.B、PG/HTTP 联验随批次）。
